AgentOS · Docker

Running the Chain of Scouts

Three-agent Gmail orchestrator: cron trigger → inbox reader → KB curator → daily brief.

Before you start
  • Docker Desktop installed and running on your Mac
  • Anthropic API key (sk-ant-...)
  • Google Cloud account — free tier works
  • Rust + Cargo — to build agentctl once
One-time setup
01
Build agentctl once

You need agentctl on your Mac to complete the Google OAuth flow. Build it from the repo root:

bash
# From repo root
cargo build --release --bin agentctl

# Optionally add to PATH
sudo cp target/release/agentctl /usr/local/bin/agentctl
02
Create Google OAuth credentials once

The CoS needs read-only Gmail access. Create an OAuth app in Google Cloud:

  1. Go to console.cloud.google.com → select or create a project
  2. APIs & Services → Library → search Gmail API → Enable
  3. APIs & Services → Credentials → Create Credentials → OAuth client ID
  4. Application type: Desktop app — name it anything
  5. Copy the Client ID and Client Secret — no redirect URI to register

Desktop app clients allow 127.0.0.1 loopback redirects automatically per RFC 8252 — there is no redirect URI field in the Google Cloud Console for this client type. agentctl auth google uses port 8585 by default; pass --port <N> if that port is in use.

03
Authorize Gmail access once

Run the PKCE OAuth flow on your Mac. A browser window will open — sign in with your Google account and grant Gmail read access. The refresh token is saved locally.

bash
agentctl auth google \
  --client-id     "YOUR_CLIENT_ID.apps.googleusercontent.com" \
  --client-secret "YOUR_CLIENT_SECRET"

On success, credentials are written to ~/.agentos-secrets/google.json. The container mounts this file read-only — no credentials are passed via environment variables.

04
Create local directories once

Two host directories are mounted into the container: one for runtime state (checkpoint, memory DB, evidence log), one for the brief output.

bash
mkdir -p ~/.agentos-output ~/.agentos-data
Run it
05
Pull the image
bash
docker pull ghcr.io/0x89karan/runtime1:full
06
Start the CoS

Set your Anthropic key and run. TRIGGER_INTERVAL=every 2m fires the cron quickly for testing — change it to a cron expression like 0 8 * * * for production use.

bash
export ANTHROPIC_API_KEY=sk-ant-...

docker run --rm -it \
  --name agentos-cos \
  --privileged \
  -e ANTHROPIC_API_KEY \
  -e "TRIGGER_INTERVAL=every 2m" \
  -v ~/.agentos-secrets:/run/secrets:ro \
  -v ~/.agentos-output:/data/output \
  -v ~/.agentos-data:/data \
  ghcr.io/0x89karan/runtime1:full cos

The container boots agentd, patches the config, and parks the orchestrator agent in a cron wait loop. Logs stream to your terminal.

What happens in the first 3 minutes
0:00
agentd starts. MCP servers (cron, oauth) connect. Orchestrator agent begins its loop.
~0:30
Cron fires. Orchestrator spawns the Inbox agent with a 500k-token budget.
~1:00
Inbox agent reads Gmail. Calls the OAuth sidecar → fetches last 24h of messages → returns structured JSON.
~1:30
Curator agent persists to KB. Writes briefs + entities to the redb memory store.
~2:00
Brief written. Orchestrator writes brief-YYYY-MM-DD.md and parks for next trigger.
07
Watch the agents optional

In a second terminal, watch the live cockpit — per-agent status, last tool call, and the flight log — from inside the running container:

bash
docker exec -it agentos-cos agentctl watch

Requires the --name agentos-cos from step 6. Press q to exit the cockpit (the agents keep running).

08
Read the brief

In a second terminal, once the first cycle completes:

bash
# List briefs
ls -la ~/.agentos-output/

# Read today's brief
cat ~/.agentos-output/brief-$(date +%Y-%m-%d).md
Updating & older images
Stopping the CoS (run vs compose)
  • Started with docker run … cos (this guide): press Ctrl+C in its terminal — --rm stops and removes the container automatically. If one is left over (still running elsewhere, or holding the agentos-cos name), remove it with docker rm -f agentos-cos. You do not need docker compose down here.
  • Started with docker compose up / run (the dev / build-from-source path): use docker compose down to stop and remove the compose containers + network.
  • Not sure what's running? docker ps -a --filter name=agentos lists every AgentOS container; remove leftovers with docker rm -f <name>.
  • Your data is safe. State (checkpoint, memory, briefs, flight log) lives in the host mounts ~/.agentos-data and ~/.agentos-output — removing a container never touches them, so the next run resumes. The only destructive command is docker compose down -v, which also deletes compose named volumes (state loss); plain down keeps them.
After every release — re-pull
  • The image is the code. Fixes ship as new agentos:full / :latest builds; a running container never updates itself. After a release, re-pull to get the fix — e.g. the v0.73.0 → v0.73.1 Gmail-auth fix. A stale local image is the #1 cause of "a fix landed but nothing changed."
bash
# 1. Pull the newest build (re-checks the registry by digest)
docker pull ghcr.io/0x89karan/runtime1:full

# 2. Remove the old container before re-running (--rm cleans it on exit,
#    but a still-running or leftover one holds the name)
docker rm -f agentos-cos 2>/dev/null || true

# 3. Re-run step 6 with the fresh image
Clean re-test after a fix (drop stale / failed agents)
  • A restart resumes prior agents from the checkpoint — by design (the CoS survives restarts and picks up its cron loop). But that includes any agent that failed in an earlier run, so after pulling a fix you want a fresh start rather than reloading a broken state. docker rm alone doesn't do this — the checkpoint lives on the host mount, not in the container.
bash
# 1. Stop the old container
docker rm -f agentos-cos 2>/dev/null || true

# 2. Drop the checkpoint so no stale/failed agents reload
rm -f ~/.agentos-data/checkpoint.json 2>/dev/null || true

# 3. Pull the fixed image
docker pull ghcr.io/0x89karan/runtime1:full

# 4. Re-run step 6 — a fresh orchestrator starts, no carryover

Full reset (only if a run still reloads stale state): rm -rf ~/.agentos-data/* regenerates the memory store, flight log, and signing keys from scratch. Your Google credentials live in ~/.agentos-secrets and are not touched.

Clean up stale images & check versions
  • See what you have: docker image ls ghcr.io/0x89karan/runtime1 and docker ps -a --filter name=agentos.
  • Remove old images: docker image prune clears dangling layers; docker rmi <image-id> removes a specific old tag. Frees disk and stops you accidentally running yesterday's build.
  • Confirm what a build is: docker image inspect ghcr.io/0x89karan/runtime1:full --format '{{.Created}}' shows its build date; the boot logs also print the agentos version.
  • Building locally instead of pulling? docker pull already fetches the newest by digest, but a local docker compose build caches — force a clean one with docker compose build --no-cache.
  • Pin a version for reproducibility: use an exact tag like ghcr.io/0x89karan/runtime1:v0.73.1 instead of :full/:latest when you want an unchanging build.
Troubleshooting
  • Inbox agent stuck at "Not authenticated" / "no active session" (with a valid google.json): your image predates the v0.73.2 Gmail-auth fix. Re-pull agentos:full (see Updating & older images above) and restart — older images never refresh the stored token, so oauth_check_auth returns no_session.
  • Container exits with "ANTHROPIC_API_KEY is not set": the key wasn't in the shell that ran docker run. Re-export it in this terminal, or use the agentos.env approach below.
  • Browser shows ERR_CONNECTION_REFUSED during auth: port 8585 was already in use when agentctl auth google started. Re-run with --port <free-port> — Desktop app clients accept any loopback port automatically.
  • No brief after a few minutes: check the cron fired and Gmail was reached — jq 'select(.kind=="mcp_tool_called")' ~/.agentos-data/flight.jsonl | tail. An empty result means the trigger hasn't fired yet.
  • Can't docker exec to watch: the container must have been started with --name agentos-cos (step 6).
Notes
  • Schedule: TRIGGER_INTERVAL="every 2m" (used above) is for testing and only accepts every N(s|m|h). For a daily brief use the separate cron variable: -e "TRIGGER_CRON=0 8 * * *" (08:00 UTC). A cron expression in TRIGGER_INTERVAL will not parse.
  • API key across shells: -e ANTHROPIC_API_KEY forwards it from the shell you exported in — run docker run in that same terminal, or put ANTHROPIC_API_KEY=sk-ant-... in ~/.agentos-secrets/agentos.env (the entrypoint sources it) so it survives across shells.
  • Talk to it interactively: instead of the autonomous cron brief, run the orchestrator REPL — docker run --rm -it -e ANTHROPIC_API_KEY ghcr.io/0x89karan/runtime1:full orchestrate.
  • Stopping: Ctrl+C triggers a graceful checkpoint. State is preserved in ~/.agentos-data — the next run resumes from where it left off.
  • Google auth on subsequent runs: The refresh token in google.json handles re-authorization automatically. No browser needed.
  • If OAuth fails: Re-run agentctl auth google with the same flags — it overwrites the token file.
  • Logs & receipts: everything the agents do is recorded in ~/.agentos-data/flight.jsonl — inspect it with jq. The signed action receipts are separate: verify the chain with agentctl verify ~/.agentos-data/evidence.jsonl.
  • Building agentctl: macOS has no prebuilt binary, so step 1's cargo build is required; on Linux you can download agentctl from GitHub Releases instead.
