# Spike: p3.3 — Kernel-Level Capability Enforcement

**Status:** Complete. Prototype landed in `p3.3-ebpf-lsm` branch.
**Date:** 2026-06-10

## Goal

Enforce the capability scopes defined in p1.4 at the kernel syscall boundary
for MCP server subprocesses, so that a server that exceeds its declared
filesystem access or attempts to spawn a child process is blocked by the OS —
not just by agentd's in-process tool registry.

---

## Mechanism Selected: Landlock LSM + seccomp-bpf

### Why not eBPF directly?

The roadmap increment is named "eBPF/LSM enforcement" but the correct tool here
is **seccomp-bpf** (which does use BPF programs) and the **Landlock LSM** (which
is a dedicated filesystem restriction mechanism). Raw eBPF programs attached to
LSM hooks (BPF LSM) require `CAP_BPF` and `CAP_SYS_ADMIN` or a kernel with
`CONFIG_BPF_LSM` + user-accessible policy. None of that is available in the
single-tenant agentOS model without root, which we want to avoid.

Landlock and seccomp-bpf are:
- **Unprivileged**: no capability required, available to any process.
- **Inherited**: applied to the child process via `pre_exec`, persists through exec.
- **Composable**: Landlock handles filesystem access; seccomp handles syscall filtering.

### Landlock LSM

Introduced in Linux 5.13 (`CONFIG_SECURITY_LANDLOCK=y`). Maps our
`FsRead`/`FsWrite` capabilities to filesystem access rules:

| Capability | Landlock access flags |
|---|---|
| `FsRead { prefix }` | `ReadFile \| ReadDir` (0x000C) |
| `FsWrite { prefix }` | All ABI V1 flags (0x1FFF = ReadFile..MakeSym) |

ABI version used: **V1** (Linux 5.13+). Our Buildroot 2024.02.9 ships Linux 6.6.x
LTS which fully supports V1. ABI V3 (Linux 6.4, adds `Refer`) and V4 (Linux 6.7,
adds network rules) are available in our kernel but deferred to Phase 4.

**Compat mode:** BestEffort. On kernels without Landlock (`ENOSYS`/`EOPNOTSUPP`
from `landlock_create_ruleset`), the ruleset fd is -1 and `landlock_restrict_self`
is skipped silently.

### seccomp-bpf

Classic BPF program installed via `prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, ...)`.
The filter checks the syscall number and kills the process on matches.

**Blocked syscalls (DenySpawn rule):**
- `execve` (59 on x86_64)
- `execveat` (322 on x86_64)
- `fork` (57 on x86_64 only; does not exist on aarch64)

**NOT blocked: `clone` / `clone3`**. These are used by Tokio's thread pool and
must remain available even in sandboxed async MCP servers.

Return action: `SECCOMP_RET_KILL_PROCESS` (sends SIGSYS, kills the whole process
group). This is stricter than `SECCOMP_RET_ERRNO` because a malicious server
should not be allowed to handle the error and retry.

## Architecture

### New `sandbox/` crate

A sibling crate (no circular dependency with `agentd/`) that defines:

```rust
pub enum SandboxRule { AllowFsRead { prefix }, AllowFsWrite { prefix }, DenySpawn }
pub struct CompiledSandbox { ... } // holds ruleset_fd + Option<BpfProgram>

pub fn compile(rules: &[SandboxRule]) -> Result<CompiledSandbox, SandboxError>;
pub fn apply_compiled(compiled: &CompiledSandbox) -> Result<(), SandboxError>;
pub fn apply_sandbox(rules: &[SandboxRule]) -> Result<(), SandboxError>; // convenience
```

On non-Linux: all types and functions are zero-size / no-op stubs. The crate
compiles on macOS (used for development) with no Linux-gated symbols.

### `caps_to_rules()` adapter in `agentd`

Converts `&[Capability]` (agentd's domain type) into `Vec<SandboxRule>` (sandbox
crate's domain type). Lives in `main.rs` to avoid a circular dep.

```
capabilities: None        → no sandbox (SandboxSkipped flight event)
capabilities: Some([])    → [DenySpawn]
capabilities: Some([...]) → DenySpawn (if no Spawn cap) + FS rules
```

### Per-server sandbox (not per-agent)

MCP servers are spawned once at startup, before any agent runs. The `capabilities`
field lives in `McpServerConfig`, not `AgentConfig`. This is intentional: a server
that allows any filesystem access grants it to all agents that can invoke it. The
agent-level capability system (p1.4) is the inner layer; this kernel enforcement
is the outer layer.

### `pre_exec` integration

```rust
// compile() runs in the parent — may allocate (CString for path fds)
let compiled = sandbox::compile(rules)?;

// pre_exec closure runs in the child after fork(), before exec()
// apply_compiled() is async-signal-safe: raw syscalls only, no allocation
cmd.pre_exec(move || {
    sandbox::apply_compiled(&compiled)
        .map_err(|_| std::io::Error::from_raw_os_error(libc::EPERM))
});
```

The Landlock ruleset fd is created in the parent (`compile()`), inherited by the
child after fork (O_CLOEXEC doesn't prevent fork inheritance), and used inside
`pre_exec` via `landlock_restrict_self(ruleset_fd, 0)`. After exec, the O_CLOEXEC
flag closes it in the child — correct because `restrict_self` has already fired.

## Kernel compat matrix

| Kernel | Landlock | seccomp-bpf | Status |
|---|---|---|---|
| < 3.17 | No | No | No sandbox (BestEffort pass) |
| 3.17–5.12 | No | Yes | seccomp only; Landlock no-op |
| 5.13+ | V1 | Yes | Full enforcement ✓ |
| 6.4+ | V3 (Refer) | Yes | V3 available; we use V1 |
| 6.6 (our LTS) | V3 | Yes | Our production target ✓ |
| 6.7+ | V4 (Network) | Yes | Network rules deferred to Phase 4 |

`CONFIG_SECURITY_LANDLOCK=y` added to `distro/kernel-extras.config`.

## Known limitations / Phase 4 items

1. **Network rules not enforced.** Landlock ABI V4 (Linux 6.7) adds
   `LANDLOCK_ACCESS_NET_BIND_TCP` and `LANDLOCK_ACCESS_NET_CONNECT_TCP`.
   The `Net { hosts }` capability is advisory at this layer. Enforce via
   Landlock V4 or a seccomp filter on `connect(2)` in Phase 4.

2. **`capabilities: None` runs unsandboxed.** For backward compatibility,
   an MCP server without a `capabilities` field in TOML runs with no kernel
   enforcement. A `SandboxSkipped` flight event and `tracing::warn!` are emitted.
   Phase 4 should make sandboxing opt-out rather than opt-in, or add a global
   `[tools] mcp_sandbox_default = "deny-all"` option.

3. **seccomp architecture check absent.** The BPF filter does not verify
   `seccomp_data.arch`. On a 64-bit host running a 32-bit MCP server
   (x86 compat layer), syscall numbers differ and the filter is ineffective.
   For agentOS this is a non-issue (we target x86_64 musl), but a production
   hardening pass should add the arch check.

4. **Symlink traversal via Landlock.** Landlock rules apply to the path prefix
   as opened at `compile()` time. A symlink inside the allowed prefix that
   points outside it is allowed (Landlock follows the link). Mitigated by the
   p1.4 `normalize_path` check (existing TODO in TODOS.md). Full mitigation
   requires a `landlock_create_ruleset` flag (not yet upstream) or bind-mounting
   in a user namespace.

5. **`apply_compiled` and the fork-malloc hazard.** The Landlock and seccomp
   steps inside `apply_compiled_inner` use only raw `libc::syscall` and `prctl`
   calls — no allocation. The `compile()` phase uses `CString::new` (allocation)
   but runs in the parent before fork. This is the correct split. Any future
   change that adds string operations inside `apply_compiled_inner` would
   reintroduce the fork-malloc deadlock risk (p3.3 review finding).

## Implementation summary

| Component | Change |
|---|---|
| `sandbox/` crate | New; raw Landlock + seccomp-bpf via `libc::syscall` / `prctl` |
| `agentd/src/config.rs` | `McpServerConfig.capabilities: Option<Vec<Capability>>` |
| `agentd/src/tools/mcp.rs` | `McpClient::spawn` gains `sandbox: Option<&[SandboxRule]>` |
| `agentd/src/main.rs` | `caps_to_rules()` adapter; `SandboxApplied`/`SandboxSkipped` events |
| `agentd/src/flight_recorder.rs` | `SandboxApplied`, `SandboxSkipped` event kinds |
| `agentd/tests/fixtures/sandbox_probe.rs` | Test fixture binary |
| `distro/kernel-extras.config` | `CONFIG_SECURITY_LANDLOCK=y` |

Flight events emitted:
- `sandbox_skipped { server }` — `capabilities` absent; running unsandboxed
- `sandbox_applied { server, rules }` — sandbox compiled and pre_exec hook installed

### TOML example

```toml
[[tools.mcp_servers]]
name = "my-fs-tool"
command = "/usr/bin/my-mcp-server"
capabilities = [
  { FsRead = { prefix = "/workspace" } },
  { FsWrite = { prefix = "/tmp" } },
]
```

Produces rules: `[DenySpawn, AllowFsRead{/workspace}, AllowFsWrite{/tmp}]`.
The server process cannot exec other programs; can read under `/workspace`; can
read and write under `/tmp`; cannot access any other path.
