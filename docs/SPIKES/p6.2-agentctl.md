## Goal

Add an operator CLI binary (`agentctl`) as a new workspace member. Two subcommands:

1. `agentctl list-templates` — list all available templates (repo + user dir), showing name, source, and showcases.
2. `agentctl spawn <template> --task "…"` — lower a template to an `agent.toml` file, then exec `agentd` with it.

No daemon, no inter-process communication, no TUI (that's p6.3). Works in QEMU over the serial console with the same 9p mounts as `agentd`.

## Scope

### In scope
- New `agentctl/` binary crate added to the workspace (`Cargo.toml` workspace member)
- `agentctl list-templates` — calls `TemplateResolver::list()`, formats as table: name · source (Repo/User) · showcases
- `agentctl spawn <template-name> --task <task> [--cap-add <cap>...]` — calls `TemplateResolver::resolve()` + `TemplateConfig::to_agent_config()`, writes a temp `agent.toml`, execs `agentd <path>`
- `--cap-add` flag uses a **flat named alias syntax** (not raw TOML): `fs-read:/path`, `fs-write:/path`, `kb-read:segment`, `kb-write:segment`, `net`, `spawn`. Parsed into `Capability` values by a `parse_cap_alias()` helper in `agentctl/src/spawn.rs`.
- Capability cap: `--cap-add` cannot grant a capability that is NOT in the template's `[card].suggested_caps: Vec<Capability>` list without `--force`. `suggested_caps` uses `Capability` directly (single vocabulary — no human-readable string aliases stored in the template file).
- `TemplateCard` gains `suggested_caps: Vec<Capability>` field (additive, `#[serde(default)]`).
- `agentctl` is compiled as a static musl binary alongside `agentd` (same cross-build target)
- CONVENTIONS.md updated with `agentctl/` module entry
- ROADMAP.md p6.2 checked off

## Architecture

### `agentd` must expose a `[lib]` target

`agentctl` needs `TemplateResolver`, `TemplateConfig`, `Capability`, and `Config` from `agentd`. Currently `agentd` has only `[[bin]]` entries — no `[lib]`. Fix: add to `agentd/Cargo.toml`:

```toml
[lib]
name = "agentd_lib"
path = "src/lib.rs"
```

`src/lib.rs` already exists and re-exports `pub mod template`, `pub mod capability`, `pub mod config`, etc. `agentctl/Cargo.toml` then depends on `agentd = { path = "../agentd" }`.

### New workspace member: `agentctl/`

```
agentctl/
  Cargo.toml        # bin crate, name = "agentctl"; dep: agentd (lib), clap, anyhow, toml
  src/
    main.rs         # clap CLI entry point; subcommand dispatch
    list.rs         # list-templates subcommand
    spawn.rs        # spawn subcommand; parse_cap_alias(); cap guard
```

### CLI interface

```
agentctl <SUBCOMMAND>

SUBCOMMANDS:
  list-templates              List available agent templates
  spawn <NAME> --task <STR>   Lower a template and exec agentd

agentctl list-templates
  --user-templates-dir <PATH>  Override user templates dir (default: ~/.agentos/templates/)
  --repo-dir <PATH>            Override repo templates dir (default: auto-detect)

agentctl spawn <NAME>
  --task <STR>                 Task override (required when template task = "")
  --cap-add <CAP>              Add a capability (repeatable; must be in suggested_caps or --force)
  --force                      Allow --cap-add beyond suggested_caps
  --user-templates-dir <PATH>  Override user templates dir
  --agentd-path <PATH>         Override agentd binary location
  --output-dir <PATH>          Write agent.toml here instead of a temp dir (debugging)
  --dry-run                    Print the generated agent.toml without running agentd
```

### `list-templates` output format

```
NAME         SOURCE   SHOWCASES
scout        Repo     read_file, list_dir, recursive exploration
```

Tab-aligned, no external formatting crate (tabwriter is acceptable if already in the dep tree, otherwise manual padding).

### `spawn` flow

1. `TemplateResolver::new(user_dir, repo_dir)` — resolves dirs (see QEMU paths below)
2. `resolver.resolve(name)` → `(TemplateConfig, TemplateSource)`
3. Parse each `--cap-add` string via `parse_cap_alias()` → `Vec<Capability>` (hand-rolled, NOT `toml::from_str`)
4. Validate each cap against `template.card.suggested_caps`: call `cap_add_allowed_by_suggestion(cap, suggested)`. Absent `card` or absent `suggested_caps` field → no guard (legacy template). Empty `suggested_caps = []` → every `--cap-add` requires `--force`.
5. `config.to_agent_config(task.as_deref(), extra_caps)` → `Config`
6. Serialize `Config` to TOML via `toml::to_string_pretty` (enabled by p6.1 `Serialize`)
7. Write via `tempfile::NamedTempFile::new_in(tmpdir)?.persist(final_path)` (O_EXCL, no TOCTOU). Path: `<tmpdir>/agentctl-<name>-<pid>.toml` (or `--output-dir`). File leaks after exec — acceptable in single-tenant QEMU context, noted in comment.
8. Resolve `agentd` binary: try directory of `agentctl` binary first (`std::env::current_exe()`), then `PATH`. `--agentd-path` overrides both.
9. `exec agentd <toml_path>` — replaces the agentctl process (`CommandExt::exec` on unix; blocking `Command::status()` + `exit()` on non-unix). On error: print path + OS error, exit 1.

On `--dry-run`: print the TOML to stdout, exit 0, no exec.

### QEMU in-image paths

```
/usr/bin/agentctl          — binary (new, alongside agentd)
/etc/agentd/templates/     — repo catalogue (scout.template.toml copied here by Makefile)
/run/user/templates/       — user templates dir (writable at runtime if needed)
```

`TemplateResolver::from_env()` uses `$AGENTOS_TEMPLATES_DIR` (user) and `$AGENTOS_REPO_TEMPLATES_DIR` (repo). Defaults: `~/.agentos/templates/` (user), `/etc/agentd/templates/` (repo in QEMU) or auto-detected repo `templates/` dir in dev. Both subcommands accept `--templates-dir` and `--repo-dir` overrides.

- Copy `agentctl` binary to `overlay/usr/bin/agentctl`
- `mkdir -p overlay/etc/agentd/templates && cp templates/*.template.toml overlay/etc/agentd/templates/`

### `parse_cap_alias()` — full contract

```rust
fn parse_cap_alias(s: &str) -> anyhow::Result<Capability>
```

| Input | Output |
|---|---|
| `fs-read:<path>` | `FsRead { prefix: normalize(path) }` — rejects non-absolute, empty |
| `fs-write:<path>` | `FsWrite { prefix: normalize(path) }` |
| `kb-read:<seg>` | `KbRead { segment: seg }` — rejects empty |
| `kb-write:<seg>` | `KbWrite { segment: seg }` |
| `spawn` | `Spawn` |
| `mcp:…` | `Err("mcp cannot be added via --cap-add; specify it in [agent].capabilities in the template")` |
| `net` | `Err("net requires ports: net:<port>[,<port>…]; e.g. net:443")` — see below |
| `net:<ports>` | `Net { hosts: [], ports: [p1, p2…] }` — comma-separated port list |
| unknown prefix | `Err("unknown alias 'foo'; valid: fs-read, fs-write, kb-read, kb-write, spawn, net:<ports>")` |

`net` without ports is rejected (avoids granting unrestricted outgoing TCP via a terse alias).
Path inputs: call `normalize_path(Path::new(raw))` and store the normalized form; reject if not absolute before normalization.

### `cap_add_allowed_by_suggestion()` — guard logic

Not `capability::satisfies()` (that answers "does this cap permit this action" — wrong direction). Dedicated function with per-variant rules:
- `FsRead/FsWrite`: allowed if `suggested_caps` contains an `FsRead/FsWrite` whose prefix is an ancestor of (or equal to) the requested prefix.
- `KbRead/KbWrite`: exact segment match or prefix match.
- `Net`: allowed if a `Net` entry in suggested_caps covers the requested ports (subset).
- `Spawn`: allowed if `Spawn` in suggested_caps.
- If `suggested_caps` is empty and no `--force`: all `--cap-add` denied.

## Error message spec

All errors follow: "error: <what failed>; <why>; <how to fix>"

| Scenario | Error text |
|---|---|
| Template not found | `error: template 'foo' not found; searched: <user_dir>, <repo_dir>; run 'agentctl list-templates' to see available` |
| task = "" and no --task | `error: template 'scout' has no default task; pass --task '…'` |
| --cap-add beyond suggested, no --force | `error: capability 'fs-read:/tmp' not in template 'scout' suggested_caps ([fs-read:/workspace]); use --force to override` |
| suggested_caps = [] strict mode | `error: template 'scout' has empty suggested_caps — all --cap-add requires --force` |
| agentd not found | `error: agentd not found at <resolved_path>; set --agentd-path or ensure agentd is in PATH` |
| ANTHROPIC_API_KEY missing | `error: ANTHROPIC_API_KEY is not set — agentd requires it` |
| Invalid cap alias | `error: unknown capability alias 'foo'; valid: fs-read:<path>, fs-write:<path>, kb-read:<seg>, kb-write:<seg>, spawn, net:<ports>` |
| Relative path in --cap-add | `error: 'fs-read:../../etc' — path must be absolute, got '../../etc'` |

## TODOS / open questions

1. **`suggested_caps` field on `TemplateCard`**: p6.1's `TemplateCard` has `showcases` but not `suggested_caps`. Add `suggested_caps: Vec<Capability>` with `#[serde(default)]` — uses the real `Capability` type (single vocabulary).
