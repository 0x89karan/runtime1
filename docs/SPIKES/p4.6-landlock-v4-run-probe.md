# p4.6 — Landlock V4 net enforcement + run_probe --log-path fix

## Summary

Two items:
1. **run_probe --log-path** (3-line fix): `run_probe` ignores `--log-path`; thread
   `log_path_override` through so `--probe --log-path /tmp/flight.jsonl` works.
2. **Landlock V4 TCP port enforcement** (full wiring): add `AllowNetConnect { port: u16 }`
   to `SandboxRule`; add `ports: Vec<u16>` to `Net` capability; wire `caps_to_rules()` to
   generate `AllowNetConnect` rules; implement V4 syscall structs + runtime ABI detection.

## Architecture decisions locked (D1 = A)

- `AllowNetConnect { port: u16 }` — port-only. Landlock V4 enforces TCP ports, not hostnames.
  A `host` field in the sandbox rule would be unenforced at the kernel layer and misleading.
  Host strings stay in the `Net { hosts }` capability field (advisory, for future DNS-filter
  use), but they do NOT flow into `AllowNetConnect`.
- `Net { hosts: Vec<String>, ports: Vec<u16> }` — add `ports` field with `#[serde(default)]`.
  Empty ports = no Landlock net enforcement (backward-compatible with all existing configs).
- Runtime BestEffort degradation: query ABI version via `landlock_create_ruleset(NULL, 0, 1)`.
  V4 available → add net rules; V3/V1 → silently skip net rules, FS rules still apply.
- `IsolateNetwork` (namespace) and `AllowNetConnect` (Landlock port rules) are mutually exclusive
  in the capability-driven path: no `Net` cap → `IsolateNetwork`; `Net` with ports → `AllowNetConnect`
  rules; `Net` with empty ports → neither (unrestricted, same as today).

## Implementation: sandbox/src/lib.rs

### New constants (in `linux` mod)

```rust
// Landlock ABI version query flag
const LANDLOCK_CREATE_RULESET_VERSION: libc::c_int = 1;

// Landlock V4 net access flags (Linux 6.7+)
const LANDLOCK_ACCESS_NET_CONNECT_TCP: u64 = 1 << 1; // outgoing TCP connections

// Landlock V4 rule type
const LANDLOCK_RULE_NET_PORT: libc::c_long = 3;
```

### New structs

```rust
struct LandlockRulesetAttrV4 {
    handled_access_fs:  u64,
    handled_access_net: u64,
}

// V4 net port rule
#[repr(C)]
struct LandlockNetPortAttr {
    allowed_access: u64,
    port:           u64,  // kernel uses u64 even though ports fit in u16
}
```

### ABI version detection (in `compile()`)

```rust
fn query_landlock_abi_version() -> i64 {
    unsafe {
        libc::syscall(
            SYS_LANDLOCK_CREATE_RULESET,
            std::ptr::null::<libc::c_void>(),
            0_libc::size_t,
            LANDLOCK_CREATE_RULESET_VERSION,
        )
    }
    // Returns version (1..4) on success, -1 on ENOSYS/EOPNOTSUPP (no Landlock).
}
```

### `compile()` net rule path

Pseudocode added to the existing `compile()` function in the Linux mod:

```rust
// Collect AllowNetConnect ports
let net_ports: Vec<u16> = rules.iter().filter_map(|r| {
    if let SandboxRule::AllowNetConnect { port } = r { Some(*port) } else { None }
}).collect();

// If net ports requested, detect ABI version and build ruleset with V4 struct
let (landlock_fd, landlock_net_active) = if !path_entries.is_empty() || !net_ports.is_empty() {
    let abi_version = query_landlock_abi_version();
    let use_v4_net = abi_version >= 4 && !net_ports.is_empty();
    let fd = build_landlock_ruleset_v4(&path_entries, &net_ports, use_v4_net)?;
    (fd, use_v4_net && fd >= 0)
} else {
    (-1, false)
};
```

### `build_landlock_ruleset_v4` (replaces `build_landlock_ruleset`)

When `use_v4_net`:
- Use `LandlockRulesetAttrV4` struct with `handled_access_net = LANDLOCK_ACCESS_NET_CONNECT_TCP`
- Pass `size_of::<LandlockRulesetAttrV4>()` to the syscall
- After FS rules, add `LANDLOCK_RULE_NET_PORT` rules for each port

When !`use_v4_net` (V1/V3 kernel or no net ports):
- Use existing `LandlockRulesetAttr` with only `handled_access_fs`
- Pass `size_of::<LandlockRulesetAttr>()` (8 bytes, not 16) — critical: passing V4 size to V3 kernel returns EINVAL

### `apply_compiled_inner()` net addition

The net Landlock rules are already baked into the `landlock_fd` at compile time. No change needed in `apply_compiled_inner()` — the existing `landlock_restrict_self` call activates all rules (FS + net) on the already-created ruleset fd.

## Key implementation invariant

The size passed to `landlock_create_ruleset` **must match the struct** used:
- V1-V3 kernels: pass `size_of::<LandlockRulesetAttr>()` = 8 bytes (fs-only struct)
- V4+ kernels: pass `size_of::<LandlockRulesetAttrV4>()` = 16 bytes (fs + net struct)

Passing the V4 size to a V3 kernel returns EINVAL, which (unlike ENOSYS/EOPNOTSUPP)
is NOT a BestEffort-tolerable error — it means "bad args". The ABI version check MUST
gate the struct size selection. Do not use the V4 struct path without first confirming
`abi_version >= 4`.
