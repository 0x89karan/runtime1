## T1 — checkpoint.json chmod 0600

### Problem

`CheckpointStore::save()` calls `tokio::fs::write(&self.tmp_path, &json)`. This creates
the tmp file using the process umask (typically 0644 — world-readable). The rename
then atomically replaces `checkpoint.json` with the same permissions. On a shared
filesystem, the full agent conversation history (unredacted) is readable by any user
on the box for the duration of the run.

### Fix

Replace the `tokio::fs::write` call with a helper that creates the file with mode 0600:

```rust
// In checkpoint.rs

#[cfg(unix)]
async fn write_mode_600(path: &std::path::Path, data: &[u8]) -> std::io::Result<()> {
    use std::os::unix::fs::OpenOptionsExt;
    use tokio::io::AsyncWriteExt as _;
    let mut f = tokio::fs::OpenOptions::new()
        .write(true)
        .create(true)
        .truncate(true)
        .mode(0o600)
        .open(path)
        .await?;
    f.write_all(data).await
}

#[cfg(not(unix))]
async fn write_mode_600(path: &std::path::Path, data: &[u8]) -> std::io::Result<()> {
    tokio::fs::write(path, data).await
}
```

Update `save()` to call `write_mode_600(&self.tmp_path, json.as_bytes())`.

**Why the rename is safe:** `rename(2)` on Linux atomically replaces the destination
with the source — it does not inherit the destination's permissions. The final
`checkpoint.json` gets 0600 from the renamed tmp file.

**Non-Unix fallback:** On Windows (hypothetical; production target is Linux), fall back
to `tokio::fs::write` — Windows has a different ACL model and 0600 doesn't map.

### Test

```rust
#[cfg(unix)]
#[tokio::test]
async fn checkpoint_save_sets_mode_0600() {
    use std::os::unix::fs::PermissionsExt;
    let dir = tempfile::TempDir::new().unwrap();
    let store = CheckpointStore::new(dir.path());
    store.save(&minimal_scheduler_checkpoint()).await.unwrap();
    let meta = std::fs::metadata(dir.path().join("checkpoint.json")).unwrap();
    let mode = meta.permissions().mode() & 0o777;
    assert_eq!(mode, 0o600, "checkpoint.json must be mode 0600, got 0o{mode:03o}");
}
```

## T2 — pre_exec error propagation

### Problem

When `apply_compiled()` fails in `pre_exec` (e.g. Landlock `prctl` returns EINVAL),
the error is thrown away and replaced with `EPERM`. The parent's `McpClient::spawn()`
gets an `io::Error(EPERM)` from the child's exit status with no indication whether:
- The sandbox application failed (Landlock/seccomp step)
- The MCP server binary wasn't found
- Some other pre-exec issue occurred

### Fix

Use a pre-exec error pipe (classic Unix pattern) to propagate the failure stage:

```
pre-fork:   parent creates (read_fd, write_fd) with O_CLOEXEC
fork:       child has both fds; parent retains both
pre_exec:   if apply_compiled fails → write b"sandbox" to write_fd → return Err(EPERM)
exec:       if apply_compiled succeeds → exec runs → O_CLOEXEC closes write_fd in child
parent:     close write_fd; if spawn returned Err, read from read_fd for stage tag;
            close read_fd; include stage tag in error message
```

O_CLOEXEC on `write_fd` means: on exec success, the fd is auto-closed in the child →
parent's `read(read_fd)` returns 0 (EOF) immediately. On exec failure (pre_exec error),
exec doesn't run, so O_CLOEXEC doesn't fire; child writes the stage tag and exits →
parent reads the tag.

**Implementation in `McpClient::spawn()` (Linux section):**

```rust
#[cfg(target_os = "linux")]
if let Some(compiled) = sandbox {
    // Create the error-propagation pipe. O_CLOEXEC closes the write end in
    // the child if exec succeeds (parent reads EOF = no error).
    let mut pipe_fds: [libc::c_int; 2] = [-1; 2];
    let ret = unsafe { libc::pipe2(pipe_fds.as_mut_ptr(), libc::O_CLOEXEC) };
    if ret != 0 {
        return Err(std::io::Error::last_os_error())
            .context("sandbox error pipe")?;
    }
    let (read_fd, write_fd) = (pipe_fds[0], pipe_fds[1]);

    unsafe {
        cmd.pre_exec(move || {
            if let Err(_) = sandbox::apply_compiled(&compiled) {
                // async-signal-safe: raw write syscall only
                let tag = b"sandbox";
                let _ = libc::write(write_fd, tag.as_ptr() as *const libc::c_void, tag.len());
                return Err(std::io::Error::from_raw_os_error(libc::EPERM));
            }
            Ok(())
        });
    }

    let spawn_result = cmd.spawn();

    // Parent releases write end — ensures our read returns EOF (not block forever)
    // when exec succeeded (O_CLOEXEC + parent-close = both writers gone).
    unsafe { libc::close(write_fd) };

    let child = match spawn_result {
        Ok(c) => {
            unsafe { libc::close(read_fd) };
            c
        }
        Err(e) => {
            let mut buf = [0u8; 16];
            let n = unsafe {
                libc::read(read_fd, buf.as_mut_ptr() as *mut libc::c_void, buf.len())
            };
            unsafe { libc::close(read_fd) };
            let stage = if n > 0 {
                std::str::from_utf8(&buf[..n as usize]).unwrap_or("unknown").to_owned()
            } else {
                "unknown".to_owned()
            };
            return Err(anyhow::anyhow!(
                "spawning MCP server '{}' failed (sandbox stage: '{}'): {}",
                command, stage, e
            ));
        }
    };
    // ... continue with stdin/stdout/handshake using child
}
```

**Notes:**
- `libc::write` and `libc::read` are async-signal-safe — safe in pre_exec and in parent
- The write_fd close in parent must happen before the read_fd read so the read sees EOF
  from exec-success, not blocks waiting for the parent's write_fd to be released
- The non-Linux path (`#[cfg(not(target_os = "linux"))]`) stays unchanged (no sandbox)

### Test

Hard to test in isolation without triggering a real sandbox failure. The improvement
is observable in logs: spawn failure messages now include "(sandbox stage: 'sandbox')".

Update THREAT_MODEL.md §6 to note pre_exec errors now include a stage tag.

## T3 — sandbox_probe integration test

### Background

`sandbox_probe` is declared as `[[bin]]` in `agentd/Cargo.toml` at
`tests/fixtures/sandbox_probe.rs`. It accepts `--path <file>` and `--exec` flags:
- `--path <file>`: exit 0 = read succeeded; exit 1 = EACCES/EPERM; exit 2 = other error
- `--exec`: exit 0 = exec succeeded (bad — sandbox not working); non-0 = blocked

Since sandbox_probe doesn't speak MCP protocol, tests use `tokio::process::Command`
directly with `pre_exec` to apply sandbox rules — bypassing McpClient. This still
verifies the full sandbox enforcement path (compile → apply_compiled → child behavior).

### Tests (Linux-only)

```rust
#[cfg(target_os = "linux")]
mod sandbox_probe {
    use sandbox::{compile, apply_compiled, SandboxRule};
    use std::os::unix::process::CommandExt;
    use tempfile::TempDir;
    use tokio::process::Command;

    fn probe_bin() -> &'static str {
        env!("CARGO_BIN_EXE_sandbox-probe")
    }

    // T3.1: AllowFsRead on tmpdir grants read access inside it
    #[tokio::test]
    async fn allowed_path_read_succeeds() {
        let dir = TempDir::new().unwrap();
        let file = dir.path().join("secret.txt");
        std::fs::write(&file, b"contents").unwrap();

        let rules = vec![
            SandboxRule::AllowFsRead { prefix: dir.path().to_str().unwrap().to_owned() },
        ];
        let compiled = compile(&rules).expect("compile");

        let mut cmd = Command::new(probe_bin());
        cmd.args(["--path", file.to_str().unwrap()]);
        unsafe {
            cmd.pre_exec(move || {
                apply_compiled(&compiled)
                    .map_err(|_| std::io::Error::from_raw_os_error(libc::EPERM))
            });
        }
        let status = cmd.spawn().unwrap().wait().await.unwrap();
        assert_eq!(status.code(), Some(0), "read inside AllowFsRead prefix should succeed");
    }

    // T3.2: AllowFsRead on tmpdir denies reads outside it
    #[tokio::test]
    async fn denied_path_read_fails() {
        let dir = TempDir::new().unwrap();
        let rules = vec![
            SandboxRule::AllowFsRead { prefix: dir.path().to_str().unwrap().to_owned() },
        ];
        let compiled = compile(&rules).expect("compile");

        let mut cmd = Command::new(probe_bin());
        cmd.args(["--path", "/etc/hostname"]);
        unsafe {
            cmd.pre_exec(move || {
                apply_compiled(&compiled)
                    .map_err(|_| std::io::Error::from_raw_os_error(libc::EPERM))
            });
        }
        let status = cmd.spawn().unwrap().wait().await.unwrap();
        assert_eq!(status.code(), Some(1), "read outside AllowFsRead prefix should be denied");
    }

    // T3.3: DenySpawn blocks exec inside the sandbox
    #[tokio::test]
    async fn deny_spawn_blocks_exec() {
        let rules = vec![SandboxRule::DenySpawn];
        let compiled = compile(&rules).expect("compile");

        let mut cmd = Command::new(probe_bin());
        cmd.arg("--exec");
        unsafe {
            cmd.pre_exec(move || {
                apply_compiled(&compiled)
                    .map_err(|_| std::io::Error::from_raw_os_error(libc::EPERM))
            });
        }
        let status = cmd.spawn().unwrap().wait().await.unwrap();
        assert_ne!(status.code(), Some(0), "DenySpawn must block exec (exit non-0)");
    }
}
```

**Note on DenySpawn test:** DenySpawn uses seccomp BPF to block fork/vfork (not execve
directly). `sandbox_probe --exec` spawns `/bin/true` via `Command::new(...).status()`,
which internally calls fork+exec. The seccomp filter kills the process on fork → the
probe exits non-zero. Test passes only on x86_64 (seccomp filter is x86_64-only per
the existing architecture gate). Gate T3.3 additionally with
`#[cfg(target_arch = "x86_64")]`.

**libc in tests:** `libc` is already in `[dependencies]` (not just dev-deps), so the
`EPERM` constant is available in integration tests.

## T4 — --no-fuse flag

### Problem

`surfaces::agents_fs::mount()` is called unconditionally on Linux in `main.rs`. On a
host dev machine without FUSE available (or in CI without the FUSE kernel module),
the mount fails and `tracing::warn!` fires. The behavior is correct but the warning
is noisy for developers who know FUSE isn't available — there's no way to say
"I know, skip it intentionally."

### Fix

**Arg parsing change:** Collect args, strip `--no-fuse` flag, dispatch remaining as before.

```rust
// In main()
let raw_args: Vec<String> = std::env::args().skip(1).collect();
let no_fuse = raw_args.contains(&"--no-fuse".to_string());
let filtered: Vec<&str> = raw_args.iter()
    .filter(|a| *a != "--no-fuse")
    .map(String::as_str)
    .collect();

let result = match filtered.first().copied() {
    Some("--probe") => {
        let prompt = filtered.get(1).copied()
            .ok_or_else(|| anyhow::anyhow!("--probe requires a prompt argument"))?;
        run_probe(prompt).await
    }
    Some(path) => run_agent(PathBuf::from(path), no_fuse).await,
    None => run_agent(PathBuf::from("agent.toml"), no_fuse).await,
};
```

**run_agent signature:** Add `no_fuse: bool` parameter.

**FUSE mount block change:**

```rust
#[cfg(target_os = "linux")]
let maybe_session = if no_fuse {
    tracing::info!("FUSE mount skipped (--no-fuse)");
    None
} else {
    match surfaces::agents_fs::mount(&fuse_mountpoint, Arc::clone(&snapshot)) {
        Ok(session) => {
            recorder.record(...FuseMounted...);
            Some(session)
        }
        Err(e) => {
            tracing::warn!("FUSE mount failed (continuing without /agents): {e}");
            None
        }
    }
};
```

Also support `AGENTOS_NO_FUSE` env var as a CI-friendly alternative:
```rust
let no_fuse = no_fuse || std::env::var("AGENTOS_NO_FUSE").is_ok();
```

This allows CI pipelines to set the env var without changing the command invocation.

### Test

No unit test needed — the flag just toggles a conditional. Add a `no_fuse_skips_mount`
test only if it can be done without FUSE infrastructure (it can: just verify the flag
is parsed and no FuseMounted event is emitted). This is a functional test via integration
tests — lower priority for this sprint.
