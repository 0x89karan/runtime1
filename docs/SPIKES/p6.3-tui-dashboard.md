# p6.3 — Read-only TUI: dashboard + agent detail + system

**Status:** Planning — branch `p6.3-tui-dashboard`, base v0.28.0
**Branch:** p6.3-tui-dashboard
**Version target:** v0.29.0
**Depends on:** p6.2 (agentctl binary crate), p3.1 (FUSE `/agents/` surface)

---

## Goal

Add a live, read-only TUI (`agentctl watch`) that shows the operator what the
multi-agent runtime is doing — without opening a separate shell or grepping logs.
Three views:

1. **Dashboard** — table of all running agents; status, turns, context%, budget%
2. **Agent detail** — per-agent deep view: task preview, tool list, memory snapshots, flight log tail
3. **System** — global view: total budget, queue depth, sandbox status, provider info

The TUI reads existing FUSE virtual files from `/agents/<id>/*` plus two new
surfaces that `surfaces/` must expose: `/agents/<id>/tools` and
`/agents/system/{budget,queue,sandbox,provider}`.

## Scope

### In scope

**`agentctl/`:**
- New `watch` subcommand: `agentctl watch [--agents-dir <path>] [--plain] [--no-plain]` (default dir `/agents`)
  - `--plain`: force plain text mode
  - `--no-plain`: force TUI mode, bypassing TERM-based auto-detection
  - Auto-plain triggers when `TERM=dumb|vt100|linux` or stdout is not a TTY; prints notice to stderr
- `ratatui` + `crossterm` deps in `agentctl/Cargo.toml`
- `agentctl/src/watch/` module with three view structs: `DashboardView`, `AgentDetailView`, `SystemView`

**Keyboard navigation:**
- `q` / `Ctrl-C` = quit (always restore terminal: disable raw mode, exit alternate screen)
- `↑`/`↓` = select agent in dashboard OR scroll flight log in detail view
- `Enter` = open agent detail for selected agent
- `Tab` = cycle views: Dashboard → System → Dashboard (detail view is entered via Enter only)
- `Esc` = back to dashboard from any other view

**Dashboard table layout (operator-first ordering):**
- Column order: Status | ID (truncated) | Ctx% | Budget% | Turn | Tools#
- Status column is leftmost — operators scan for problems first
- ID column: max 16 chars, truncate with `…` suffix
- Ctx% and Budget%: show as `87%` (4 chars); if Ctx% ≥ 90 or Budget% ≥ 90, use highlight color
- Sort order: unhealthy/failed first, then running (by budget% desc), then done/deferred
- When agent count > terminal height − 4: scroll with `↑`/`↓`; show row count in title bar
- Selection tracked by `selected_id: Option<String>` (not index); stable when agents appear/disappear

**Terminal compatibility (designed-first, not afterthought):**
- Detect TERM: if `TERM=dumb`, `TERM=vt100`, `TERM=linux`, or no TERM set → use `--plain` mode automatically
- ASCII border fallback: detect Unicode support via `TERM` and `LANG`; use `+`/`-`/`|` when uncertain
- Minimum terminal width: 80 columns. If `<80`, show error: "Terminal too narrow (need ≥80 cols)"
- Color depth: detect 256-color support; fall back to 8-color if not; no color assumptions baked in

**`--plain` mode** (for QEMU serial, `TERM=dumb`, `--plain` flag):
- Disables alternate screen, disables raw mode
- Prints a refreshing table to stdout using `\r\n` + reprint only — **no ANSI escape sequences** (`\x1b[2K` or similar are incompatible with `TERM=dumb`)
- Same 1 Hz refresh loop; `q` + Enter to quit (no raw key input)
- When auto-plain engages, print to stderr: `note: plain mode (TERM={t}; use --no-plain to override)`

**`--no-plain` override flag:**
- `--no-plain` bypasses all auto-detection and forces TUI mode even on `TERM=linux`
- Use when SSH config or container sets TERM incorrectly but the terminal supports TUI

**Interaction states — all defined:**
- Loading (tick 0, no data yet): "Connecting to /agents/…" spinner or "Loading"
- Zero agents running: empty dashboard with headers + "No agents running" message
- FUSE not mounted: "FUSE surface not mounted — start agentd first"
- Agent detail with empty tools: shows `-` in tools column
- Agent detail with empty flight log: shows "(no events)"
- Agent detail with empty memory: shows "(no memory)"
- Agent terminates while detail is open: show "(agent completed)" in status; auto-return to dashboard after 3 s
- System view when sandbox_applied = false: shows "WARN: unsandboxed" in red/bold
- JSON parse error on system file: shows "?" for that field, not panic
- SIGINT/panic: ensure `crossterm::terminal::disable_raw_mode()` + `LeaveAlternateScreen` in all exit paths (using `Drop` **AND** `std::panic::set_hook` — both are required; `Drop` handles normal early returns, `set_hook` handles panics; using only one leaves the other exit path uncovered)

**Polling:**
- Dashboard view: 1 Hz
- Agent detail view — flight log: 2 Hz (more responsive to active inference)
- Selection model: `selected_id: Option<String>`; when selected agent disappears, fall back to first agent

- No write operations; read-only throughout
- `ratatui` ≥ 0.28, `crossterm` ≥ 0.28 — check for musl-static compatibility

**`surfaces/` amendments (Linux-gated, must pass `make clippy-linux`):**
- `AgentStatus` enrichment: add `AwaitingInference` and `AwaitingTool` variants alongside existing `AwaitingChild(String)`. `Running` is further disambiguated via snapshot when the agent is mid-turn: `AgentSnapshot::running_phase: Option<RunningPhase>` where `RunningPhase = { Inference, ToolExec }`.
- Actually simpler approach: add `AwaitingInference` and `AwaitingTool` as two new variants of `AgentStatus` (orthogonal to `AwaitingChild`). No `RunningPhase` sub-enum needed.
- Per-agent `tools` virtual file: `OFF_TOOLS = 8`, inode = agent_base + 8; content = newline-separated tool names, alphabetically sorted
- `SchedulerSnapshot` gains `queue_depth: usize` field (number of agents currently in the deferred queue, currently omitted from the snapshot struct)
- `/agents/system/` virtual directory: fixed inode 10
  - `system/budget` = inode 11: `{spent: u64, budget: u64}` JSON
  - `system/queue`  = inode 12: `{depth: usize}` JSON
  - `system/sandbox` = inode 13: `{applied: bool, mode: String}` JSON (reads from flight events or a new `SandboxStatus` snapshot field)
  - `system/provider` = inode 14: `{model: String, backend: String}` JSON (reads from config — expose in snapshot)
- `AgentsFs` struct: add 4 new fixed inodes (10-14) for system subtree, 1 new per-agent offset (+8=tools); update `readdir(Root)` to emit `system/` dir entry; update `getattr` + `read` for all new paths
- `snapshot.rs`: `AgentSnapshot` gains `tools: Vec<String>` field (populated from `ToolRegistry`); `SchedulerSnapshot` gains `queue_depth: usize`, `provider_model: String`, `sandbox_applied: bool` fields
- `surfaces` unit tests: ≥ 15 new tests covering new inodes, new status variants, system dir

### Out of scope
- Writable surfaces (`/agents/control`) — deferred to p6.6
- Topology graph view — p6.4
- Memory browser tab — p6.5
- Spawn view — p6.6
- Mouse support — not needed for a terminal OS operator
- Color themes / config — not yet; default 256-color palette only
- p6.3 does NOT change `agentd/` scheduler logic — new snapshot fields are populated by `main.rs` when building the snapshot, not by deeper scheduler changes

## Architecture

```
agentctl watch
    │
    ├── WatchApp (crossterm event loop, 1 Hz timer)
    │       ├── App::tick()  — re-read all FUSE files → update AppState
    │       └── App::draw()  — ratatui frame render
    │
    ├── AppState
    │       ├── agents: Vec<AgentRow>  (from /agents/<id>/{status,context_size,budget,tools})
    │       ├── system: SystemRow      (from /agents/system/{budget,queue,sandbox,provider})
    │       └── selected_id: Option<String>  (stable selection by agent ID)
    │
    ├── DashboardView
    │       └── ratatui Table widget: Status | ID | Ctx% | Budget% | Turn | Tools#
    │
    ├── AgentDetailView
    │       ├── Header: id, status, turn
    │       ├── Task: task_preview (from /agents/<id>/status)
    │       ├── Tools: /agents/<id>/tools
    │       ├── Memory: /agents/<id>/memory/short_term (first 5 items)
    │       └── Flight: /agents/<id>/flight (last 10 lines)
    │
    └── SystemView
            ├── Budget: global_tokens_spent / token_budget (% bar)
            ├── Queue: deferred agent count (0 = "idle")
            ├── Sandbox: applied=YES (green) / WARN: unsandboxed (red)
            └── Provider: model name + backend string
```

## Implementation Steps

### Step 1 — `surfaces/` amendments (must compile + pass `make clippy-linux`)

1a. **Inode collision audit (required before any code):** Verify that inodes 10–14 are unoccupied in the current scheme (root=1, kb=9, first-agent=1010, dynamic≥1M). Confirm `OFF_TOOLS=8` fits in `DIR_STEP`. **Bump `DIR_STEP` from 10 to 20** in this increment (current scheme uses 0–8 = 9 slots, 10-step is at 90%; add `const_assert!` equivalent: `static_assertions::const_assert!(OFF_TOOLS < DIR_STEP - 1)`). Document the inode map in a comment block above the new constants.

1b. **`snapshot.rs`**: Add `tools: Vec<String>` to `AgentSnapshot` (capability-filtered, from `AgentTask`'s filtered spec names — NOT global `tool_names()`); add `queue_depth: usize`, `provider_model: String`, `sandbox_applied: bool` to `SchedulerSnapshot`. All new fields have `#[serde(default)]`. **`AwaitingInference`/`AwaitingTool` variants REMOVED from p6.3 scope entirely** (all references to them have been removed from this plan — see Decision Audit Trail #1).

1c. **`agents_fs.rs`**: Add constants `OFF_TOOLS = 8`, `INO_SYSTEM = 10`, `INO_SYS_BUDGET = 11`, `INO_SYS_QUEUE = 12`, `INO_SYS_SANDBOX = 13`, `INO_SYS_PROVIDER = 14`. **Critically:** add `ParentKind::SystemDir` and `ParentKind::SystemFile(u64)` enum variants to the `parent_kind()` dispatch. Add `getattr` + `lookup` branches for system dir (INO_SYSTEM) and its 4 children (11–14) that check these new variants — do NOT route system inodes through `inode_to_id` (they are not in that map). Add `file_content_for_ino()` branches for `INO_SYS_BUDGET..=INO_SYS_PROVIDER` that format JSON directly. Add `read` handlers for the per-agent `tools` inode (base + OFF_TOOLS) through the existing inode_to_id path.

System file JSON formats (exactly):
- `system/budget`: `{"spent":U,"total":0,"resettable":bool}` (U = u64; `resettable` added by
  ux.13-TUI — it tells the cockpit whether a budget-based park is a pause or a kill)
- `system/queue`: `{"depth":N}` (N = usize)
- `system/sandbox`: `{"applied":B}` (B = bool) — **as planned in p6.3; the shipped shape is
  `{"any_sandboxed":B,"servers":[…],"degradations":[…]}`**, grown by p6.8's enforcement surface.
  `docs/CONVENTIONS.md` carries the current one.
- `system/provider`: `{"model":"S","backend":"S"}` (S = String; `backend` is hardcoded `"anthropic"`)

**Shared serde types:** Define `SysBudget`, `SysQueue`, `SysSandbox`, `SysProvider` structs in `surfaces/src/snapshot.rs` with `Deserialize` so that `agentctl/src/watch/reader.rs` can use them without `serde_json::from_str()` on ad-hoc strings.

3. **`surfaces/` tests**: Add ≥ 15 tests: tools file content, system dir `readdir`, `getattr` for each system file, new status variant serialization.

### Step 2 — `agentd/scheduler.rs` + `main.rs` snapshot wiring

Wire the new snapshot fields:
- `queue_depth`: in `update_snapshot()` (in `scheduler.rs`), set from `state.deferred.len()`
- `tools`: in `update_snapshot()`, set per agent from `task.filtered_spec_names()` (capability-filtered names, not global `tool_names()`). Add `filtered_spec_names() -> Vec<String>` method to `AgentTask` if not present.
- `sandbox_applied`: set ONCE at scheduler startup (before the first `update_snapshot()`), via a blocking `write()` call on the snapshot Arc — not via `try_write()`. Never set again. Value comes from `had_sandbox` in `main.rs`.
- `provider_model`: set ONCE at scheduler startup via blocking `write()`, from `cfg.model.model_id` or similar. Never set again.

The blocking `write()` for static fields is safe at startup (no FUSE handler is reading yet); `try_write()` is only needed in the hot path.

### Step 3 — `agentctl/` watch subcommand

1. Add `ratatui`, `crossterm` to `agentctl/Cargo.toml`
2. Create `agentctl/src/watch/` module: `mod.rs` (Args, run entry), `app.rs` (WatchApp, event loop), `views.rs` (three view structs), `reader.rs` (FUSE file readers → typed structs)
3. Wire `Commands::Watch(watch::Args)` in `main.rs`
4. `make clippy-linux` clean (the watch module reads files — no Linux-gated code needed in `agentctl/`, only in `surfaces/`)
5. `reader.rs` contract:
   - `AgentFiles::read(agent_id, agents_dir) -> Option<AgentRow>`: reads all per-agent files; if ANY file returns ENOENT, returns `None` (entire agent discarded for this tick — no partial rows)
   - Ctx% = `context_size_bytes / budget_total * 100` (derive from two FUSE files)
   - System files parsed using shared serde types from `surfaces::snapshot::{SysBudget, SysQueue, SysSandbox, SysProvider}`
   - `flight` file: ONLY read when view is `AgentDetailView` AND this is the selected agent
6. SIGTERM handling: install a SIGTERM handler in `app.rs` (via `ctrlc` crate or `signal_hook`) that sets an `AtomicBool` exit flag; the event loop checks this flag on each tick before rendering. On any exit path (normal, panic, signal): call `crossterm::terminal::disable_raw_mode()` + `execute!(stdout(), LeaveAlternateScreen)`. Implement via **both** a `CleanupGuard` struct with `Drop` (for normal exits + early returns) **and** `std::panic::set_hook` (for panics). Using only `Drop` leaves panic paths uncleaned; using only `set_hook` leaves normal-return paths uncleaned.
7. Non-TTY auto-plain: on startup, check `crossterm::terminal::is_raw_mode_enabled()` failure OR `!std::io::stdout().is_terminal()` → auto-select `--plain` mode. CI smoke test uses this to avoid needing a real PTY. When auto-plain engages, print: `eprintln!("note: plain mode ({reason}); use --no-plain to force TUI")`.
8. Startup mount validation: on startup, check that `{agents_dir}/system/` exists. If absent, print: `"warning: {agents_dir} does not look like an agentd FUSE mount (no system/ directory found) — start agentd first"`. This catches the common case where the operator runs `agentctl watch` before agentd auto-mounts FUSE.

### Step 4 — Binary size check

`ratatui` + `crossterm` add ~1-1.5 MB to the musl binary. The current 4 MB guard on `agentctl` must still pass after adding deps. If it fails: bump guard to 6 MB (consistent with agentd) — **do not split into a separate binary** (see Decision Audit Trail #2). Enable LTO on release builds if binary exceeds 5 MB.

### Step 5 — Integration test

Add a CI integration test (startup smoke test only — rendering tests are manual):
- Start `agentctl watch --agents-dir /tmp/mock-agents` with a mock directory (no live agentd needed)
- Verify the TUI exits 0 when `q` is piped to stdin
- Verify the TUI prints a degradation message (not panics) when the agents dir is missing

**Manual acceptance test procedure:** Start the multi-agent demo (`agentd agents.toml`), mount FUSE at `/agents`, run `agentctl watch --agents-dir /agents`, confirm all three views render. Then kill one agent mid-run and confirm the TUI handles the mid-poll race without crash (agent-terminates-during-poll acceptance criterion).

**QEMU serial console test:** Boot the QEMU image, confirm `TERM=linux` or `TERM=vt100` is set, run `agentctl watch`, verify crossterm does not render garbage. If it does, implement `crossterm::terminal::disable_raw_mode()` fallback to `--plain` output mode.

## Open Questions

1. **`sandbox_applied` source:** The current `SandboxApplied` flight event is logged but not captured in the snapshot. Option A: add a `sandbox_applied: bool` field to `SchedulerSnapshot`, set at startup in `main.rs`. Option B: read from flight events at snapshot build time. **Recommend A** — simpler, no log-parsing overhead.

2. **`provider_model` source:** Config already has `[agent].model`; the scheduler has it per-agent. For the system view we want the global default. Expose `config.agent.model.clone()` in `SchedulerSnapshot`. Fine.

3. **Tools list source:** `ToolRegistry` is per-agent (or global?). In `main.rs`, the registry is built once and shared. Snapshot builder can call `registry.names()` → sorted `Vec<String>`. Cheap.

## Error & Rescue Registry

| Error | Where | User sees | Recovery |
|---|---|---|---|
| FUSE not mounted | `agentctl watch` startup | "FUSE surface not mounted at {path} — start agentd (e.g. `agentd agents.toml`) and wait ~1s for mount" | User runs `agentd agents.toml` |
| Agent terminates mid-poll (ENOENT) | `reader.rs` file reads | Agent row disappears on next tick | Skip agent on ENOENT; no crash |
| Snapshot lock poisoned (race) | `update_snapshot()` | Stale data shown for one tick | `try_write` skip; next tick self-heals |
| crossterm fails on TERM | `app.rs` init | Error message to stderr, then auto-fallback to `--plain` mode | Automatic; operator can use `--no-plain` to force TUI (at own risk) |
| ratatui panic (render bug) | `app.rs` draw | Program crashes to terminal | Catch `draw()` error; print to stderr; exit 1 |
