## Goal

Ship three first-party MCP servers that add new agentic capabilities (shell
execution, HTTP fetch, web search) that no template could previously express
without custom operator setup. Each server is a small Python script following
the `docker/weather_mcp.py` pattern.

**Accurate scope statement:** h7.1 adds new capability servers — it does NOT
remove existing template dependencies on npx/uvx (those require Docker packaging
in h8.2). Existing templates that depend on `npx @modelcontextprotocol/server-filesystem`
or `uvx mcp-server-git` still require those runtimes; h7.1 doesn't change that.

**What h7.1 does unlock:** Any template can now call `run_command`, `fetch_url`,
or `web_search` without the operator writing a custom MCP server.

## Architecture

### Server pattern (from `docker/weather_mcp.py`)

Each server is a self-contained Python script (`#!/usr/bin/env python3`, stdlib
only) that reads JSON-RPC lines from stdin and writes responses to stdout.

```
stdin → json.loads(line) → dispatch → json.dumps(response) + "\n" → stdout
```

Methods handled: `initialize`, `notifications/initialized`,
`notifications/cancelled`, `tools/list`, `tools/call`.

### File layout

```
docker/
  weather_mcp.py        (existing)
  shell_mcp.py          (new)
  http_mcp.py           (new)
  search_mcp.py         (new)
```

### ShellExec capability (minimal agentd touch)

**Design clarification (resolves roadmap ambiguity):**

The ROADMAP's phrase "sandbox applies DenySpawn + file grants" is misleading.
The shell_mcp.py subprocess MUST suppress DenySpawn — it calls `subprocess.run()`
which calls fork+exec. If DenySpawn (seccomp) were applied, no shell command
could ever run. The correct design:

- `ShellExec` in `[[tools.mcp_servers]] capabilities` → suppresses DenySpawn
  in `caps_to_rules_inner` (identical to `Spawn` behavior). File grants come
  from `FsRead`/`FsWrite` caps listed alongside `ShellExec`.
- `ShellExec` is a **subprocess sandbox capability only**, not an agent-level
  capability. Agent-level gating for shell_exec tools uses the existing
  `Mcp { server = "shell_exec", tools = [] }` capability mechanism.

**Changes to agentd/src/capability.rs:**

```rust
pub enum Capability {
    // ... existing variants ...
    ShellExec,  // subprocess sandbox: suppresses DenySpawn (like Spawn)
}
```

Add to `satisfies()` (exhaustive match — compile error without it):
```rust
Capability::ShellExec => granted.iter().any(|g| matches!(g, Capability::ShellExec)),
```

**Changes to agentd/src/main.rs `caps_to_rules_inner()`:**

Line ~1057, update `has_spawn` bool:
```rust
let has_spawn = caps.iter().any(|c| matches!(c, Capability::Spawn | Capability::ShellExec));
```

Add to the exhaustive match inside the cap loop (currently only has FsRead/FsWrite/Net/Spawn/Mcp/KbRead/KbWrite arms):
```rust
Capability::ShellExec => {} // has_spawn already handles this
```

**Changes to `agentctl/src/spawn.rs` `parse_cap_alias()`:**
```rust
"shell-exec" | "shellexec" => Ok(Capability::ShellExec),
```

### TOML serialization

`Capability` uses `#[serde(rename_all = "PascalCase")]`. Unit variants serialize
as `"ShellExec"` (string form). Add a round-trip test at step 1 to confirm:
```rust
let toml_str = r#"ShellExec"#;  // or inline table form depending on toml crate
let cap: Capability = toml::from_str(toml_str).unwrap();
assert_eq!(cap, Capability::ShellExec);
```
(Run this test before writing any Python server that embeds example TOML snippets,
to ensure the format is correct.)

### Template files work as-is

`to_agent_config()` clones `self.tools` wholesale (`tools: self.tools.clone()`),
so `[[tools.mcp_servers]]` blocks in template TOML files propagate correctly.
No changes to `TemplateCapabilities` or `template.rs` needed.

## Server implementations

### shell_exec server (`docker/shell_mcp.py`)

Tool: `run_command`  
Input: `{command: str, timeout_s?: int (default 30, max 120), env?: {str: str}}`  
Output: `{stdout: str, stderr: str, exit_code: int}`

Safety:
- `shell=True` is intentional — we're a shell execution server; the operator is
  responsible for not granting shell_exec to untrusted agents
- `timeout_s` clamped to [1, 120] (not 300 — MCP has no heartbeat; 5-min stalls
  are unacceptable. 120 s is a reasonable max for legitimate long-running commands)
- `subprocess.run(command, shell=True, capture_output=True, timeout=timeout_s, stdin=subprocess.DEVNULL)`
- stdout + stderr each capped at 64 KB; truncated with `[TRUNCATED]` marker
- Environment: agentd already restricts the MCP server's inherited env to a
  safe allowlist (PATH, HOME, USER, LANG, LC_ALL, TMPDIR). The Python server
  does NOT need to strip ANTHROPIC_API_KEY — it doesn't have it. Any
  operator-provided `env` overrides are merged in as-is.

SSRF/shell risk note in docstring at top of script.

### http_fetch server (`docker/http_mcp.py`)

Tool: `fetch_url`  
Input: `{url: str, method?: str (default "GET"), headers?: {str: str}, body?: str}`  
Output: `{status_code: int, headers: {str: str}, body: str, is_redirect?: bool}`

Safety:
- `url` must start with `https://` (HTTP rejected with isError=true + clear message)
- Response body capped at 4 MB; truncated with `[TRUNCATED at 4MB]` marker
- `urllib.request.urlopen` with 30 s timeout, no redirect following
- Redirects: return `{status_code: 3xx, is_redirect: true, headers: {"Location": "..."}}` so
  smart agents can retry with the new URL
- SSRF risk documented in comment block at top of script:
  ```python
  # SSRF NOTE: This server does not block loopback (127.x, ::1), RFC1918
  # (10.x, 172.16-31.x, 192.168.x), or link-local (169.254.x) addresses.
  # In production environments, restrict via Net capability host lists.
  ```

### web_search server (`docker/search_mcp.py`)

Tool: `web_search`  
Input: `{query: str, count?: int (default 5, max 10)}`  
Output: `{results: [{title, url, description}], total_found: int}`

**Setup requirement:** Requires `BRAVE_SEARCH_API_KEY` env var.
Brave Search API has a free tier (2,000 queries/month) at brave.com/search/api.
This is low-setup, not zero-setup. Templates that wire this up must document it.

Backend: Brave Search API (`https://api.search.brave.com/res/v1/web/search`)  
Auth: `BRAVE_SEARCH_API_KEY` env var (never logged; read at call time)  
Degradation: key absent → `isError: true`, content: `"BRAVE_SEARCH_API_KEY not set. Get a free key at brave.com/search/api"`  
No SearXNG fallback in this increment.

## Path convention (important)

MCP server `args` paths are relative to the CWD from which agentd is launched.
When running from `agentd/` (the canonical way): `args = ["../docker/shell_mcp.py"]`.
When running from the repo root: `args = ["docker/shell_mcp.py"]`.

All template and agent.toml examples in this PR use `../docker/shell_mcp.py`
(assumes `agentd/` as CWD). Add a comment above every `args` field:
```toml
# Path relative to agentd/ (where cargo run is invoked)
args = ["../docker/shell_mcp.py"]
```

## Risk register

| Risk | Severity | Mitigation |
|------|----------|------------|
| shell_exec arbitrary command execution | High | ShellExec is deny-by-default; DenySpawn on subprocess still blocks spawning further MCP servers; FsRead/FsWrite limit filesystem access; 120 s hard timeout |
| DenySpawn/ShellExec conflict | High | Resolved: ShellExec suppresses DenySpawn (same as Spawn); documented above |
| BRAVE_SEARCH_API_KEY in flight log | Medium | Key read from env at call time; never logged; search query is logged (acceptable) |
| http_fetch SSRF | Medium | Documented risk in script header; operator uses Net host lists to restrict |
| python3 not in PATH | Low | isError with "python3 not found" from agentd McpServerStartFailed event |
| clippy-linux failure on new ShellExec match arms | High | Step 4 in impl order: run make clippy-linux before Python work |
| TOML unit variant format surprises | Medium | Round-trip test is step 1; catches format before anything depends on it |
