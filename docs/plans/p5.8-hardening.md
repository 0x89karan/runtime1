### 2. Startup assertion in main.rs

At the point where `store_path` is resolved (line ~156 in main.rs), before opening the store, canonicalize both paths and assert no overlap:

```rust
// Normalize: resolve `..` components without requiring the path to exist.
// Use the same normalize_path helper that sandbox/capability.rs uses.
let norm_store = normalize_path(&store_path);
// OV-3: Relative store_path resolved from CWD may not match MCP prefix after normalization.
// Require an absolute path to make the comparison unambiguous.
if !norm_store.is_absolute() {
    bail!("store_path must be an absolute path, got: {}", store_path.display());
}
for srv in &cfg.tools.mcp_servers {
    for cap in srv.capabilities.iter().flatten() {
        let prefix = match cap {
            Capability::FsRead { prefix } | Capability::FsWrite { prefix } => prefix,
            _ => continue,
        };
        let norm_prefix = normalize_path(Path::new(prefix));
        // Empty prefix after normalization is not a valid grant — skip it.
        // (mirrors the guard in capability.rs:119-122 for satisfies())
        if norm_prefix.as_os_str().is_empty() {
            continue;
        }
        if norm_store.starts_with(&norm_prefix) {
            bail!("memory store {} falls inside MCP server {:?}'s {} sandbox prefix {}; \
                   move the store outside all server FS prefixes \
                   (e.g. set store_path = \"/run/memory/memory.redb\" in [memory])",
                  norm_store.display(), srv.name,
                  if matches!(cap, Capability::FsRead { .. }) { "FsRead" } else { "FsWrite" },
                  norm_prefix.display());
        }
    }
}
```

Notes:
- Use `srv.capabilities.iter().flatten()` (not `&srv.capabilities`) — `capabilities` is `Option<Vec<...>>`.
- Normalize both sides before `starts_with` to handle `..` components and relative paths.
- **OV-3 guard**: require `norm_store.is_absolute()` before the loop — relative paths resolve from CWD at startup and may not match the MCP prefix correctly; bail! early with a clear error.
- Depends on "no hot reload" invariant — config is immutable after startup.
- Error message must include a concrete path hint (DX-01): append `" (e.g. set store_path = \"/run/memory/memory.redb\" in [memory])"` — the distro's canonical safe location.
- Error message should include the capability kind (FsRead vs FsWrite) in the diagnostic (DX-02): extend bail! to include `"via {:?}", cap_kind` or match arm label.
- Use `.display()` not `{:?}` for path values in the message (DX-02).

Test: `main::tests::store_path_inside_sandbox_prefix_fails_startup`:
- Case A: absolute store path inside absolute cap prefix → bail!
- Case B: relative store path, absolute prefix not matching → passes
- Case C: store path with `..` components that canonicalize inside prefix → bail!

### 5. p5.7-ar sweeps in agents_fs.rs

- **p5.7-ar-01** (inode pruning): Prune lazily inside `AgentsFs::readdir` for the `Root` case, NOT in `update_snapshot()` (which is in scheduler.rs and has no access to AgentsFs maps). Pattern:
  ```
  let live_ids: HashSet<&str> = agent_ids.iter().map(String::as_str).collect();
  let dead: Vec<String> = self.dir_inodes.keys()
      .filter(|id| !live_ids.contains(id.as_str()))
      .cloned()
      .collect();  // MUST collect before mutating — Rust borrow checker
  for id in &dead { self.prune_dead_agent(id); }
  ```
  `prune_dead_agent(agent_id)` removes from ALL 5 maps:
  - `dir_inodes` (agent_id → base inode) — remove by agent_id
  - `inode_to_id` (inode → agent_id) — remove all 8 fixed per-agent inodes (base + offsets 1–7)
  - `dyn_ino_kind` — remove all entries where inode is in `lt_key_ino` for this agent
  - `lt_key_ino` ((agent_id, key) → ino) — remove all keys where key.0 == agent_id
  - `kb_seg_ino` — remove entries where segment key starts with `"agent/{agent_id}/"` NOT just `"agent/"` (avoid pruning inodes for other live agents' namespaces) ~30 lines.

- **p5.7-ar-02** (debug_assert kind, P3 cosmetic): in `getattr`/`read` dynamic dispatch, add `debug_assert!(matches!(kind, DynInoKind::LtFile { .. }))` etc. ~5 lines each handler.

- **p5.7-ar-03** (getattr ENOENT for memory/ when no store): in `getattr`, for `OFF_MEMORY_DIR` (+5) and `OFF_LONG_TERM_DIR` (+7) inodes specifically, check `self.memory.is_none()` and return `ENOENT`. NOTE: `OFF_SHORT_TERM` (+6) serves from snapshot (not the memory store) and must NOT get this guard — it's valid even without a store configured. **OV-2 acknowledgment**: this creates a POSIX asymmetry where `stat /agents/{id}/memory/short_term` succeeds even when `stat /agents/{id}/memory/` returns ENOENT. This is intentional (short_term is snapshot-backed); add a `// intentional: short_term serves AgentSnapshot regardless of store state` comment at the guard site.

### 6. p5.7-ar-04: NAMESPACES index in store.rs

Add `NAMESPACES: TableDefinition<&str, u64>` (key=namespace, value=entry count). Updated atomically in every `put()`/`append()`/`delete()` write transaction.

Key design decisions:
- **No FORMAT_VERSION bump needed** — backfill happens in `init_schema()` on open: if NAMESPACES table is empty AND ENTRIES is non-empty, run a one-time O(n) scan of ENTRIES to populate counts. **Backfill MUST be a single write transaction** — if partial (multiple commits) and the process crashes, NAMESPACES is non-empty on next open and the empty-guard won't re-run, leaving stale counts permanently. One txn = all-or-nothing.
- **OV-4**: Emit `tracing::info!("namespaces: backfilling {} entries across {} namespaces", entry_count, ns_count)` before the backfill write transaction so operators can tell why startup is slow on large stores.
- **Delete removes key at count=0** — when decrement reaches 0, use `table.remove(ns)` instead of writing `0`. This prevents ghost namespace entries in FUSE `kb/` after all entries in a segment are deleted/evicted.
- **OV-1: Insert vs update check in `put()`** — `put()`/`append()` must check whether the key already exists before incrementing the NAMESPACES counter. Within the same write transaction, read the existing ENTRIES row: if it already exists, this is an update → counter stays flat; if it is absent, this is an insert → increment counter. A naive unconditional increment on every `put()` overcounts when agents overwrite existing entries (e.g. `kv_set` on an existing key), which would cause namespaces to appear in FUSE with inflated counts and never reach 0 on delete.
- `list_namespaces()` becomes a full range scan over NAMESPACES (O(k) where k = segment count, vs O(n) where n = entry count).
