# h8.2 — `agentos:full` Docker Distribution

## Goal

Formally split the Docker image into two named tiers so operators can choose the right footprint:

- **`agentos:core`** — only `agentd` + `agentctl` + `agentos-otel` (Rust binaries + fuse3/bash/jq). No Python. For operators who BYO MCP servers or use HTTP-only MCP endpoints.
- **`agentos:full`** — extends core with python3, all h7.1–h7.3 Python MCP servers (`shell_mcp.py`, `http_mcp.py`, `search_mcp.py`, `oauth_mcp.py`, `cron_mcp.py`, `fs_watch_mcp.py`, `webhook_mcp.py`, `semantic_kb_mcp.py`), and the full template catalogue. Matches the current image content.

The Rust runtime is identical in both. Qdrant sidecar remains a separate compose service (unchanged).

## Version

`v0.73.0` — pure packaging, no Rust changes.

## Decisions

| # | Decision | Choice | Rationale |
|---|----------|--------|-----------|
| D1 | `latest` tag target | `full` | Preserves existing `docker pull ghcr.io/0x89karan/runtime1` behavior; no regression for existing users |
| D2 | Dockerfile structure | Single `Dockerfile`, two named runtime stages (`runtime-core`, `runtime-full`), CI uses `--target` | Shares the expensive builder stage; `runtime-full` layers on top of `runtime-core` — single QEMU arm64 compile pass |
| D3 | docker-compose.yml | No change (keep `build: .`) | Operators who use compose already have the repo; switching to image refs adds CI-timing complexity |
| D4 | semantic-kb-mcp publishing | Defer to a follow-on increment | It's a Qdrant sidecar image; compose handles it; out of scope for the binary split |
| D5 | Templates in core | Include all templates in both tiers | TOML files are tiny; operators choose which to use at runtime |
| D6 | agentos-otel in core | Yes | Compiled Rust binary, no extra apk deps, useful standalone |

## Tag scheme

| Image | Tags |
|-------|------|
| core tier | `ghcr.io/0x89karan/runtime1:core`, `ghcr.io/0x89karan/runtime1:v0.73.0-core` |
| full tier | `ghcr.io/0x89karan/runtime1:full`, `ghcr.io/0x89karan/runtime1:v0.73.0-full` |
| aliases pointing to full | `ghcr.io/0x89karan/runtime1:latest`, `ghcr.io/0x89karan/runtime1:v0.73.0` |

## Implementation deliverables

### E1 — Refactor `Dockerfile` into tiered multi-stage

Add a second runtime stage that inherits from `runtime-core`:

```dockerfile
# ── Stage 1: builder (unchanged) ─────────────────────────────────────────────
FROM rust:1-alpine AS builder
...

# ── Stage 2a: runtime-core — Rust binaries only ──────────────────────────────
FROM alpine:3.20 AS runtime-core
RUN apk add --no-cache fuse3 bash jq
RUN echo "user_allow_other" >> /etc/fuse.conf
COPY --from=builder /src/target/release/agentd       /usr/local/bin/agentd
COPY --from=builder /src/target/release/agentctl     /usr/local/bin/agentctl
COPY --from=builder /src/target/release/agentos-otel /usr/local/bin/agentos-otel
COPY docker/agent.toml      /etc/agentd/agent.toml
COPY docker/agents.toml     /etc/agentd/agents.toml
COPY agentd/cos.agents.toml /etc/agentd/cos.agents.toml
COPY templates/             /etc/agentd/templates/
RUN mkdir -p /agents /workspace /run/memory /data
WORKDIR /workspace
COPY docker/entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh
ENTRYPOINT ["/entrypoint.sh"]
CMD ["shell"]

# ── Stage 2b: runtime-full — adds Python harness ─────────────────────────────
FROM runtime-core AS runtime-full
RUN apk add --no-cache python3
COPY docker/*.py               /etc/agentd/
COPY docker/weather-agent.toml /etc/agentd/weather-agent.toml
```

`docker build --target runtime-core` → core image  
`docker build --target runtime-full` (or no `--target`) → full image

### E2 — Update CI `publish-docker` job

Replace the single `build-push-action` step with two sequential steps:

```yaml
- name: Build and push agentos:core
  uses: docker/build-push-action@v6
  with:
    context: .
    target: runtime-core
    platforms: linux/amd64,linux/arm64
    push: true
    provenance: false
    tags: |
      ghcr.io/0x89karan/runtime1:core
      ghcr.io/0x89karan/runtime1:v${{ steps.version.outputs.version }}-core
    cache-from: type=gha
    cache-to: type=gha,mode=max

- name: Build and push agentos:full (and :latest)
  uses: docker/build-push-action@v6
  with:
    context: .
    target: runtime-full
    platforms: linux/amd64,linux/arm64
    push: true
    provenance: false
    tags: |
      ghcr.io/0x89karan/runtime1:full
      ghcr.io/0x89karan/runtime1:latest
      ghcr.io/0x89karan/runtime1:v${{ steps.version.outputs.version }}-full
      ghcr.io/0x89karan/runtime1:v${{ steps.version.outputs.version }}
    cache-from: type=gha
    cache-to: type=gha,mode=max
```

The second step reuses the cached `runtime-core` layers — only the Python `apk add` and file copies run again (< 5 min on arm64).

## Acceptance criteria

- `docker run --rm ghcr.io/0x89karan/runtime1:core python3 --version` → exits non-zero (Python absent)
- `docker run --rm ghcr.io/0x89karan/runtime1:core agentd --version` → prints version
- `docker run --rm ghcr.io/0x89karan/runtime1:full python3 --version` → prints Python 3.x
- `docker run --rm ghcr.io/0x89karan/runtime1:full ls /etc/agentd/*.py` → lists all MCP servers
- `docker pull ghcr.io/0x89karan/runtime1:latest` → same as `:full` (non-breaking)
- CI `publish-docker` job produces all 6 tags per push to main

## CI timing estimate

- First push after h8.2: arm64 QEMU build ~75 min (builder) + ~10 min (python layer for full) = ~85 min total (< current 90 min timeout, well within the 120 min timeout)
- Subsequent pushes: GHA cache hit → ~15 min for core, ~20 min for full (Python layer rebuild)
