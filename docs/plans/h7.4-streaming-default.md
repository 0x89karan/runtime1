# h7.4 — Streaming-by-default + connect timeout

**Version:** v0.51.0  
**Status:** Planning  
**Branch:** (new)  
**Depends on:** con.1 (v0.49.0, tcp_keepalive already in place)

---

## Problem

After h7.2-ar-01 shipped the generic `agent` Docker entrypoint, end-to-end testing
of `google-agent` revealed a completely silent terminal for 2-10 minutes followed by
either a final answer or a silent hang. Root cause: two separate issues.

### Issue 1 — `streaming = false` default makes multi-turn agents invisible

`ModelConfig.streaming` defaults to `false` via `#[serde(default)]`. No template
sets `streaming = true`. With non-streaming inference:

1. `make_infer_future()` calls `gw.infer(req).await` and blocks until the complete
   Anthropic response arrives. Nothing is written to stdout.
2. Text blocks emitted alongside tool-use blocks in `step_with_response()` are stored
   in agent context but never printed until `AgentEffect::Completed`.
3. For the `google-agent` OAuth flow: Turn 1 → `oauth_start_auth` (silent, ~15s).
   Turn 2 — inference where Claude echoes the OAuth URL to the user (silent, ~15s).
   Turn 3 → `oauth_check_auth` blocks on port 8585 waiting for a callback the user
   can't trigger because they never saw the URL. Indefinite hang.

With `streaming = true`, Turn 2's inference emits the text chunk "please visit
this URL: ..." **as it arrives**, before `oauth_check_auth` starts blocking. The
user sees the URL, opens it, completes the flow.

`cos.agents.toml` already sets `streaming = true` explicitly and works correctly
since con.1 (v0.49.0) added `tcp_keepalive`. The `streaming = false` default is
now the wrong default for the entire codebase.

### Issue 2 — No `connect_timeout` on `AnthropicGateway`

`AnthropicGateway::from_env()` builds a reqwest `Client` with `timeout(120s)` and
`tcp_keepalive(15s)` but no `connect_timeout`. If Docker's NAT drops the TCP SYN
without an RST (rare but possible after NAT table eviction or container restart),
the connect phase blocks silently until the 120s overall timeout fires, then
surfaces a timeout error. A 10s connect timeout surfaces this 12x faster and gives
the user a clear error instead of a 2-minute black box.

Note: `timeout(120s)` and `connect_timeout(10s)` serve different phases.
`timeout` is overall request duration (DNS + connect + send + receive).
`connect_timeout` caps only the TCP handshake. Both are needed.

## Fix

### 1. `agentd/src/config.rs` — flip streaming default

Add a named default function (required by serde for non-`Default` defaults) and
flip both the serde default and the `Default` impl:

```diff
+fn default_streaming() -> bool { true }
+
 pub struct ModelConfig {
     #[serde(default = "default_provider")]
     pub provider: String,
     #[serde(default = "default_model")]
     pub model: String,
     #[serde(default = "default_max_tokens")]
     pub max_tokens: u32,
-    /// When true, use SSE streaming and print text chunks progressively to stdout.
-    /// Applies to all agents in this config file. Default: false.
-    #[serde(default)]
+    /// When true, use SSE streaming and print text chunks progressively to stdout.
+    /// Applies to all agents in this config file. Default: true.
+    #[serde(default = "default_streaming")]
     pub streaming: bool,
 }
 
 impl Default for ModelConfig {
     fn default() -> Self {
         Self {
             provider: default_provider(),
             model: default_model(),
             max_tokens: default_max_tokens(),
-            streaming: false,
+            streaming: true,
         }
     }
 }
```

**Intentional non-changes** — these explicit `streaming: false` literals must NOT
be changed; they are deliberate, not defaults:

| File | Line | Reason |
|------|------|--------|
| `agentd/src/scheduler.rs` ~826 | distillation request | Internal summarization call; streaming is meaningless for an orchestrator-internal inference |
| `agentd/src/scheduler.rs` ~2310 | `model_cfg()` test helper | Mock gateway in tests doesn't implement streaming; keep `false` for test clarity |
| `agentd/src/scheduler.rs` ~3279 | inline `InferenceRequest` in test | Same — test scaffolding, not production config |
| `agentd/src/scheduler.rs` ~3395 | `model_cfg()` duplicate | Same |
| `agentd/src/main.rs` ~1174 | probe mode | `agentd --probe` is a dev/debug path; streaming off is appropriate |
| `agentd/src/checkpoint.rs` ~229 | checkpoint restore | Verify in context below |

Check `checkpoint.rs:229` during implementation — if it sets `streaming: false` on
a `ModelConfig` that is later used for production inference, change it to match
the live config's value. If it's only for internal calls (like distillation), leave it.

### 2. `agentd/src/inference/anthropic.rs` — add connect_timeout

```diff
 let client = Client::builder()
     .timeout(std::time::Duration::from_secs(120))
+    .connect_timeout(std::time::Duration::from_secs(10))
     .redirect(reqwest::redirect::Policy::none())
     // Keep TCP connections alive through Docker NAT conntrack's idle timeout.
     // Without this, connections silently die during long MCP wait periods.
     .tcp_keepalive(std::time::Duration::from_secs(15))
     .build()
     .context("building HTTP client")?;
```

### 3. `agentd/src/scheduler.rs` — update the streaming-default test

The test `model_config_streaming_defaults_to_false` explicitly asserts the old
behavior. Rename and flip the assertion:

```diff
-/// ModelConfig streaming field defaults to false via #[serde(default)].
+/// ModelConfig streaming field defaults to true via #[serde(default = "default_streaming")].
 #[test]
-fn model_config_streaming_defaults_to_false() {
-    // Verify that omitting `streaming` from a TOML snippet deserializes as false.
+fn model_config_streaming_defaults_to_true() {
+    // Verify that omitting `streaming` from a TOML snippet deserializes as true.
     let toml_str = r#"
         provider = "anthropic"
         model = "claude-sonnet-4-6"
         max_tokens = 4096
     "#;
     let cfg: crate::config::ModelConfig = toml::from_str(toml_str).unwrap();
-    assert!(!cfg.streaming, "streaming must default to false when omitted from config");
+    assert!(cfg.streaming, "streaming must default to true when omitted from config");
 }
```

The sibling test `model_config_streaming_can_be_enabled` stays unchanged — it
tests explicit opt-in from `streaming = true` in TOML, which remains valid.

Add a new test for explicit opt-out:

```rust
/// Streaming can be explicitly disabled for headless/script use cases.
#[test]
fn model_config_streaming_can_be_disabled() {
    let toml_str = r#"
        provider = "anthropic"
        model = "claude-sonnet-4-6"
        max_tokens = 4096
        streaming = false
    "#;
    let cfg: crate::config::ModelConfig = toml::from_str(toml_str).unwrap();
    assert!(!cfg.streaming, "streaming = false must be honoured when explicit");
}
```

### 4. `agentd/cos.agents.toml` — redundant but keep for documentation

`cos.agents.toml` already has `streaming  = true`. This is now redundant (matches
the new default) but keep it: it makes the intent explicit and documents that
streaming is a deliberate design choice for the flagship workload.

## What does NOT change

- All template `.template.toml` files: no `streaming` field needed — they inherit
  the new default. Do not add `streaming = true` to templates; the default should be
  the source of truth so templates don't drift.
- `agentd/agent.toml`, `agentd/agents.toml`: same — inherit the default.
- `docker/entrypoint.sh`: no changes needed.
- `docker-compose.yml`: no changes needed.

## Acceptance criteria

1. `cargo build && cargo clippy -- -D warnings && cargo test` pass (the renamed
   test is the only test change).
2. `ModelConfig::default().streaming == true`.
3. Parsing a TOML `[model]` section without a `streaming` field yields `streaming = true`.
4. Parsing `streaming = false` in TOML yields `streaming = false` (opt-out works).
5. `AnthropicGateway::from_env()` client has a `connect_timeout` (visible in code).
6. **Docker integration smoke-test** (manual):
   ```bash
   # Expects: text output streams progressively, NOT silent for 60s then a dump
   TEMPLATE_NAME=scout AGENT_TASK="what is 2+2" docker compose run --rm agent
   ```
7. **Google-agent OAuth URL visibility** (manual, requires credentials):
   The OAuth URL appears in the terminal BEFORE `oauth_check_auth` starts
   waiting — i.e., the user can click the URL before the callback listener starts.

## Decision Audit Trail

| # | Decision | Classification | Rationale | Rejected |
|---|----------|----------------|-----------|---------|
| 1 | Change `ModelConfig` serde/Default to `streaming: true` | Mechanical | `cos.agents.toml` already uses it; con.1's keepalive makes it stable; non-streaming hides all agent activity from the operator — actively harmful in Docker | Keep default false, add to each template |
| 2 | Keep `streaming: false` in distillation and test-helper structs | Mechanical | These are intentional, not defaults. Distillation is internal; tests use a mock gateway | Change all occurrences |
| 3 | Use `#[serde(default = "default_streaming")]` not `#[serde(default)]` | Mechanical | `bool::default()` is `false`; the only way to make serde default to `true` is a named function | Use `#[serde(default)]` (would give false) |
| 4 | `connect_timeout(10s)` — not 30s or 5s | Taste | 10s is long enough to handle Docker DNS (typically <2s) + slow NAT setup; short enough to surface failures before user loses patience. 5s could false-positive on slow DNS. 30s is indistinguishable from a hang. | 5s, 30s, or none |
| 5 | Do NOT add `streaming = true` to template files | Mechanical | Templates inherit the config default; explicit per-template fields would drift from each other and obscure the authoritative default | Explicit per-template |
| 6 | Keep `streaming = true` explicit in `cos.agents.toml` | Taste | Documents intent; flagship workload should be self-documenting about its operational properties | Remove the now-redundant line |
