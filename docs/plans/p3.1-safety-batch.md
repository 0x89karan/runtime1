# p3.1 — agentd runtime-safety P3 batch

Branch: `p3.1-safety-batch` · Base: `main` (v0.108.0)
Kind: mechanical safety/correctness batch (no design decision — went build→review→qa, not autoplan).
Groups three cohesive, non-interacting agentd runtime/checkpoint P3s from the v0.86 audit.

## Items
1. **audit86-P3-3 — defensive `.expect` on agent lookup in the scheduler.** `scheduler.rs:876/882/916/932`
   (`state.agents.get(&agent_id).expect(...)` in the EffectResult handling) + `:2868` (`get_mut`, "checked
   above"). They hold today, but with `panic = "abort"` in release a future break (e.g. a new Kill/cancel
   path that removes the agent mid-effect) becomes whole-runtime death. Convert each to
   `let Some(task) = state.agents.get(&agent_id) else { <record a flight error + continue> };` — never
   panic on a missing agent; record and skip the effect. Upholds "the loop never panics on bad input."
2. **audit86-P3-4 — checkpoint `FORMAT_VERSION` bump 4 → 5.** cred.7 added `credential_health` to the
   checkpoint schema WITHOUT bumping `FORMAT_VERSION` (checkpoint.rs:24), violating CONVENTIONS (a schema
   change must bump the version). Bump to 5. VERIFY the restore contract still holds: a v4 checkpoint (no
   `credential_health`) must still load on new agentd (the field must be `#[serde(default)]` — confirm), and
   a v5 checkpoint is correctly rejected as too-new by an old agentd (the existing `format_version >
   FORMAT_VERSION` probe). Update the too-new test's expectations if it pins the number.
3. **audit86-P3-5 (tmp-sweep sub-item) — crash-orphaned `checkpoint.json.*.tmp` never swept.** `save()`
   writes to `tmp_path()` = `checkpoint.json.{pid}.{nanos}.tmp` then renames; a crash between write and
   rename leaks the tmp file forever (checkpoint.rs:203-220). Sweep stale sibling `checkpoint.json.*.tmp`
   files (best-effort, never crash a save/load) — on `load()` or at the start of `save()`. Match a strict
   glob (own directory, `checkpoint.json.*.tmp` only) so it can't delete anything else.

## Acceptance
- No production `.expect` on an agent-map lookup in the scheduler EffectResult path; a missing agent records
  a flight error + continues (a test drives a removed-agent effect and asserts no panic + the error event).
- `FORMAT_VERSION == 5`; a v4 checkpoint still restores (credential_health defaults); the too-new probe
  rejects a v6.
- Orphaned `.tmp` files are swept; the sweep never touches a non-`.tmp` sibling (a test with a decoy file).
- `cargo build/clippy --workspace --all-targets -D warnings` clean; `cargo test --workspace` green. No `cargo fmt`.

## Risk
LOW. Defensive + additive. The one care point is P3-4 (the restore contract — a v4 checkpoint must still load).
