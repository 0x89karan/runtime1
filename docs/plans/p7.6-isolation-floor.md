# p7.6 — Isolation floor (gVisor) for the universal tier [CORE]

**Branch:** `p7.6-isolation-floor`
**Depends on:** p3.3 (Landlock/seccomp sandbox crate), p4.2 (`IsolationMode::Gvisor` + `IsolateNetwork` rule), p7.5b (egress proxy, `start_http_proxy`, `egress_bound_addr`).
**Version:** v0.41.0
**Related:** `docs/PRODUCT-THESIS.md` security model, `docs/OBSERVABILITY-PLAN.md`.
**Unblocks:** obs.1 (eBPF / gVisor-sink observability).

> **Scope note:** Firecracker is deferred to p7.7 or later. KVM availability, TAP networking,
> rootfs lifecycle, and guest kernel bootstrap are not in CI and cannot be integration-tested.
> gVisor rootless (`runsc`) is the sole isolation backend for this increment.
> Firecracker will be specified separately once the gVisor path is proven end-to-end.

## Problem

The existing `IsolationMode::Gvisor` (p4.2) wraps MCP server subprocesses with `runsc do` — scoped to MCP servers only. The product thesis demands a **universal tier** for foreign agent frameworks (LangChain, headless `claude`/`codex`, arbitrary scripts): governed child processes isolated from the host kernel. Landlock/seccomp/namespaces share the host kernel; one unpatched kernel CVE compromises the host. gVisor's Sentry intercepts syscalls in user space — a real kernel boundary without KVM.

Today there is no mechanism to spawn a universal-tier workload under gVisor, point its `ANTHROPIC_BASE_URL` at the egress proxy, and record the isolation tier in the flight log.

## Execution contract for universal-tier agents

A universal-tier agent is:
- **Process model:** spawned as a child process (`Command`), not an in-process Rust task.
- **Allowed IO:** stdout/stderr captured and forwarded to flight log; stdin closed. Each stream is capped at 4 MB per chunk; overflow emits `universal_output_truncated` event.
- **Dependency model:** operator provides the executable + its dependencies (venv, binary). AgentOS does not manage packaging.
- **Network:** sole egress path is the AgentOS loopback → egress proxy (see "Network wiring" below). No direct internet.
- **Secret model:** `ANTHROPIC_API_KEY` = structurally valid placeholder (never real). `ANTHROPIC_BASE_URL` = egress proxy address. Child env is cleared and rebuilt (see "Environment injection" below).
- **Observability:** `UniversalAgentStarted` / `UniversalAgentExited` flight events. gVisor-sink observability deferred to obs.1.
- **Lifecycle:** agentd monitors exit status; SIGTERM → SIGKILL after 5 s on agentd shutdown.
- **Checkpoint:** universal-tier agents are NOT checkpointed. Their state is opaque. On restart, agentd re-spawns from config.
- **send_message:** `send_message` to a universal-tier agent returns an `is_error` ToolResult to the sender: `"cannot send_message to a universal-tier agent"`. Universal agents have no message sink; messages are not queued.
- **Wall-clock timeout:** `max_wall_seconds: Option<u64>` config field (default: absent = unlimited in v1). Documented as a future governance hook for p7.7+; the field is accepted but not enforced in this increment.

## Design

### Isolation backend (gVisor only)

```
governed workload (LangChain / headless claude / arbitrary script)
  └─ gVisor (runsc --rootless run)
        Sentry intercepts all syscalls in user space
        network: host loopback accessible via --network=host (see below)
        future (obs.1): seccheck.Sink listener on a unix socket
```

### Network wiring (critical — 127.0.0.1 problem)

**Problem:** gVisor's `--network=none` gives no networking. `runsc do` without `--network=none` gives gVisor's own network stack, where `127.0.0.1` is the sandbox's own loopback — NOT agentd's loopback. `SandboxRule::IsolateNetwork` (unshare CLONE_NEWNET) does the same thing. A child process injected with `ANTHROPIC_BASE_URL=http://127.0.0.1:<port>` has no route to the egress proxy.

**Solution:** Pass the egress proxy address as a **Unix domain socket path** injected into the gVisor sandbox via a bind mount. The child connects to `/run/agentd-egress.sock`; gVisor passes the FD through to the host. Alternatively (if gVisor host network mode is available): `runsc do --network=host --` which gives the sandbox access to the host network stack, making `127.0.0.1` reach agentd's loopback. Host network mode reduces isolation slightly but is the simplest path.

**v1 decision:** Use `--network=host` for the initial implementation. Document that this reduces the network namespace boundary (traffic is on host loopback, not sandboxed network). Upgrade to veth or unix socket in obs.1 when the seccheck.Sink listener is wired.

**v1 compensating controls:** agentd binds no HTTP ports other than the egress proxy (`[egress].proxy_addr`); there is no local database in the default install; `ANTHROPIC_API_KEY` is a placeholder so LLM calls must route through the proxy and are brokered; all traffic is single-tenant loopback. Review for multi-service hosts before production deployment.

So the child env becomes: `ANTHROPIC_BASE_URL=http://127.0.0.1:<egress_port>` and `runsc do --network=host -- <cmd> <args>`.

### Environment injection (security — env_clear)

`UniversalAgent::spawn()` calls `Command::env_clear()` before setting any variables. Only the following are injected:

| Variable | Value |
|---|---|
| `PATH` | inherited from agentd's `PATH` |
| `HOME` | inherited |
| `USER` | inherited |
| `LANG` | inherited |
| `TMPDIR` | inherited (or `/tmp`) |
| `ANTHROPIC_API_KEY` | structurally valid placeholder (never the real key) |
| `ANTHROPIC_BASE_URL` | `http://127.0.0.1:<egress_port>` |

Any other secrets in agentd's environment (MCP server tokens, `GITHUB_TOKEN`, etc.) are NOT passed to the child. This is consistent with MCP server env handling (`McpServerConfig.env`).

### Scheduler: `AgentSlot` enum (unified map)

**Problem with the originally-proposed `universal_agents: HashMap`:** A second map breaks FUSE snapshots (blind to universal agents), checkpointing, `send_message` routing, shutdown fan-out, and `spawn_agent` lookups. All scheduler lifecycle logic keys on `state.agents`.

**Fix:** Introduce an `AgentSlot` enum stored in the existing `state.agents` map:

```rust
enum AgentSlot {
    Native(AgentTask),
    Universal(UniversalAgent),
}
```

All map lookups, snapshot generation, shutdown, and `send_message` routing operate on `AgentSlot`. FUSE and agentctl see both tiers uniformly. Status for a universal agent = `Running` / `Completed` (no LLM turn state).

**Delegation pattern:** All `AgentTask`-specific callsites in `scheduler.rs` use `match slot { AgentSlot::Native(t) => ..., AgentSlot::Universal(u) => ... }`. **No new trait is introduced** — explicit match arms keep the code auditable without premature abstraction. Callsite categories:
- **Native-only** (inference, tools, step, approval): `AgentSlot::Universal(_)` arm is unreachable; log a warning if hit.
- **Both tiers** (snapshot, shutdown, send_message guard, checkpoint skip): explicit handling for Universal values.

**Rust constraint: `Child: !Clone`** — `UniversalAgent` holds `child: std::process::Child` which does not implement `Clone` or `Serialize`. `AgentSlot` must NOT derive `Clone`, `Serialize`, or `Deserialize`. This is compatible with the existing codebase since `AgentTask` also does not derive `Clone`.

### Construction point: `run()` seed phase (not `Scheduler::new()`)

`Scheduler::new()` is a sync constructor. `UniversalAgent::spawn()` requires the `egress_addr` parameter which is not available until `main.rs` resolves it. Universal agents are therefore constructed in the `run()` seed phase:

1. `Scheduler::new()` stores `UniversalPending { cfg }` entries alongside `AgentSlot::Native(...)` entries (staging type).
2. The seed loop in `run()` constructs `UniversalAgent::spawn(cfg, egress_addr)` and promotes them to `AgentSlot::Universal(...)`.
3. Native agents proceed through `step()` as before.

### Universal agent snapshot defaults

When `update_snapshot` encounters an `AgentSlot::Universal(u)`, it produces an `AgentSnapshot` with:
- `turn = 0`
- `context_tokens = 0` (displayed as `N/A` in agentctl watch)
- `token_budget = cfg.token_budget`
- `tools = []`
- `status = Running` (or `Completed` if exited)
- `tier = "universal"` (new field — exposed via `/agents/<id>/tier` virtual file)
- `pid = u.child.id()` (new field — exposed via `/agents/<id>/pid` virtual file)

### Main loop: Universal agent polling

The scheduler main loop exits when `state.pending.is_empty()`. Universal agents never push futures into `state.pending` — without a guard, Universal-only populations would exit immediately.

**Fix:** The idle-exit condition becomes:

```rust
if state.pending.is_empty() && !universal_agents_running(&state) {
    break;
}
```

A 100ms timer tick (added to the `tokio::select!` arms) calls `poll_universal_agents(&mut state)` to check child exit status and emit `UniversalAgentExited` events.

### Post-loop SIGTERM and Universal agent kill

The SIGTERM handler sets `state.shutdown_requested = true`. After the main loop exits, before returning outcomes:

```rust
kill_universal_agents(&mut state).await; // SIGTERM → 5 s → SIGKILL
```

`kill_universal_agents` uses `tokio::time::timeout(Duration::from_secs(5))` for the SIGKILL window. Dropping `Child` after exit (normal exit path) is safe on Linux — the OS reclaims the zombie when the handle is dropped.

### Egress addr storage (already fixed by p7.5b)

`egress_bound_addr: Option<SocketAddr>` is already stored in `main.rs` after `start_http_proxy()` returns (wired by p7.5b). `UniversalAgent::spawn()` receives it as a parameter. If `egress_bound_addr` is `None` when a universal-tier agent is configured, startup fails with the "proxy_addr not set" error message.

### Checkpoint compatibility

`FORMAT_VERSION` remains **3** for this increment. New `AgentConfig` fields (`tier`, `command`, `args`, `isolation`, `max_wall_seconds`) all carry `#[serde(default)]`, so v3 checkpoints written before p7.6 deserialize cleanly with `tier = AgentTier::Native`. Universal agents are excluded from `SchedulerCheckpoint` — `build_scheduler_checkpoint` pattern-matches to skip `AgentSlot::Universal` entries. No schema change; no version bump required.

### Config additions

```toml
[[agents]]
id        = "langchain-worker"
tier      = "universal"          # "native" (default) = in-process; "universal" = child process
command   = "python"
args      = ["-m", "my_agent", "--task", "research X"]
isolation = "gvisor"             # only valid value in v1
token_budget = 50_000            # existing convention (NOT budget = { max_tokens })
# max_wall_seconds = 300         # optional; absent = unlimited in v1 (governance hook for p7.7+)
```

Config validation rules:
| tier | command | isolation | Result |
|---|---|---|---|
| native | absent | any | ok (existing behavior) |
| native | set | any | error: "native tier does not use command" |
| universal | absent | any | error: "universal tier requires command" |
| universal | set | gvisor | ok |
| universal | set | none | error: "universal tier requires isolation = \"gvisor\"" |
| universal | set | firecracker | error: "firecracker not available in this build" |

All new `AgentConfig` fields must carry `#[serde(default)]` for backward compatibility with existing `[[agents]]` entries.

### Fail-fast — no graceful degradation

Universal-tier agents MUST NOT fall back silently. If `runsc` is not on PATH at startup, agentd exits with:

```
agentd: agent 'langchain-worker' requires isolation = "gvisor" but 'runsc' is not found on PATH.
Install gVisor: https://gvisor.dev/docs/user_guide/install/
Then verify: runsc --version
```

The `UniversalAgentIsolationDegraded` event kind exists as an **audit event** for cases where the operator explicitly configures `allow_isolation_degradation = true` (future config flag, not in this increment). In v1, it is only emitted then immediately followed by a fatal exit.

## Acceptance criteria

1. `cargo build --release` succeeds; `cargo clippy -- -D warnings` + `make clippy-linux` clean.
2. `cargo test` passes (all existing + new tests).
3. Existing `agent.toml` / `agents.toml` (no `tier` field) parses correctly — serde backward compat.
4. Config with `tier = "universal"` + `isolation = "gvisor"` + `runsc` absent → startup error with exact message from "Error messages" section above.
5. Config with `tier = "universal"` + `isolation = "firecracker"` → startup error with exact message above.
6. With `runsc` installed: `UniversalAgentStarted` flight event emitted with `isolation_mode = "gvisor"`, `pid`, `command`; child process appears in FUSE (`/agents/<id>/status`).
7. SIGTERM to agentd while universal child running → child receives SIGTERM within 100 ms; SIGKILL if still alive after 5 s.
8. `agentctl watch` shows universal-tier agent in Dashboard (status) and AgentDetail (TIER/ISO/PID badge; context_tokens displays as N/A).
9. Binary size stays ≤ 6 MB.
10. With real egress forwarding (p7.5b already shipped): universal-tier agent completes ≥1 round-trip inference call through the proxy; `egress_brokered` event emitted.

## Non-goals / deferred

- **Firecracker** — deferred to p7.7+. Requires KVM, TAP, rootfs lifecycle.
- **obs.1 gVisor remote sink** (`seccheck.Sink` listener) — hooks in place but listener deferred.
- **Full container runtime** (OCI/Docker) — not p7.6.
- **Universal-agent checkpoint/restore** — opaque child process; not checkpointed.
- **Dependency packaging** (venv, npm, etc.) — operator responsibility.
- **Wall-clock timeout enforcement** — `max_wall_seconds` field accepted in config but not enforced in v1. Governance enforcement deferred to p7.7.
- **Template `{{task}}` arg substitution** — not implemented in p7.6. Operators set their args directly in the template. Interpolation syntax deferred.
- **MCP-server alternative to gVisor** — MCP stdio transport could serve as a universal agent adapter, but that is the existing MCP path (p7.1). Universal-tier targets non-MCP-aware workloads (LangChain, headless scripts). Decision: keep both paths; no consolidation in p7.6.
- **Observability gap** — Universal agents produce stdout/stderr in the flight log but no structured LLM-turn events (no turn, token, or tool-call granularity). Structured observability requires MCP or a native tier refactor; deferred to obs.1+.

## Flight events taxonomy

| Event kind | Tier | Description |
|---|---|---|
| `universal_agent_started` | 5 | Universal-tier child spawned; `isolation_mode`, `pid`, `command` |
| `universal_agent_exited` | 5 | Child exited; `exit_status`, `isolation_mode` |
| `universal_agent_isolation_degraded` | 5 | Reserved; fatal exit emitted before this in v1 |
| `universal_output_truncated` | 5 | stdout/stderr chunk exceeded 4 MB cap; `stream`, `bytes_dropped` |

## Open risks

1. **gVisor `--network=host` reduces network sandbox**: the sandbox can see agentd's loopback but also any other loopback service. v1 compensating controls documented in "Network wiring" above (no other bound ports in default install; placeholder key forces proxy routing). Upgrade to veth/unix socket in obs.1.
2. **gVisor rootless + writable /tmp**: verify `--rootless` doesn't prevent tmpfs mounts for Python workloads that write to `/tmp`. Needs smoke-test with a real LangChain script.
3. **`ANTHROPIC_BASE_URL` inside gVisor with `--network=host`**: gVisor inherits env via `Command::env()` after our allowlist injection; this should work. Needs explicit test.
4. **CI gVisor availability**: all gVisor/universal-tier tests that actually spawn `runsc` must be marked `#[ignore]` or gated on `runsc` being available. Compile-path tests run everywhere.
