# p7.5 — Egress mediator (the governance linchpin) [CORE]

**Branch:** `p7.5-egress-mediator`
**Depends on:** p4.2 (`IsolateNetwork` = `unshare(CLONE_NEWUSER|CLONE_NEWNET)` in pre_exec),
p4.6 (`AllowNetConnect{port}` Landlock V4), p7.1 (HTTP/SSE machinery, `reqwest`), p0.2
(`InferenceGateway` + `ANTHROPIC_BASE_URL` indirection), the MCP gateway (`McpBackend`).
**Related floor:** for the *universal tier* (untrusted/foreign code), a netns confines the
*network* but not the *kernel* — real isolation needs the microVM/gVisor floor (see
`docs/PRODUCT-THESIS.md` security model). The egress mediator and the isolation floor are
both prerequisites for hosting foreign workloads; this spec covers egress, the floor is a
separate increment.
**Why it's the keystone:** the product thesis (`docs/PRODUCT-THESIS.md`) is "secure +
observable." Both — plus framework-agnostic hosting and per-agent model metering — collapse
without this. It is load-bearing three times over. Gate before the universal tier and before
any "your data is bounded/audited" claim.

## Problem

Today an agent (native) or a tool subprocess can be put in a network namespace
(`IsolateNetwork`) or port-restricted (`AllowNetConnect`), but there is **no brokered egress
path**: nothing forces a workload's model calls and tool calls through AgentOS so they can be
metered, audited, routed, and allowlisted. Consequences:
- A foreign-framework agent (LangChain) or headless `claude`/`codex` calls the model API
  **directly**, bypassing metering/audit (the universal tier is fiction without this).
- A compromised/malicious tool can reach arbitrary hosts and exfiltrate data.
- The LLM gateway is an **internal trait**, not a served endpoint, so nothing can point a
  foreign client at it.

## Design

**Confine, then broker.** Each governed workload runs in a network namespace with **no route
to the internet** — its only egress is a local AgentOS proxy. The proxy is the LLM gateway +
the MCP gateway + a per-agent allowlist; everything else is dropped and recorded.

```
governed workload (native agent | LangChain | headless claude)
  netns: only path out = agentd's local proxy (unix socket / loopback veth)
     ├─ POST /v1/messages        → LLM gateway: meter + route + audit + (native) redact → upstream
     ├─ tool call (MCP)          → MCP gateway: capability-scope + approval-gate + audit
     ├─ allowlisted tool API host (Gmail/Linear/…)  → forwarded + audited
     └─ anything else            → DENIED + egress_denied event
```

**Three honesty boundaries (state them in code comments + the event payloads):**
1. **Confinement is strong; the seal is not hermetic.** The model channel and the allowlisted
   tool hosts are themselves potential covert/exfil channels. This bounds blast radius and
   makes everything accountable; it does not make exfiltration impossible.
2. **Content observability is tiered.** Native agents → agentd is the client, full content
   audit/redaction. Universal-tier foreign workloads that pin TLS → connection-level metering
   only (no MITM); content audit is best-effort and must be reported as such.
3. **This is a service-mesh-grade subsystem**, not a flag. Scope v1 narrowly (below).

### Boundary secret rewriting (deterministic anti-credential-theft)

The agent never holds real credentials. The scheduler injects **structurally valid
placeholders** (e.g. `sk-ant-PLACEHOLDER-<id>`) into the workload's env. On an outbound call,
the egress proxy swaps placeholder→real secret *at the boundary* before forwarding. A full
memory dump / context-window exfiltration of the agent yields only inert placeholders. This is
deterministic (vs. probabilistic DLP) and structurally eliminates credential exfiltration —
it does NOT stop laundering data through the allowed model channel (different threat; see
non-goals). The real secrets live only in the proxy's isolated namespace.

### Tamper-evident audit receipts (forensic evidence, not forgeable logs)

The flight recorder is append-only JSONL the agent's own process could delete/forge if
compromised. The egress proxy — outside agent memory, holding an Ed25519 key the agent cannot
reach — emits a signed **action receipt** per attempted action: `{action, target, principal,
policy_hash, verdict, ts, chain_prev_hash}`, where `chain_prev_hash` is the SHA-256 of the
prior receipt's bytes (hash chain). Removing/forging/reordering breaks the chain. The receipts
form an offline-verifiable `evidence.jsonl` the agent is mathematically incapable of forging.
This is the upgrade that makes "unsupervised agent" auditable by a third party.

## Scope — files

- **`agentd/src/egress.rs` (new) — the served gateway.** A local HTTP server (loopback +
  unix socket) exposing an Anthropic-compatible `/v1/messages` (reuse `AnthropicGateway`
  streaming from p7.1/p7.2) that wraps `InferenceGateway`: meters tokens per calling agent,
  records `inference_request`/`inference_response` with the agent id, routes upstream. Plus a
  tool-proxy path that dispatches to the MCP gateway under the caller's capability set. Plus an
  allowlist forwarder for granted tool-API hosts. Default: deny + record. Also performs
  **boundary secret rewriting** (placeholder→real swap before forward) and emits a signed
  **action receipt** per attempted call (Ed25519, `chain_prev_hash`) to `evidence.jsonl`.
- **`agentd/src/scheduler.rs` — placeholder injection + signer key.** Inject placeholder
  secrets into the workload env; hold the real secrets + the Ed25519 signer key in the proxy's
  namespace, never in the agent's. (Secrets-from-env invariant preserved: reals still come
  from env, just not the agent's env.)
- **`agentctl verify` (or a standalone verifier) — offline receipt verification.** Recompute
  each receipt's canonical hash, check the Ed25519 signature against a pinned public key, and
  verify the SHA-256 chain. Exit 0 = valid, non-zero = tampered.
- **`sandbox/src/lib.rs` — egress-confinement mode.** Extend the net story: when a workload is
  `IsolateNetwork`, provide a *controlled path to the proxy only* (impl spike: veth pair to the
  agentd net, or pass the proxy's unix-socket FD + a tiny in-netns loopback forwarder). New
  `SandboxRule::EgressViaProxy { socket }` (or fold into `IsolateNetwork`). `EnforcementStatus`
  gains `egress_brokered: bool`.
- **`agentd/src/main.rs` + scheduler — workload supervisor (minimal).** Spawn a *foreign-agent*
  workload as a governed child (like an MCP server today), in the egress-confined netns, with
  its model `base_url`/`ANTHROPIC_BASE_URL` (or `OPENAI_BASE_URL`) pointed at the proxy socket.
  v1 supports one foreign workload shape (a command + args), not a full container runtime.
- **`agentd/src/config.rs` — per-agent egress allowlist.** Reuse/extend `Capability::Net
  { hosts, ports }` as the allowlist of tool-API hosts the proxy will forward; model host is
  implicit (the gateway). Deny-by-default.
- **`agentd/src/events.rs` — events.** `egress_brokered` (kind, dest, agent, bytes, content_audited:bool),
  `egress_denied` (agent, attempted dest), `action_receipt_emitted` (agent, verdict, chain_seq).
  CONVENTIONS.md rows.
- **`agentctl` — surface egress in the inspector** (brokered/denied counts per agent; the
  content-audited flag so the two tiers are visible).

**Capabilities:** reuse `Net { hosts, ports }` for the tool-host allowlist; no raw network
without it. Model access is implicit via the proxy (always metered). **No new agent-facing
tool** — this is infrastructure, not something an agent calls.

## Tests

- `egress::proxy_meters_and_audits_model_call` — a call through the proxy is recorded with the
  agent id + token counts and forwarded.
- `egress::denies_unallowlisted_host` — a brokered request to a host not in `Net.hosts` →
  `egress_denied`, dropped.
- `sandbox::isolate_network_has_no_default_route` (Linux, gated) — a confined child cannot
  reach an external host directly; only the proxy socket works.
- `egress::foreign_client_via_base_url` — a tiny non-native client pointed at the proxy
  `base_url` gets a metered/audited completion (proves universal tier, no rewrite).
- `egress::content_audit_flag_reflects_tier` — native call records `content_audited:true`;
  a simulated pin-TLS foreign call records `content_audited:false` (honesty in the data).
- `egress::placeholder_is_rewritten_at_boundary` — the workload only ever sees the placeholder;
  the forwarded request carries the real secret; an env/memory dump of the agent has no real key.
- `egress::receipt_chain_detects_tampering` — a valid chain verifies (exit 0); removing/forging/
  reordering a receipt fails verification (non-zero). Agent cannot produce a valid signature.

## Acceptance

- A governed foreign workload (e.g. a 20-line Python script using an OpenAI-compatible client)
  runs with its `base_url` at the proxy and network locked down: its model call **succeeds,
  metered + audited**, and a raw `curl https://example.com` from inside its netns **fails** and
  is recorded as `egress_denied`.
- A leaked agent context / env contains only placeholder secrets; the real secret reached the
  upstream API; the `evidence.jsonl` chain verifies offline (exit 0) and fails if tampered.
- The single-agent + memory demos are unchanged when egress confinement is not enabled.
- `cargo build` + `clippy --all-targets` + `test` + `make clippy-linux` clean; `agentd` ≤ 6 MB
  (watch the proxy/server weight — reuse existing `reqwest`/HTTP, add no heavy deps).

## Non-goals (honest)

- Not a hermetic seal — does not stop laundering via the allowed model/tool channels.
- Not content-DLP for cert-pinning foreign workloads (native tier only in v1).
- Not a full container runtime — v1 hosts one foreign-workload shape; richer supervision later.
- Prompt-injection-driven exfiltration is out of scope (mitigated by allowlist + audit +
  approval gate p7.4, not eliminated).

### Phase 3 — Engineering Review

**Dual-voice consensus: Claude Eng (8 findings) + Codex Eng (5 critical + 5 high)**

#### CRITICAL (both voices agree)

| # | Finding | Fix |
|---|---------|-----|
| E1 | **Netns/transport mechanism underspecified.** `IsolateNetwork` creates a net namespace with `unshare(CLONE_NEWNET|CLONE_NEWUSER)` but does NOT configure loopback, routing, or any veth. The foreign workload is in a namespace with no network at all — `http://localhost:PORT` doesn't work because loopback is down. Foreign clients (Anthropic/OpenAI SDKs) need `http://host:port`, not unix sockets. Plan says "unix socket / loopback veth" without committing to either — neither works as stated. | Commit to: FD-pass via `socketpair()` + in-netns TCP forwarder (tiny listener bound to 127.0.0.1 in the child's netns, forwarded to the pre-opened socketpair FD). `SandboxRule::EgressViaProxy { proxy_fd: RawFd }` carries the FD; `apply_compiled` clears close-on-exec on it; workload env gets `AGENTOS_EGRESS_ADDR=127.0.0.1:PORT`. Veth is out of scope for v1. |
| E2 | **No HTTP server library in the codebase.** `reqwest` is an HTTP client. `tokio::net` provides sockets, not HTTP framing. A hand-rolled HTTP/1.1 server that is security-safe (framing, chunked bodies, keep-alive, slowloris, SSE disconnect, backpressure) is security-sensitive and 500+ lines. | Use `hyper` v1 directly (already in the dep tree transitively via `reqwest`; server-side surface). Do NOT add axum. Explicitly enable hyper server features in `Cargo.toml` and measure binary size delta with `cargo bloat` before any other work. |
| E3 | **Caller identity must come from the connection, not a header.** A shared HTTP listener cannot trust an `agent_id` or `X-AgentOS-Agent-Id` header supplied by the workload — a malicious workload can spoof it to inherit another agent's capability set or charge calls elsewhere. | Use a **per-workload unix socket** (one socket per governed child, bound at spawn time, path encoded in `AGENTOS_EGRESS_ADDR`). The proxy maps socket → policy at accept time; identity is the file descriptor, not a header value. |

#### HIGH (both/one voice)

| # | Finding | Fix |
|---|---------|-----|
| E4 | **Binary size risk is larger than stated.** Codex measured the workspace binary at 4,198,464 bytes (~4.0 MB); only ~2.0 MB headroom. New linkage: hyper server surface, Ed25519 ops, proxy parsing/policy, `agentctl verify` linking back to `agentd`. Using `ring` (already in dep tree via rustls) for Ed25519 reuses already-linked code and minimizes delta. | First PR commit: add hyper server + `ring` signing behind a minimal stub, build musl target, record delta. An MCP-server-style `Command::spawn()` inherits the parent env by default. If the foreign workload spawns before the placeholder is substituted, it gets the real key. | Foreign workload spawn path must call `.env_clear().env("ANTHROPIC_API_KEY", &placeholder).env("ANTHROPIC_BASE_URL", &proxy_url)`. Remove the `curl` recording claim from the acceptance criteria. |
| E8 | **Secret rewriting is format-naive and unsafe for non-Anthropic credentials.** Generic byte substitution across a streaming/compressed body risks accidental replacement, corruption, and injection into attacker-controlled fields. ### Pre-implementation requirements (p7.5 vertical slice)

Before writing any implementation code, the plan has the following required amendments from the review:

1. **E4 — Binary size delta first.** First commit: add `ring` (Ed25519 signing) + hyper v1 server surface behind a stub, build musl target, measure delta. If delta > 1.5 MB → stop, redesign. Add CI size-delta test.
2. **E5 — `env_clear()` in spawn path.** Any foreign-workload spawn path must call `.env_clear().env("ANTHROPIC_API_KEY", &placeholder)`. Add test asserting forwarded `x-api-key` header carries the real key.
3. **E6 — `evidence.jsonl` outside agent FsWrite grants.** Apply OV-1 invariant (p5.8 pattern): `evidence_path` must not fall inside any agent's `FsWrite` prefix. `anyhow::ensure!` at startup.
4. **D1 (DX) — Native-agent activation model.** State explicitly in spec and code comments: proxy always starts; native agents call `InferenceGateway` directly (in-process, no HTTP hop); secret rewriting and receipt emission happen in-process. No new TOML field required for native agents.
5. **D2 (DX) — Fail-closed startup invariant.** If proxy fails to bind, agentd exits non-zero. `egress_proxy_failed` flight event. Never start the runtime without a functioning proxy when egress confinement is configured.

### Revised scope for p7.5 (post-gate)

**In scope:**
- `agentd/src/egress.rs` (new): local HTTP server (hyper v1, loopback-only for native tier), serves `/v1/messages` wrapping `InferenceGateway`, emits metered events. - Allowlisted host forwarder (DNS rebinding mitigations, host policy enforcement).
