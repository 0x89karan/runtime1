# p7.3 — Write-capable FUSE control surface

**Branch:** p7.3-fuse-write-control-surface
**Depends on:** p3.1 (AgentsFs + FUSE mount), p6.2 (agentctl spawn), p6.6 (spawn view in agentctl watch)
**Version:** 0.37.0

---

## Problem

`agentctl watch`'s spawn view (p6.6) spawns agents by exec'ing a new `agentd` process —
completely separate from the running scheduler. You get two schedulers, two FUSE mounts
fighting for `/agents`, and two isolated runtimes with no awareness of each other.

The FUSE surface (`/agents/`) is read-only today. There is no mechanism for an operator
to inject work into a running scheduler without restart.

## Goal

Add `/agents/control` as a writable pseudo-file. Writing a JSON command (`spawn`,
`signal`) injects it directly into the already-running scheduler via an in-process
channel. `agentctl watch` spawn view writes to `/agents/control` instead of exec'ing
a second agentd.

## Acceptance criteria (from ROADMAP)

1. `echo '{"spawn":{"task":"summarise the news","id":"news-scout"}}' > /agents/control`
   starts a new agent in the running scheduler. The agent appears in
   `agentctl watch` within one FUSE TTL (< 1 s).
2. `agentctl watch` spawn view (p6.6) writes the control file instead of exec'ing
   agentd. Spawning from the TUI adds the agent to the live runtime.
3. `/agents/control` is absent (not listed in root readdir) on macOS (non-Linux stub).
4. Invalid JSON or unknown command returns a write error.
5. 889 → ~920+ tests pass.

## Architecture

### Channel design

```
     FUSE OS thread                         tokio scheduler loop
     ─────────────                         ────────────────────
     write("/agents/control", data, fh)
           │
           ▼
     write_buffers[fh].extend(data)         (no parse yet — partial write OK)
     return Ok(data.len())
           │
     flush(fh) / release(fh) called
           │
           ▼
     parse_control_cmd(write_buffers[fh])
     write_buffers.remove(fh)
           │
           ▼
     control_tx.try_send(cmd) ──mpsc──►  select! arm on control_rx
       └─ full → EBUSY                        │
       └─ closed → EIO                         ▼
                                         dispatch_operator_spawn(cmd)
                                         (no parent, depth=0)
```

`tokio::sync::mpsc::channel::<ControlCommand>(16)` — bounded, 16 slots. Sender is
`Send + Sync`, so the FUSE OS thread can call `try_send()` without a runtime.

**Why `try_send` not `blocking_send`:** The FUSE OS thread serves ALL of `/agents/` —
blocking it while the scheduler is stuck on a minute-long inference call would freeze
`ls /agents/`, `cat /agents/*/status`, and every other FUSE read. `try_send` returns
`EBUSY` immediately if the 16-slot buffer is full; the operator retries.

**Why buffer on flush, not parse on write:** POSIX does not guarantee a single `write()`
syscall delivers the full JSON. `echo '{"spawn":{...}}' > /agents/control` performs:
open (truncate) → one or more `write()` calls → close. We must buffer bytes keyed by
file handle (`HashMap<u64, Vec<u8>>`) and parse only on `flush()` / `release()`.

### `ControlCommand` enum and wire format (in `agentd/src/control.rs` — new file)

`ControlCommand` lives in `agentd`, not `surfaces`. `AgentConfig` does not contain
`ModelConfig` (model config is at a higher `Config` level); carrying full `AgentConfig`
would still lose model config. The correct type for the wire format is `OperatorSpawnRequest`:

```rust
// agentd/src/control.rs
#[derive(Serialize, Deserialize, Debug)]
#[serde(rename_all = "snake_case")]
pub enum ControlCommand {
    Spawn(OperatorSpawnRequest),
}

#[derive(Serialize, Deserialize, Debug, Default)]
pub struct OperatorSpawnRequest {
    pub task:         String,
    pub id:           Option<String>,   // None → scheduler generates unique ID
    pub capabilities: Option<Vec<String>>,
    pub priority:     Option<u32>,
    pub token_budget: Option<u64>,
    pub max_turns:    Option<u32>,
}
```

`id` is `Option<String>` — shell users may omit it; scheduler auto-generates a
`nanoid`-style ID.

JSON wire format (same for shell and TUI — TUI fills more fields from template):
```json
{"spawn": {"task": "summarise the news", "id": "news-scout"}}
```
All fields except `task` are optional. The TUI serializes the template's `AgentConfig`
fields it has (capabilities, priority, token_budget, skills) into the same struct.

### `surfaces` crate: opaque control callback

`surfaces` does NOT import `agentd` types (prevents circular dep: `agentd → surfaces → agentd`).
Instead, surfaces accepts an opaque dispatch callback:

```rust
// surfaces/src/lib.rs (linux-only)
pub type ControlDispatch = Arc<dyn Fn(&[u8]) -> i32 + Send + Sync>;
```

`AgentsFs` holds `control_dispatch: Option<ControlDispatch>`. On `flush()`/`release()`,
it calls `control_dispatch(raw_bytes)`, receives an errno (0 = ok, else error). Parsing
of `ControlCommand` happens inside the closure defined in `agentd/src/main.rs`.

In `main.rs`:
```rust
let (control_tx, control_rx) = mpsc::channel::<ControlCommand>(16);
let tx = control_tx.clone();
let dispatch: ControlDispatch = Arc::new(move |bytes: &[u8]| {
    match serde_json::from_slice::<ControlCommand>(bytes) {
        Ok(cmd) => match tx.try_send(cmd) {
            Ok(()) => 0,
            Err(TrySendError::Full(_)) => libc::EBUSY,
            Err(TrySendError::Disconnected(_)) => libc::EIO,
        },
        Err(_) => libc::EINVAL,
    }
});
surfaces::agents_fs::mount(&mountpoint, snapshot, mem_access, Some(dispatch))
```

### Inode assignment

```
1      = root "/"
9      = kb/ directory
10     = system/ directory
11     = system/budget
12     = system/queue
13     = system/sandbox
14     = system/provider
15     = control  ← NEW (write-only pseudo-file, root level)
1010+  = per-agent directories (unchanged)
```

`INO_CONTROL = 15`. Added to the `_: () = assert!` chain ensuring no slot collision.

### FUSE mount option change

Remove `MountOption::RO` from `mount()`. Do NOT add `MountOption::AllowRoot` — in this
single-tenant system the operator user is the same UID as agentd; owner-write mode
(`0o222`) is sufficient. Implement `write()`, `flush()`, `release()`, and `setattr()`
on `AgentsFs` — gated `#[cfg(target_os = "linux")]`.

Read of `/agents/control` returns empty bytes (ACK-less write-only semantics). The
command result is observable via the agent appearing in `/agents/<id>/status`.

### `agentd/src/scheduler.rs`
- `Scheduler` struct gains `control_rx: Option<tokio::sync::mpsc::Receiver<ControlCommand>>`
  and `default_model_cfg: ModelConfig` (needed by `dispatch_operator_spawn` since
  `SchedulerState` has no model config and operator spawns have no parent to inherit from).
- `Scheduler::with_control(rx)` builder method.
- The `run()` loop `select!` integration. The current loop exits when
  `FuturesUnordered::next()` yields `None` (all agents done). After adding the control
  arm, it must NOT exit on that condition alone — an idle scheduler should keep waiting
  for control commands until the channel itself is closed. Correct pattern:
  ```rust
  loop {
      tokio::select! {
          biased;  // check pending agents first
          Some(effect) = state.pending.next(), if !state.pending.is_empty() => {
              handle_effect(effect, &mut state, ...);
          },
          Some(cmd) = async {
              if let Some(rx) = control_rx.as_mut() { rx.recv().await } else { None }
          } => {
              dispatch_operator_spawn(cmd, &mut state, ...);
          },
          else => break,  // both arms disabled → pending empty AND rx closed/None
      }
  }
  ```
  The `else` arm fires only when ALL other arms are disabled simultaneously — meaning
  `pending` is empty AND `control_rx` is closed or None. This is the correct exit
  condition for a scheduler that accepts live work injection.
- `dispatch_operator_spawn(req: OperatorSpawnRequest, state: &mut SchedulerState,
  model_cfg: &ModelConfig, ...)`: generates ID if `req.id` is None, builds `AgentConfig`
  from req fields + `model_cfg`, calls `AgentTask::new()`, inserts into `state.agents`,
  enqueues with `enqueue_or_defer`, inserts `spawn_depths[id] = 0`.
  Records `FuseControlReceived` flight event.
- No entry in `awaiting` (no parent to notify), no entry in `parent_map` (root agent).

### `agentctl/src/watch/mod.rs`
- `execute_pending_spawn` is restructured to return `SpawnOutcome`:
  ```rust
  enum SpawnOutcome { InjectedViaControl { id: String }, FellBackToExec(PathBuf, PathBuf) }
  ```

## GSTACK REVIEW REPORT

**Status: APPROVED — ready for implementation on branch `p7.3-fuse-write-control-surface`**

### What changed from the initial draft

The initial plan had 8 correctness bugs across three layers that would have produced broken or uncompilable code:

| Layer | Bug | Fix |
|---|---|---|
| FUSE OS thread | `blocking_send` freezes all /agents/ reads during inference | `try_send` + EBUSY |
| FUSE write() | Partial JSON on split writes → EINVAL on every real shell redirect | Buffer by fh, parse on flush()/release() |
| surfaces crate | `ControlCommand(AgentConfig)` creates circular dep | Opaque `ControlDispatch` callback |
| Wire format | `AgentConfig.id` required field → parse error for shell users | `OperatorSpawnRequest` with Option<String> id |
| Scheduler loop | `?.recv()` in async{} doesn't compile; early break drops queued cmds | `select!` with `else` arm |
| FUSE dispatch | INO_CONTROL missing from getattr/lookup/open → ENOENT | Explicit arms in all three |
| ModelConfig | Not available in SchedulerState for operator spawns | `default_model_cfg` on Scheduler |
| Tests | `ReplyEmpty` not constructible → 7 tests unwritable | `process_control_flush()` non-trait helper |

Additionally, 4 DX improvements were caught that improve the feature's ergonomics:
- TUI stays in Dashboard (not exits) after spawning → operator sees agent come alive
- TUI preview shows JSON wire payload (the actual format sent)
- `docs/CONTROL_SURFACE.md` for operator reference
- `FuseControlError` includes `is_error: true` for Inspector filter
