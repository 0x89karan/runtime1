# p6.8 — Sandbox-enforcement surface + edge-case polish

**Branch:** p6.8-sandbox-enforcement-surface  
**Depends on:** p6.3 (System/Agent-detail views), p4.1–p4.6 (full sandbox stack)  
**Version bump:** v0.34.0  
**Status:** planning

---

## What we're building

Phase 6 closes with p6.8 as the final exit criterion: the operator can inspect
every sandbox enforcement detail, see degradation warnings, and filter the flight
log without writing `jq`. This increment has two orthogonal parts:

1. **Enforcement surface** — expose `EnforcementStatus` in FUSE + TUI (System view,
   Agent-detail). Make silent degradation (F-002: Landlock V4 missing → net rules
   silently not enforced) visible as a prominent warning.

2. **Inspector / flight-log filters** — a new TUI view (`View::Inspector`) that loads
   `flight.jsonl` and lets the operator filter by event kind, agent, error, and
   sandbox-specific event types.

## Implementation plan

### Step 1: Richer snapshot data

**File: `surfaces/src/snapshot.rs`**

Add `ServerSandboxInfo` and `SandboxEnforcementSummary` structs to `SchedulerSnapshot`:

```rust
#[derive(Debug, Clone, Serialize, Deserialize, Default)]
pub struct ServerEnforcement {
    pub name:            String,
    pub isolation:       String,        // "none" | "gvisor"
    pub landlock:        bool,
    pub seccomp:         bool,
    pub spawn_enforcement: String,      // "fork_vfork_only" | "none"
    pub namespace_net:   bool,
    pub namespace_mount: bool,
    pub landlock_net:    bool,
}

#[derive(Debug, Clone, Serialize, Deserialize, Default)]
pub struct SandboxSummary {
    pub applied:      bool,
    pub servers:      Vec<ServerEnforcement>,
    pub degradations: Vec<String>,      // e.g. "landlock_net_unavailable"
}
```

Replace `sandbox_applied: bool` on `SchedulerSnapshot` with `sandbox: SandboxSummary`.

**Degradation strings (canonical):**
- `"landlock_net_unavailable"` — kernel < 6.7, net caps present but port rules not enforced
- `"spawn_enforcement_unavailable_arch"` — aarch64 + DenySpawn requested, BPF not applied
- `"gvisor_active"` — isolation=gvisor, native sandbox skipped

**File: `agentd/src/main.rs`**

After spawning all MCP servers, populate `snap.sandbox` from the per-server
`EnforcementStatus` structs (already computed in the loop). Also compute
`degradations` by checking each server's caps against its enforcement.

**Degradation detection logic:**
```
For each server:
  if server has AllowNetConnect rules AND !enf.landlock_net:
    add "landlock_net_unavailable"
  if server has DenySpawn AND enf.spawn_enforcement == "none":
    add "spawn_enforcement_unavailable_arch"
  if server.isolation == gvisor:
    add "gvisor_active"
```

### Step 3: Per-agent `/agents/<id>/sandbox`

**File: `surfaces/src/agents_fs.rs`**

Add `OFF_SANDBOX: u64 = 10` (next available slot; `OFF_PARENT = 9`).

The per-agent sandbox file shows the **agent → server → enforcement chain**: which MCP
servers this agent has `Mcp` capability access to, and how those servers are sandboxed.
Sandbox enforcement belongs to MCP server processes, not to agents; this view surfaces
the chain correctly.

```json
{
  "agent_id": "scout",
  "accessible_servers": [
    {
      "name": "fs",
      "isolation": "none",
      "landlock": true,
      "seccomp": false,
      "spawn_enforcement": "none",
      "namespace_net": true,
      "namespace_mount": false,
      "landlock_net": false
    }
  ]
}
```

This requires `AgentSnapshot` to carry the names of MCP servers the agent has `Mcp`
capability access to. Add `accessible_server_names: Vec<String>` to `AgentSnapshot`.

**Wire-up in `main.rs`**: after building `SandboxSummary`, for each agent collect the
server names from its `Capability::Mcp { server, .. }` grants →
`accessible_server_names`. The FUSE read handler then filters `SandboxSummary.servers`
by those names to produce the per-agent view (no duplicate server data stored).

The per-agent sandbox file also needs plumbing in:
- `readdir` for the agent directory (emit `OFF_SANDBOX` entry `"sandbox"`)
- `lookup` for `"sandbox"` name under agent directory
- `read` dispatch for `OFF_SANDBOX` inode
- `getattr` for the new file
- **`alloc_dir` offset array** — add `OFF_SANDBOX` to the registration loop (currently only 0–9; `OFF_SANDBOX = 10` must be explicitly included); add `assert!(OFF_SANDBOX < DIR_STEP)` compile-time guard
- **`prune_dead_agent`** — add `OFF_SANDBOX` to the cleanup offset list to avoid inode leak on agent exit
- **`file_name_for_offset`** — add `OFF_SANDBOX => "sandbox"` match arm (used in tests)

### Step 7: Inspector view (`View::Inspector`)

New module: `agentctl/src/watch/inspector.rs`

**Data model:**
```rust
pub struct FlightEntry {
    pub agent_id:  String,    // from "agent" field
    pub kind:      String,    // from "kind" field
    pub ts:        String,    // from "ts" field (ISO)
    pub summary:   String,    // formatted one-liner
    pub raw:       String,    // original JSON line
}

pub enum InspectorFilter {
    All,
    Errors,     // kind contains "error"
    Sandbox,    // kind = "sandbox_applied" | "sandbox_skipped"
    CapDenied,  // kind = "capability_denied" (if we emit this) or tool errors
    Custom(String),   // substring match on agent_id or kind
}
```

**TUI view:**
- Key `[i]` from Dashboard → `View::Inspector`  
- `[Tab]` cycles filter preset: All → Errors → Sandbox → CapDenied
- `[/]` opens text input for custom filter (same pattern as memory view search)
- `↑↓/j/k` scroll
- Header shows current filter + line count
- `Esc/q` back to Dashboard

**Flight file reading:**
Re-use/refactor `read_flight_tail_from()` in agents_fs. The TUI reads the raw
`flight.jsonl` path (passed via `--log-path`, same as topology). Lines are parsed
client-side; invalid JSON lines are shown as `[parse error]`.

Parse each JSON line to extract: `agent`, `kind`, `ts`, and a one-line summary
from the `data` field (top-level keys joined as `key=value`).

**Filter predicates:**
- `All`: no filter
- `Errors`: `kind.contains("error") || kind == "tool_result" && data.is_error == true`
- `Sandbox`: `kind == "sandbox_applied" || kind == "sandbox_skipped"`
- `CapDenied`: kind contains `"capability"` or data contains `"denied"`
- `Custom(s)`: `agent_id.contains(s) || kind.contains(s)`

**MAX_INSPECTOR_LINES = 500** (client-side cap, reading full flight.jsonl up to 512 KB)

## Data flow

```
main.rs
  MCP server spawn loop
    → per-server EnforcementStatus
    → SandboxSummary { applied, servers, degradations }
    → snap.sandbox = summary
    → snap.agents[i].sandbox_degradations = per-agent subset

SchedulerSnapshot (surfaces crate)
  → agents_fs.rs:
      INO_SYS_SANDBOX → serialize SandboxSummary as JSON
      agent_dir + OFF_SANDBOX → serialize AgentSandboxInfo as JSON

agentctl watch reader.rs
  read_sys_sandbox() → SysSandbox { applied, servers, degradations }
  read_agent_sandbox() → AgentSandbox { has_net_cap, net_enforced, degradations }

agentctl watch views.rs
  render_system(): warnings from sys_sandbox.degradations
  render_agent_detail(): sandbox row from agent.sandbox

agentctl watch inspector.rs
  load from --log-path flight.jsonl
  filter/display FlightEntry list
```
