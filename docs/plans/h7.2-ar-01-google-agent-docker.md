# h7.2-ar-01: Generic Docker Agent Entrypoint Mode

## Problem

6 templates in the catalogue embed `../docker/` relative paths in `[[tools.mcp_servers]] args`.
These paths resolve correctly when agentd runs from `agentd/` (the `cargo run` CWD) but break
inside Docker where agentd runs from `/workspace` and MCP scripts live at `/etc/agentd/*.py`.

**Broken templates (standalone — not covered by the existing `cos` entrypoint mode):**
- `google-agent` — `../docker/oauth_mcp.py`
- `scout` — `../docker/http_mcp.py`, `../docker/search_mcp.py`
- `code-aware` — `../docker/shell_mcp.py`, `../docker/http_mcp.py`
- `librarian` — `../docker/http_mcp.py`, `../docker/search_mcp.py`

(`cos-inbox` and `cos-orchestrator` embed `../docker/` paths but are already handled by the `cos`
entrypoint mode's sed rewrite — not in scope here.)

## Goal

A single `agent` entrypoint mode that can run **any** single-agent template in Docker with correct
path resolution. No per-template modes; no bespoke sed blocks for each template.

```bash
TEMPLATE_NAME=google-agent AGENT_TASK="Summarize my last 5 unread emails" \
  docker compose run --service-ports --rm agent
```

## Approach: generic `agent` entrypoint + `agentctl spawn --dry-run` + sed

`agentctl spawn <name> --task "..." --dry-run` already lowers a template to a valid TOML config.
The output is piped through a single generic sed rewrite (`../docker/` → `/etc/agentd/`) before
being written to `/data/agent.toml` and passed to agentd.

This is strictly better than per-template modes: new templates get Docker support for free.

## Implementation

### 1. `docker/entrypoint.sh` — add `agent)` case + `set -o pipefail`

Add `set -o pipefail` after `set -e` at the top of entrypoint.sh (catches agentctl failure in
pipeline — `set -e` alone does not, as pipeline exit status is the last command).

```bash
agent)
  check_api_key
  TEMPLATE="${TEMPLATE_NAME:?TEMPLATE_NAME must be set}"
  TASK="${AGENT_TASK:?AGENT_TASK must be set}"
  mkdir -p /data
  # Warn if OAuth callback port set but port publishing may be missing
  if [ -n "${OAUTH_CALLBACK_PORT:-}" ]; then
    echo "  OAuth mode: run with 'docker compose run --service-ports' to publish port $OAUTH_CALLBACK_PORT"
  fi
  # Lower template → TOML, rewrite ../docker/ paths to /etc/agentd/ (Docker layout)
  # Use $() capture so agentctl failure is caught even without pipefail on older bash
  _raw=$(agentctl spawn "$TEMPLATE" --task "$TASK" --dry-run) || {
    echo "ERROR: agentctl spawn failed for template '$TEMPLATE' — check TEMPLATE_NAME" >&2
    exit 1
  }
  printf '%s\n' "$_raw" | sed 's|"\.\./docker/|"/etc/agentd/|g' > /data/agent.toml
  [ -s /data/agent.toml ] || {
    echo "ERROR: rendered config is empty for template '$TEMPLATE'" >&2
    exit 1
  }
  cd /data
  exec agentd /data/agent.toml
  ;;
```

Notes:
- `$()` capture + explicit `||` error check catches `agentctl` failure cleanly (avoids relying
  on `pipefail` being set, and preserves agentctl's stderr error messages in the terminal)
- `agentctl spawn --dry-run` writes TOML-comment provenance lines (`# Generated by...`) which
  are valid TOML — no stripping needed
- `--task "$TASK"` is a CLI flag, not inline sed — no shell injection risk from task text
- `AGENTOS_REPO_TEMPLATES_DIR=/etc/agentd/templates` in compose makes template resolution
  explicit (replaces 8-level binary-walk heuristic)

### 2. `docker-compose.yml` — add `agent` service

```yaml
  agent:
    build: .
    privileged: true
    volumes:
      - agent-data:/data
      # Mount your files here for templates that read from /workspace (scout, librarian):
      # - ./my-files:/workspace:ro
    ports:
      - "8585:8585"    # OAuth callback — Docker Desktop proxies host:8585 → container:8585
    environment:
      - ANTHROPIC_API_KEY
      - TEMPLATE_NAME              # required: "google-agent", "scout", "librarian", etc.
      - AGENT_TASK                 # required: the task string
      - HOME=/data                 # token files land on named volume — persist across restarts
      - AGENTOS_REPO_TEMPLATES_DIR=/etc/agentd/templates  # explicit; avoids binary-walk heuristic
      # OAuth (google-agent and any OAuth template)
      - OAUTH_CLIENT_ID
      - OAUTH_CLIENT_SECRET
      - OAUTH_REFRESH_TOKEN        # optional: skip the OAuth dance on re-runs
      - OAUTH_AUTH_URL=https://accounts.google.com/o/oauth2/v2/auth
      - OAUTH_TOKEN_URL=https://oauth2.googleapis.com/token
      - OAUTH_SCOPES=https://www.googleapis.com/auth/gmail.readonly https://www.googleapis.com/auth/drive.readonly
      - OAUTH_ALLOWED_HOSTS=accounts.google.com,oauth2.googleapis.com,www.googleapis.com,gmail.googleapis.com
      - OAUTH_PROVIDER_NAME=google
      - OAUTH_CALLBACK_PORT=8585
      # Web search (scout, librarian)
      - BRAVE_SEARCH_API_KEY
    command: agent
    stdin_open: true
    tty: true
    sysctls:
      net.ipv4.tcp_keepalive_time: 15
      net.ipv4.tcp_keepalive_intvl: 5
      net.ipv4.tcp_keepalive_probes: 3
```

`HOME=/data` makes OAuth token files (`~/.agentos-oauth/google.json`) land on the named volume
so they persist across `--rm` runs. On re-runs, set `OAUTH_REFRESH_TOKEN` to skip the dance.

`docker compose run --service-ports --rm agent` (not plain `run`) is required to publish port
8585 for the OAuth callback. Without `--service-ports`, the port is not forwarded and the
callback hangs silently.

Add `agent-data` to the top-level `volumes:` block.

## Scope boundary: `code-aware` template

`code-aware` uses `../docker/shell_mcp.py` and `../docker/http_mcp.py` — path rewriting works.
But it also requires `runsc` (gVisor), `npx`, and `uvx` which are not installed in the Docker
image. Path rewriting is verified; actual execution is out of scope for this increment. Document
this clearly in the test plan — do not claim "any template runs".

## What's deferred

- **h7.1-ar-01** (`${AGENTOS_SCRIPTS_DIR}` interpolation in agentd itself): still the right
  long-term fix. This increment is the minimal shell bridge until that lands.
- **Memory-enabled templates with QEMU-only paths** (e.g. `store_path = "/run/memory/memory.redb"`):
  these fail in Docker regardless of path rewriting. Out of scope.
- **`cos-inbox` / `cos-orchestrator` standalone Docker mode**: not needed — these templates
  are only spawned by the `cos` orchestrator.

### 3. Google-agent OAuth flow (requires credentials)

**Prereq:** Ensure `http://127.0.0.1:8585` is in your Google OAuth client's authorized redirect URIs.

```bash
export OAUTH_CLIENT_ID="<your-client-id>.apps.googleusercontent.com"
export OAUTH_CLIENT_SECRET="<your-client-secret>"
export ANTHROPIC_API_KEY="sk-..."

TEMPLATE_NAME=google-agent \
AGENT_TASK="Summarize my last 5 unread emails" \
  docker compose run --service-ports --rm agent
```

1. Entrypoint lowers `google-agent` template → `/data/agent.toml` with `/etc/agentd/oauth_mcp.py`
2. Agent calls `oauth_start_auth` → URL printed (browser required)
3. Open URL → sign in → authorize Gmail + Drive
4. Browser → `http://127.0.0.1:8585/callback` → Docker Desktop → container:8585 → callback captured
5. Agent calls `oauth_check_auth` → tokens stored at `/data/.agentos-oauth/google.json` (HOME=/data)
6. Agent calls `oauth_call_api` → reads Gmail → summarizes

On re-runs, extract the refresh token to skip the dance:
```bash
docker compose run --rm agent cat /data/.agentos-oauth/google.json | jq -r .refresh_token
export OAUTH_REFRESH_TOKEN="<token>"
```

## Adversarial review findings (post-implementation)

Findings from Claude adversarial review pass; all resolved before ship:

| # | Sev | Finding | Fix applied |
|---|-----|---------|------------|
| F1 | block | `OAUTH_CALLBACK_PORT=8585` hardcoded in compose → OAuth warning fires for every non-OAuth run (scout, librarian) | Changed to `- OAUTH_CALLBACK_PORT` pass-through in agent service |
| F2 | block | `journaler`/`memory-custodian` silently lose all memory — `/run/memory` is ephemeral in Docker | Added entrypoint guard with clear error; removed from TEMPLATE_NAME comment |
| F3 | block | `sed` could rewrite AGENT_TASK if value starts with `../docker/` | Scoped sed to lines matching `args` only |
| F4 | block | Checkpoint cross-contamination when switching templates on same named volume | `rm -f /data/checkpoint.json` before exec; each `run` is fresh |
| F5 | block | `langchain-worker` not blocked despite requiring gVisor (inconsistent with `code-aware`) | Added to guard case block |
| F6 | non-issue | `set -o pipefail` affects catch-all `exec "$@"` | `exec` replaces shell process; pipefail is NOT inherited by exec'd programs |
| F7 | minor | `DRY_RUN_ONLY` only accepts `1` | Extended to accept `1\|true\|yes` |
| — | block | `cron-agent`/`watcher`/`webhook-agent` use `/usr/lib/agentos/docker/` which Docker doesn't have at that path | Added second sed expression for `/usr/lib/agentos/docker/` → `/etc/agentd/` |

## Acceptance Criteria

- `docker compose build agent` succeeds
- `agent-data` named volume defined
- Rendered `/data/agent.toml` contains `/etc/agentd/` paths (not `../docker/` or `/usr/lib/agentos/docker/`) for scout, librarian, google-agent, cron-agent, watcher, and webhook-agent
- `TEMPLATE_NAME=code-aware` exits with a clear "requires runsc" error (not a silent mid-run failure)
- `TEMPLATE_NAME=langchain-worker` exits with a clear "requires runsc" error
- `TEMPLATE_NAME=journaler` exits with a clear "requires /run/memory volume" error
- `OAUTH_CALLBACK_PORT` unset by default in agent service; OAuth warning does NOT appear for scout/librarian runs
- Google-agent OAuth flow completes on macOS Docker Desktop (URL → browser → callback → token)
- Both Gmail and Drive scopes wired in compose service
