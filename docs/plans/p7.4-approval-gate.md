# p7.4 — Approval gate (human-in-the-loop primitive) [CORE]

**Branch:** `p7.4-approval-gate`
**Depends on:** p7.3 (`/agents/control` write surface + `ControlCommand` + scheduler
mpsc dispatch), p1.5 (await/resume mechanism: `AgentEffect::SpawnAgent`/`SendMessage`
park an agent and resume it with a delivered tool result), p3.1 (FUSE surface).
**Why now:** it is the keystone the ops harness (`docs/HARNESS-OPS-PLAN.md`) needs and
cannot reuse or defer; p7.3 is its exact substrate, just merged. Gate before any
harness increment that performs external writes.

## Problem

`agentd` runs agents **autonomously to completion**. There is no way to make an agent
*propose* a risk-bearing action and **park until an operator approves**. The personal
ops harness is "human-in-the-loop by default, escalate autonomy" — impossible without a
runtime approval primitive. The *policy* (which actions are risky, per autonomy level)
belongs in the harness; the **mechanism** (park → surface → resolve → resume) is a core
scheduler concern, exactly like the read-only FUSE surface and p7.3's write surface
already in core.

## Design

Reuse the existing park-and-resume path (how `spawn_agent`/`send_message` already
work): a new sole-call native tool **`request_approval`** produces a new
`AgentEffect::RequestApproval`; the scheduler records a **PendingAction**, parks the
agent (as it parks a parent awaiting a child), and resumes it when the operator writes
an **`Approve`/`Reject`** command to the existing `/agents/control` surface. The queue
is observable via a new read-only **`/agents/approvals`** file.

```
agent calls request_approval{action,risk,summary,args,prev?,new?}
   └─ AgentEffect::RequestApproval ──► scheduler: push PendingAction(id), park agent
                                       snapshot.pending_actions updated
operator (TUI/CLI) reads /agents/approvals  ◄── projects the queue
operator writes /agents/control:
   {"approve":{"id":"act_…","edits":{…}?}}  ──► deliver ToolResult{is_error:false, edited args} → agent resumes
   {"reject":{"id":"act_…","reason":"…"}}   ──► deliver ToolResult{is_error:true, reason}        → agent resumes
```

The approved action is then executed by the agent on its next turn (the agent owns the
write tool + capability; the gate only decides *whether it proceeds*). This keeps
least-privilege intact and avoids the scheduler performing external writes.

## Scope — files

- **`agentd/src/control.rs`** — make `ControlCommand` a **tagged** enum and wire format:
  ```rust
  #[derive(Debug, serde::Deserialize)]
  #[serde(rename_all = "lowercase")]
  pub enum ControlCommand {
      Spawn(OperatorSpawnRequest),
      Approve { id: String, #[serde(default)] edits: Option<serde_json::Value> },
      Reject  { id: String, #[serde(default)] reason: Option<String> },
  }
  ```
  Wire: `{"spawn":{...}}` / `{"approve":{"id":"act_1"}}` / `{"reject":{"id":"act_1","reason":"…"}}`.
  **Back-compat:** keep accepting the current bare `{"task":...}` as `Spawn` (try tagged
  first, fall back to `OperatorSpawnRequest`), or migrate `agentctl` in the same PR and
  document the break in CHANGELOG. Update `parse_control_command` + its tests.

- **`agentd/src/agent/mod.rs`** — register a `request_approval` native tool; intercept it
  in `step()` as a **sole-call** effect (same pattern as `spawn_agent`, including the
  F-16 batched-with-other-tools → recoverable `is_error` handling):
  ```rust
  AgentEffect::RequestApproval { call_id, action: PendingActionRequest }
  ```
  where `PendingActionRequest { kind, risk, summary, args, prev_state?, new_state?, linked? }`.
  Parses from the tool input; malformed input → `is_error` + re-infer (no panic).

- **`agentd/src/scheduler.rs`** — `pending: HashMap<String, ParkedApproval>` in
  `SchedulerState` (+ checkpoint, like `awaiting`). On `RequestApproval`: mint
  `id="act_{seq}"`, store the parked agent + call_id, emit `ApprovalRequested`, update
  snapshot. Extend the `control_rx` `select!` arm: `Approve` → deliver
  `ToolResult{is_error:false, content: edited-or-original args JSON}` to the parked
  agent, emit `ApprovalGranted`; `Reject` → deliver `ToolResult{is_error:true,
  content: reason}`, emit `ApprovalRejected`. Unknown `id` → control write returns an
  errno (already the p7.3 contract). Parked approvals survive restart via checkpoint.

- **`surfaces/src/agents_fs.rs`** — `INO_APPROVALS: u64 = 16` (root-level, read-only,
  mode `0o444`), mirroring `INO_CONTROL = 15`. List it in root `readdir`; `getattr` +
  `read` project `snapshot.pending_actions` as bounded JSON lines (id, agent, kind,
  risk, summary, age). Non-Linux stub omits it.

- **`surfaces/src/snapshot.rs`** — `pending_actions: Vec<PendingActionView>` on
  `SchedulerSnapshot` (bounded, e.g. ≤100), populated each scheduler tick.

- **`agentd/src/events.rs`** — `ApprovalRequested`, `ApprovalGranted`, `ApprovalRejected`
  (+ `kind_str` + CONVENTIONS.md rows).

- **`agentctl`** — `watch`/`ops` approval view: read `/agents/approvals`, and
  approve/reject by writing the tagged command to `/agents/control`. (Read+write both
  over the existing surfaces — no new data plane.)

**Capabilities:** none new — `request_approval` is self-limiting (it only *reduces* what
an agent can do). **Policy/risk classification is OUT OF SCOPE** (harness:
`docs/HARNESS-OPS-PLAN.md` §9, the Approval/Safety agent + policy file).

## Tests

- `control::parse_*` — tagged `spawn`/`approve`/`reject` parse; back-compat bare-spawn
  parses as `Spawn`; bad/unknown → error.
- `agent::request_approval_parks` — calling `request_approval` yields
  `AgentEffect::RequestApproval`, agent not terminal; batched-with-other-tools recovers
  via `is_error` (F-16 parity).
- `scheduler::approve_resumes_agent` — after `RequestApproval`, an `Approve` control
  command delivers a non-error tool result and the agent continues; `edits` override the
  args in the delivered result.
- `scheduler::reject_resumes_with_error` — `Reject` delivers `is_error:true` + reason;
  the agent handles it as normal control flow (no termination).
- `scheduler::pending_survives_checkpoint` — a parked approval restored after restart.
- `surfaces::approvals_surface_lists_pending` — `/agents/approvals` read reflects the
  queue; absent/empty renders cleanly.
- Event-taxonomy completeness test updated for the 3 new kinds.

## Acceptance

- `echo '{"approve":{"id":"act_1"}}' > /agents/control` resumes a parked agent; a
  rejecting write resumes it with an error result; an unknown id returns a write error.
- `cat /agents/approvals` lists pending actions on a running multi-agent demo; the
  `agentctl` approval view approves/rejects them.
- An agent that calls `request_approval` never proceeds with the gated action until
  resolved; every request/grant/reject is in the flight log.
- `cargo build` + `clippy --all-targets` + `test` + `make clippy-linux` clean;
  `agentd` ≤ 6 MB; the single-agent demo flight sequence is unchanged when
  `request_approval` is unused.

## Out of scope (→ harness)

Risk classification, autonomy-level policy (L0–L4), the Approval/Safety subagent, and
the rich `agentctl ops` queue UX — all `docs/HARNESS-OPS-PLAN.md`.
