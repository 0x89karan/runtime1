# p6.7 — Starter Catalogue (7 committed templates)

**Branch:** p6.7-starter-catalogue  
**Base:** main  
**Version target:** v0.33.0  
**Depends on:** p6.1 (template schema), p5.x (memory-gated templates)

---

## Goal

Ship the 7 starter templates that make the agent catalogue tangible and self-describing:
`scout` (already exists), `librarian`, `journaler`, `coordinator`, `code-aware`,
`watcher`, and `memory-custodian`. Each template has a `showcases` rationale that
names the specific AgentOS primitive it demonstrates — not generic LLM-agent behavior.

Phase-5-gated templates (journaler, memory-custodian) and trigger-gated (watcher) ship
in the catalogue with their dependency stated, so the showcase set is honest.

---

## Context

- `templates/scout.template.toml` already exists and passes all template tests.
- `TemplateResolver`, `TemplateConfig`, `TemplateCapabilities` are fully implemented (p6.1).
- `to_agent_config()` strips template-only keys and lowers to a valid `Config`.
- `agentctl list-templates` and `agentctl spawn` both work and are tested (p6.2).
- All Phase-5 memory primitives are implemented: `mem_remember`, `mem_recall`,
  `kb_put`, `kb_get`, `kb_search`, `KbRead`/`KbWrite` capabilities (p5.1–p5.9).
- `spawn_agent`, `list_agents`, `send_message` native tools exist (p1.5).
- `IsolationMode::GVisor` is implemented on Linux (p4.2).

## Increment scope

### New files

1. **`templates/librarian.template.toml`**  
   Caps: `FsRead`/`FsWrite {/workspace/library}`.  
   Tools: `@modelcontextprotocol/server-filesystem` MCP server, sandboxed (Landlock).  
   Showcases: per-tool kernel sandbox (Landlock FS confinement on an MCP subprocess) + capability scoping.  
   `sample_tasks`: at least 2.

2. **`templates/journaler.template.toml`**  
   *Phase-5-gated.*  
   Caps: `FsRead {/workspace}`, `KbRead`/`KbWrite {agent/journaler}`.  
   Tools: native `mem_remember`, `mem_recall`, `kb_get`, `kb_search`.  
   Memory: `[[memory.segments]]` entry for `agent/journaler` (class = "log").  
   `store_path = "/run/memory/memory.redb"`.  
   `gated_requires = "Phase-5 memory (memory.store_path must point to a running redb volume)"`.  
   Showcases: Phase-5 durable per-agent memory surviving across runs + checkpoint/restore.  
   `sample_tasks`: at least 2.

3. **`templates/coordinator.template.toml`**  
   Caps: `Spawn`.  
   Tools: native `spawn_agent`, `send_message`, `list_agents`.  
   `max_turns = 20`.  
   `memory.enabled = false`.  
   Showcases: p1.5 bus + p1.6 Agent Cards + spawn tree — the multi-agent runtime.  
   `sample_tasks`: at least 2.

4. **`templates/code-aware.template.toml`**  
   Caps: `FsRead`/`FsWrite {/workspace/repo}`, `Net {ports:[443]}`.  
   Tools: `@modelcontextprotocol/server-filesystem` + `uvx mcp-server-git`, both with  
   `isolation = "gvisor"`.  
   Showcases: gVisor process isolation (p4.2) + network namespace isolation.  
   (NOTE: gVisor replaces Landlock on MCP subprocess; Landlock net-port claim removed.)  
   `gated_requires = "gVisor (runsc must be on PATH); without it the MCP server will fail to start"`.  
   `sample_tasks`: at least 2.

5. **`templates/watcher.template.toml`**  
   *Trigger-gated (requires future event-trigger surface).*  
   Caps: `FsRead {/workspace}`.  
   Tools: native `read_file`, `list_dir`.  
   `gated_requires = "event-trigger surface (not yet implemented — post-Phase-6 roadmap)"`.  
   Showcases: closest thing to a daemon in AgentOS — REQUIRES event-trigger surface (not yet implemented).  
   `sample_tasks`: at least 1.

6. **`templates/memory-custodian.template.toml`**  
   *Phase-5-gated.*  
   Caps: `KbRead`/`KbWrite {project:}`.  
   Tools: native `kb_get`, `kb_put`, `kb_search`.  
   Memory: `[[memory.segments]]` entry for `project:findings` (class = "scratch").  
   `store_path = "/run/memory/memory.redb"`.  
   `gated_requires = "Phase-5 memory (memory.store_path must point to a running redb volume)"`.  
   Showcases: Phase-5 shared KB + segmentation + provenance — multiple agents reading one curated segment.  
   `sample_tasks`: at least 2.

- Add `gated_requires: Option<String>` field to `TemplateMeta` (`#[serde(default)]`)
- Add tests:
  - `catalogue_all_seven_templates_present`: `TemplateResolver` lists all 7 by name using `env!("CARGO_MANIFEST_DIR")` path
  - `catalogue_non_gated_templates_lower_to_valid_config`: librarian + coordinator lower without error; coordinator has `memory.enabled = false`; coordinator tools.native has spawn_agent/send_message/list_agents
  - `catalogue_gated_templates_lower_to_valid_config`: journaler, memory-custodian, watcher lower without error; all have non-empty `gated_requires`
  - `catalogue_gvisor_template_config`: code-aware lowers with `isolation = GVisor` on MCP servers; `gated_requires` is non-empty
  - `catalogue_coordinator_has_spawn_cap`: `suggested_caps` includes `Spawn`; tools.native list contains `spawn_agent`
  - `catalogue_journaler_memory_segment_set`: segment name = `"agent/journaler"`, class = `SegmentClass::Log`, `store_path = "/run/memory/memory.redb"`

**`agentctl/src/spawn.rs`**:
- Before exec, check `template.meta.gated_requires`. If `Some(msg)`, print to stderr:
  ```
  warning: this template requires: {msg}
           proceeding — if agentd fails, ensure the requirement is met.
  ```
- Add one test for this warning path.

**`agentctl/src/list.rs`**:
- Change `print_table` third column from SHOWCASES to DESCRIPTION.
- Add SHOWCASES as an indented sub-line (or 4th column if it fits; truncate at 60 chars).

**`agentctl/src/watch/spawn.rs`**:
- Add `sample_tasks: Vec<String>` to `SpawnTemplate`.
- Populate from `TemplateEntry::sample_tasks` (must also be added to `TemplateEntry` in `template.rs`).

**`agentctl/src/watch/views.rs` / `app.rs`**:
- In `View::Spawn`, when operator selects a template (cursor moves or `[Enter]` confirms), pre-fill `task_input` with `template.sample_tasks.first().cloned().unwrap_or_default()`.
- Only pre-fill when the task_input field is empty (don't overwrite user's typed text).

## Acceptance criteria (from roadmap + gate)

1. `agentctl list-templates` lists all 7 templates with name, source, description.
2. `agentctl spawn scout --task "..."` still works (regression).
3. `agentctl spawn librarian --task "Index /workspace/library and write INDEX.md"` generates valid config.
4. `agentctl spawn coordinator --task "Spawn two scouts and synthesize their findings"` generates valid config with Spawn cap.
5. `agentctl spawn journaler --task "..."` prints a gated_requires warning before exec.
6. Gated templates (journaler, memory-custodian, watcher) list correctly and lower to valid config.
7. TUI Spawn view pre-fills task field with `sample_tasks[0]` when a template is selected (if field is empty).
8. `cargo test` passes (≥ 793 tests + new catalogue tests).
9. `cargo clippy -- -D warnings` clean on both crates.
