## Increment Summary

Add client-side HTTP/SSE MCP transport to `agentd`, enabling connection to networked MCP
servers (Gmail, Linear, Attio, GitHub, etc.) that expose HTTP endpoints rather than spawning
as subprocesses. This is the first "Beyond Phase 6" increment.

**Why now**: The custom harness (13-agent spec in `docs/prompts/70-custom-harness-prompt.md`)
requires Gmail, Linear, Attio, GitHub MCP. All of these expose HTTP endpoints. Without HTTP
transport, none of those agents can reach their tools.

**Branch**: `p7.1-http-sse-transport`
**Version**: `v0.35.0`

## Context

- Current state: MCP client is stdio-only (`McpClient` in `agentd/src/tools/mcp.rs`)
- `reqwest 0.12` (rustls-tls, json) is already in `Cargo.toml`
- `McpServerConfig` in `config.rs` has: `name`, `command`, `args`, `capabilities`, `isolation`, `env`
- `McpTool.client: Arc<McpClient>` calls `client.request("tools/call", ...)` for all tool invocations
- `McpClient::spawn()` creates a subprocess; no HTTP path exists

## Design

### Transport Abstraction

Introduce a `McpBackend` trait in `agentd/src/tools/mcp.rs`:

```rust
#[async_trait]
pub trait McpBackend: Send + Sync {
    async fn request(&self, method: &str, params: Value) -> Result<Value>;
    async fn shutdown(&self);
}
```

- `McpClient` (stdio, existing) implements `McpBackend`
- `McpHttpClient` (new) implements `McpBackend`
- `McpTool.client` changes from `Arc<McpClient>` → `Arc<dyn McpBackend>`

### Config Changes (`config.rs`)

Add to `McpServerConfig`:
```toml
[[tools.mcp_servers]]
name = "linear"
url = "https://mcp.linear.app/sse"         # new: triggers HTTP transport
headers_env = { Authorization = "LINEAR_MCP_TOKEN" }  # new: env-var → header
# command/args omitted (not needed for HTTP)
```

Fields added to `McpServerConfig`:
- `url: Option<String>` — HTTP endpoint; if Some → HTTP transport, else → stdio
- `headers_env: HashMap<String, String>` — map of header-name → env-var-name
- `command` changes default to `""` (previously required; now only needed for stdio)

**Validation**: fail fast at startup if both `url` and `command` are non-empty (ambiguous).

### `McpHttpClient` (`agentd/src/tools/mcp.rs`)

```rust
pub struct McpHttpClient {
    client: reqwest::Client,
    url: String,
    headers: reqwest::header::HeaderMap,
    next_id: AtomicU64,
}

impl McpHttpClient {
    pub async fn connect(
        url: &str,
        headers_env: &HashMap<String, String>,
    ) -> Result<(Arc<dyn McpBackend>, Vec<ToolSpec>)>;
}

#[async_trait]
impl McpBackend for McpHttpClient {
    async fn request(&self, method: &str, params: Value) -> Result<Value>;
    async fn shutdown(&self);  // no-op for HTTP
}
```

**HTTP request flow**:
1. POST `url` with JSON-RPC body
2. Set `Content-Type: application/json`, `Accept: application/json, text/event-stream`
3. Apply resolved headers (from `headers_env` → env vars)
4. If response Content-Type is `application/json`: parse JSON-RPC directly
5. If response Content-Type is `text/event-stream`: read body as text, find first
   non-comment `data:` line containing a JSON-RPC response, parse it
6. Response size guard: reject if `Content-Length > 4 MB` (mirrors stdio `MAX_RESPONSE_BYTES`)
7. Timeout: same `MCP_TIMEOUT` (30s)

**Header resolution** (secrets-from-env invariant):
```rust
// headers_env = { "Authorization" => "LINEAR_MCP_TOKEN" }
// reads std::env::var("LINEAR_MCP_TOKEN") at connect time
// header value: "Bearer <value>" if it looks like a token, or raw value
```
Actually: just pass the env var value as-is. The config author sets the full header value
in the env var (e.g. `LINEAR_MCP_TOKEN=Bearer sk-...`).

**SSE parsing** (no new crate):
```
data: {"jsonrpc":"2.0","id":1,"result":{...}}\n\n
```
Read response body as String, split on `\n`, find lines starting with `data:`, strip prefix,
parse as JSON-RPC. Skip `event:`, `id:`, comment (`:`) lines.

### Sandbox interaction

HTTP MCP servers run externally — Landlock/seccomp don't apply.

In `main.rs`:
- If `server.url.is_some()`: call `McpHttpClient::connect()`; skip sandbox compilation
- `SandboxSummary` for HTTP servers: `landlock: false`, `seccomp: false`,
  `spawn_enforcement: "n/a"`, `accessible: true` (they're always reachable)
- `ServerEnforcement` in surfaces/FUSE: show `transport: "http"` field

### Wire-up in `main.rs`

```rust
// Before (stdio only):
let (client, specs) = McpClient::spawn(&server.command, &server.args, sandbox, &server.env).await?;

// After (transport dispatch):
let (backend, specs): (Arc<dyn McpBackend>, Vec<ToolSpec>) = match &server.url {
    Some(url) => McpHttpClient::connect(url, &server.headers_env).await?,
    None      => McpClient::spawn(&server.command, &server.args, sandbox, &server.env).await?,
};
for spec in specs {
    registry.register(Box::new(McpTool::new(Arc::clone(&backend), spec, server.name.clone())));
}
```

- Timeout via `tokio::time::timeout`

## Risks

1. **SSE streaming unbounded**: tool calls that stream multi-MB responses may OOM.
   Mitigation: `Content-Length` guard + `MAX_RESPONSE_BYTES` limit on buffered text.
2. **Auth header in logs**: secrets-from-env invariant — never log header values.
   Mitigation: log only header names, not values.
3. **FUSE/sandbox surface**: `ServerEnforcement` struct needs `transport` field added
   without breaking existing JSON output.
   Mitigation: add `#[serde(default)]` field; existing JSON unchanged.
4. **Linux clippy**: any `#[cfg(target_os = "linux")]`-gated code needs `make clippy-linux`.
   Mitigation: HTTP transport is platform-agnostic (no Linux-gated code needed).

## Updated Design (post-CEO)

### Config: Tagged Transport Enum

```toml
# Stdio transport (existing)
[[tools.mcp_servers]]
name = "files"
transport = "stdio"
command = "/usr/bin/files-mcp"

# Streamable HTTP transport (new)
[[tools.mcp_servers]]
name = "linear"
transport = "http"
url = "https://mcp.linear.app/mcp"
headers_env = { Authorization = "LINEAR_MCP_TOKEN" }
```

In Rust:
```rust
#[derive(Deserialize, Serialize, Clone, Debug)]
#[serde(tag = "transport", rename_all = "lowercase")]
pub enum McpTransport {
    Stdio { command: String, #[serde(default)] args: Vec<String> },
    Http  { url: String, #[serde(default)] headers_env: HashMap<String, String> },
}
```

`McpServerConfig.command` and `McpServerConfig.url` are replaced by `McpServerConfig.transport: McpTransport`. All transport-specific fields live inside the variant. Invalid states (both/neither) are unrepresentable.

**Backward compat**: existing configs use `command = "..."` without `transport`. Use `#[serde(untagged)]` or a custom deserializer: if `transport` field absent, check for `command` field and default to `Stdio`. Or: add migration note; `deny_unknown_fields` is already set so we must handle carefully.

Actually, safest: keep `command`/`args` as top-level fields with `serde(default)`, add `url: Option<String>` + `transport: TransportKind` (enum with `stdio`/`http` defaulting to `stdio`). Existing configs stay valid. Tagged variant is the cleaner design but requires removing `deny_unknown_fields` or adding a custom deserializer.

**Chosen approach (pragmatic, backward compat):**
- Add `url: Option<String>` + `headers_env: HashMap<String, String>` to `McpServerConfig`
- `command` remains with `#[serde(default)]` (empty = not provided for HTTP)
- `transport: TransportKind` enum with default `Stdio`; if `url` is set and `transport` is `Stdio`, it becomes `Http` automatically (or error)
- Startup validation: reject if `transport=http` and no `url`; reject if `transport=stdio` and no `command`

### Streamable HTTP Spec (MCP 2025-03-26)

POST to `url`:
- `Content-Type: application/json`
- `Accept: application/json, text/event-stream`
- Body: `{"jsonrpc":"2.0","id":N,"method":"...","params":{...}}`

Response:
- If `Content-Type: application/json` → parse as JSON-RPC result
- If `Content-Type: text/event-stream` → read as SSE stream, collect `data:` lines until one parses as a JSON-RPC result for this request ID

SSE parsing rules (per spec):
- Skip `:` comment lines
- Skip `event:`, `id:`, `retry:` lines
- Collect consecutive `data:` lines (they are concatenated for multi-line values)
- Each complete event (terminated by blank line) yields one message
- Find the event whose `data` parses as JSON-RPC with matching `id`

**Streaming body size guard:** use `reqwest` with `response.bytes_stream()` (add `stream` feature to reqwest) and count bytes, rejecting at `MAX_RESPONSE_BYTES`.

## Engineering Addendum (post-Eng review)

### McpBackend Trait (revised)

```rust
#[async_trait]
pub trait McpBackend: Send + Sync {
    async fn request(&self, method: &str, params: Value) -> Result<Value>;
    async fn notify(&self, method: &str) -> Result<()>;
    async fn shutdown(&self);
    fn transport_kind(&self) -> &'static str;  // "stdio" | "http"
}
```

`McpClient` (stdio) implements all four. `McpHttpClient` implements all four:
- `notify()`: POST notification (no id, no response expected; ignore 404/405)
- `shutdown()`: POST `notifications/cancelled` if `Mcp-Session-Id` is set; no-op otherwise
- `transport_kind()`: returns `"http"`

### `McpHttpClient` fields (revised)

```rust
pub struct McpHttpClient {
    client: reqwest::Client,
    url: String,
    default_headers: reqwest::header::HeaderMap,  // never Debug-derived
    next_id: AtomicU64,
    session_id: Mutex<Option<String>>,  // Set from initialize response header
}
```

No `Debug` derive — contains secret values.

### main.rs startup order (revised)

```
1. For each mcp_server in config:
   a. If transport=http: skip gVisor check, skip sandbox compilation, skip command validation
      → call McpHttpClient::connect(); push result to backends: Vec<Arc<dyn McpBackend>>
   b. If transport=stdio: run existing validation + sandbox compile + McpClient::spawn()
      → push result to backends

2. mcp_require_capabilities: check only stdio servers (HTTP has no Landlock rules)

3. backends: Vec<Arc<dyn McpBackend>> used for shutdown, replacing mcp_clients: Vec<Arc<McpClient>>
```

### SSE State Machine

Inline state machine in `McpHttpClient::parse_sse_stream()`:

```
States: ReadingFields | EventBoundary
On line:
  "" (empty)    → emit current event (if has data), reset fields
  ": ..."       → skip comment
  "data: ..."   → accumulate data line (concatenate with \n)
  "event: ..."  → store event type (skip non-"message" types)
  "id: ..."     → store SSE event ID (not JSON-RPC id)
  "retry: ..."  → ignore
On end-of-stream → emit partial event if data non-empty

Find the emitted event whose `data` JSON-parses as JSON-RPC with matching `id` field.
```

Approximately 80-90 lines. No external crate needed.

### Test File: `agentd/tests/mcp_http.rs`

## DX Addendum (post-DX review)

### Error messages (required in implementation)

**4xx from remote server** — `McpHttpClient::request()` must emit on any non-2xx:
```
MCP server 'linear' returned HTTP 401 — check that env var LINEAR_MCP_TOKEN is set
and contains the correct value (header 'Authorization' was sent)
```
Never log header values. Log only: HTTP status, server name, URL, header env var names.

**Missing env var at startup** — fail-fast message must include:
```
MCP server 'linear': headers_env references env var 'LINEAR_MCP_TOKEN' which is not
set — export LINEAR_MCP_TOKEN=<value> before starting agentd
```

**Bad URL (not an MCP endpoint)** — when `initialize` returns non-JSON-RPC shape:
```
MCP server 'linear' did not respond to initialize with a valid JSON-RPC result —
is 'https://...' an MCP server endpoint?
```

**Silent command failure** — when `transport=stdio` and no `command`:
```
MCP server 'files': transport is 'stdio' but no command is set — add
command = "/path/to/server"
```
