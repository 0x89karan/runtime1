# p5.2 — Per-Agent Short-Term Memory + Paging

## Problem

AgentOS agents currently have a single memory tier: the live `messages: Vec<Msg>` on
`AgentTask`. When token usage approaches the per-agent `token_budget`, the only
outcome is `budget_exceeded` — the agent fails and loses its work. There is no way
for an agent to continue gracefully under memory pressure.

## Goal

Add a second memory tier (Tier 2, "short-term") that allows agents to page older
conversation turns out of the active context window without losing them. An agent
that would have hit `budget_exceeded` should instead page old turns and complete
the task within its remaining budget.

## Architecture

```
Tier 1: messages: Vec<Msg>          ← active context (in every inference request)
Tier 2: short_term: Vec<MemItem>    ← paged turns (on AgentTask, survives checkpoint)
Tier 3: memory.redb (p5.3)          ← long-term (cross-run, cross-agent)
```

## Naming note

This increment implements **eviction with preserved data**, not full paging with recall.
Paged turns are stored in `short_term` (survives checkpoint) but are NOT yet retrievable
by the agent. Recall is p5.3. The `blocks_json` field is stored now so p5.3 can add
recall without a schema change.

## Strategic rationale

Even as model context windows grow to 1M+ tokens, the memory substrate has durable value:
(a) per-agent token budgets are real and finite regardless of context window size; (b) p5.3+
adds cross-run memory (`memory.redb`) which is valuable independent of context size; (c) paging
is a foundation for p5.6 distillation. This is not a 2023-era workaround — it is the
persistence layer the Phase 5 stack is built on.

## Paging mechanics and budget interaction

**Paging provides N+1 relief, not N.** When the agent pages on turn N:
- Old turns are removed from `messages`
- The NEXT inference request (turn N+1) will be smaller, costing fewer tokens
- Prior tokens already spent (`total_input + total_output`) are not reduced
- The budget guard (`total_spent >= token_budget → BudgetExceeded`) can still fire on turn N if turn N's inference response pushes cumulative total over budget

This is by design. The acceptance criterion "an agent at 91% pages instead of hitting budget_exceeded" means: at turn N the agent is at 91%, pages, and COMPLETES on turn N+1. The test must verify the turn-sequence, not just that `BudgetExceeded` is never emitted.

## Eviction policy (placeholder)

`page_count` returns `max(0, (messages.len() - 1) / 4)`. This is FIFO-oldest — a placeholder.
**`page_count` returns 0 when `messages.len() <= 2`** (initial task + at most one assistant reply);
the hard-pressure path skips paging when `page_count` returns 0.
Principled eviction policy is deferred to p5.6. A TODO comment in `context.rs` will document this.

## Alternating-role invariant

The Anthropic API requires strict alternating roles (user/assistant). `page_turns` must drain
complete **turn pairs** (one assistant `Msg` + its following user/tool-result `Msg`), never
individual messages. After paging, `messages` must remain role-alternating.

## New components

### `memory/context.rs` — Context pressure manager

```rust
pub enum MemoryPressure { None, Soft, Hard }

/// Fraction of token_budget consumed → pressure level.
/// SOFT_THRESHOLD = 0.75, HARD_THRESHOLD = 0.90 — static constants in p5.2.
/// Will become per-agent config in p5.6.
pub fn assess(tokens_spent: u64, token_budget: u64) -> MemoryPressure

/// Extract oldest evictable turn PAIRS from messages (preserving alternating-role invariant).
/// Skips if page_count returns 0 (messages.len() <= 2).
/// Returns Result — on serde error, the turn is skipped, not panicked.
pub fn page_turns(messages: &mut Vec<Msg>, n: usize, at_turn: u32) -> Result<Vec<MemItem>>

/// Returns max(0, (messages.len() - 1) / 4). Returns 0 when messages.len() <= 2.
pub fn page_count(messages: &[Msg]) -> usize
```

Thresholds (static constants in `context.rs`):
- `SOFT_THRESHOLD: f64 = 0.75` — emits `MemoryPressureAdvisory` event only
- `HARD_THRESHOLD: f64 = 0.90` — force-pages

**Paging is independent of `memory.enabled`.** `short_term` lives on `AgentTask`,
not in the redb store. An agent with `[memory] enabled = false` still gets paging.

### `MemItem` — Serializable paged turn pair

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct MemItem {
    pub turn:            u32,       // turn index at time of paging
    pub role:            Role,      // Role enum (already Serialize/Deserialize)
    pub content_preview: String,    // first 200 chars for flight event
    pub blocks_json:     String,    // serde_json of Vec<Block>, for p5.3 recall
}
```

`role: Role` (not `String`) — uses the existing typed enum from `inference`.
Stored as `short_term: Vec<MemItem>` on `AgentTask` and `AgentCheckpoint`.

### `AgentTask` integration

Before building the `InferenceRequest` in `step_need_infer`:

1. Call `assess(total_input + total_output, cfg.token_budget)`
2. **Soft**: emit `EventKind::MemoryPressureAdvisory` flight event. No text injection —
   agent has no `mem_page` tool in p5.2 and injected text would cost tokens with no action path.
3. **Hard**: call `page_turns` (if `page_count > 0`):
   - On success: move items to `self.short_term`, emit `MemoryPaged`
   - On `page_turns` error: emit `EventKind::Error { stage: "page_turns" }`, skip paging

`to_checkpoint` and `from_checkpoint` **both** need explicit update for the `short_term` field.
`from_checkpoint` must restore `cp.short_term` (not zero it) or paged turns are lost on restart.

### Flight events

```
MemoryPressureAdvisory:
  { agent, turn, tokens_spent_pct: f64, soft_threshold: f64 }

MemoryPaged:
  { agent, turn, pages_moved: usize, short_term_depth: usize, tokens_spent_pct: f64 }
```

### Checkpoint bump: FORMAT_VERSION 1 → 2

`AgentCheckpoint` gains `#[serde(default)] pub short_term: Vec<MemItem>`.
`FORMAT_VERSION` bumped to 2.

**Back-compat:** A v1 checkpoint (no `short_term` field) loads cleanly — `serde(default)`
yields `vec![]`. Correct because v1 agents never paged, so empty short-term is always valid.
The v1 compat test must use a real `CheckpointStore::load()` call (not unit serde) to
exercise the version-probe path.

**FORMAT_VERSION policy (to be documented in CONVENTIONS.md):**
Use `#[serde(default)]` for all additive fields. Bump `FORMAT_VERSION` only for breaking
changes (field removal or rename). Version number is a compatibility floor, not a field inventory.

## What is NOT in scope (p5.2)

- Paged turn recall (reading back from `short_term`) — p5.3
- Summarization of paged turns — p5.6
- `mem_page` as an explicit agent tool call — p5.3
- Context-window-based pressure estimate (vs budget %) — may revisit in p5.6
- Per-agent configurable thresholds — p5.6
- Cross-agent or cross-run memory — p5.3/p5.4

## Acceptance criteria (12 tests)

1. `assess` returns `None` below SOFT_THRESHOLD
2. `assess` returns `Soft` at exactly SOFT_THRESHOLD
3. `assess` returns `Hard` at exactly HARD_THRESHOLD
4. `assess` returns `Hard` above HARD_THRESHOLD
5. `page_count` returns 0 for `messages.len() == 1` (only initial task)
6. `page_count` returns 0 for `messages.len() == 2`
7. `page_count` returns correct value for larger lists (e.g. len=9 → 2)
8. `page_turns` preserves alternating-role invariant after paging
9. `page_turns` leaves initial task message intact (index 0 never paged)
10. `AgentTask` with hard pressure calls `page_turns`, emits `MemoryPaged` with correct fields
11. Soft pressure emits `MemoryPressureAdvisory` event; no text injected into `messages`
12. v1 checkpoint (no `short_term` field, `format_version: 1`) loads via `CheckpointStore::load()` → `short_term` is empty; `format_version` 1 passes the guard (not refused)
13. v2 checkpoint with non-empty `short_term` round-trips through `save()`/`load()` with items intact
14. `to_checkpoint`/`from_checkpoint` preserve `short_term` (items not silently zeroed on restore)

(Exceeds the "+7 tests" spec minimum; full coverage requires 14.)
