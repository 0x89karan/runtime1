# p7.5b — Universal-tier HTTP forwarding proxy [CORE]

**Branch:** `p7.5b-universal-tier-proxy`
**Depends on:** p7.5 (`start_http_stub`, `EgressProxy`, `EvidenceWriter`, real API key captured by `AnthropicGateway` at startup), p7.2 (`reqwest`/`hyper` machinery).
**Enables:** p7.6 (gVisor spawn path points `ANTHROPIC_BASE_URL` at this proxy).
**Version:** v0.40.0
**Sequencing note (autoplan D5 decision):** This increment ships BEFORE p7.6 so that universal-tier agents can complete LLM calls end-to-end. Without this, `ANTHROPIC_BASE_URL=http://127.0.0.1:<port>` points at a 501 stub and universal agents cannot do any inference.

## Problem

`start_http_stub()` in `agentd/src/egress.rs` (lines 112–140) binds a TCP listener and returns `501 Not Implemented` for every request. This was explicitly scaffolded for p7.5b. Universal-tier agents (p7.6 — LangChain, headless claude, etc.) need to point their `ANTHROPIC_BASE_URL` at a proxy that actually forwards requests to the Anthropic API and records metered action receipts. Without real forwarding, the entire universal-tier story is blocked.

Additionally, the `SocketAddr` returned by `start_http_stub()` is currently logged and discarded at `src/main.rs:774-777`. It must be stored so p7.6 can inject it as `ANTHROPIC_BASE_URL` into spawned workloads' environments.

## Design

### Proxy overview

```
Universal-tier workload (gVisor child — p7.6)
   ANTHROPIC_BASE_URL = http://127.0.0.1:<port>        (from /agents/system/egress_addr)
   ANTHROPIC_API_KEY  = sk-ant-WORKLOAD-<id>-<random>  (ephemeral, per-spawn, never real)
      │
      │  POST /v1/messages  (HTTP/1.1)
      │  x-api-key: sk-ant-WORKLOAD-<id>-<random>
      ▼
agentd egress proxy (src/egress.rs)
   ├─ detect Accept: text/event-stream → 501 streaming_not_supported
   ├─ lookup x-api-key in ProxyRegistry → agent_id + policy
   ├─ reject 403 {"detail": "unknown_workload_key"} if not registered
   ├─ check path: /v1/messages only; other paths → 404 {"detail": "path_not_allowed"}
   ├─ check capability allowlist
   ├─ strip ephemeral key; insert real ANTHROPIC_API_KEY as x-api-key
   ├─ strip hop-by-hop headers (Host, Content-Length, Transfer-Encoding, Connection)
   ├─ pass through: anthropic-version, anthropic-beta, content-type
   ├─ forward to https://api.anthropic.com/v1/messages via reqwest (120s timeout)
   ├─ buffer response, cap at 8 MB → 502 if exceeded
   ├─ decrement token_budget_remaining (Arc<AtomicU64>)
   ├─ emit EgressBrokered + ActionReceiptEmitted
   └─ return upstream status + body to workload

Native agents: still call InferenceGateway directly (in-process, no HTTP hop)
```

### Agent identity: per-workload ephemeral key [D1, E1, DX-6]

**Decision:** Identity is determined by the `x-api-key` header value, not the URL path. The proxy listens on the standard `POST /v1/messages` endpoint. Each registered workload receives a unique ephemeral key generated at spawn time: `sk-ant-WORKLOAD-<agent_id>-<random_suffix>`.

**Why ephemeral key, not URL path:**
1. **SDK compatibility:** Anthropic Python/JS SDKs append `/v1/messages` to `ANTHROPIC_BASE_URL`; they will never send `/v1/{agent_id}/messages`.
2. **Natural intercept point:** `x-api-key` is Anthropic's actual auth header — intercepting it is the correct seam.

**Key generation and provisioning (p7.6):** The ephemeral key is generated at workload registration (p7.6 spawn path) using `ring::rand` and injected into the child's environment as `ANTHROPIC_API_KEY`. It is NOT a static compile-time constant. The real `ANTHROPIC_API_KEY` lives only in the proxy's memory and is never written to disk or logged. [DX-8]

### Credential rewriting [E5, DX-7]

The workload sends the ephemeral key as `x-api-key: sk-ant-WORKLOAD-<id>-<random>`. The proxy:

1. Looks up the ephemeral key in the registry → agent_id + policy.
2. Replaces `x-api-key` with the real `ANTHROPIC_API_KEY`.
3. Passes through `anthropic-version` and `anthropic-beta` headers verbatim.
4. Strips hop-by-hop headers before forwarding: `Host`, `Content-Length`, `Transfer-Encoding`, `Connection`. (`reqwest` will set the correct `Host` and `Content-Length` for the upstream request.)

### Streaming detection [DX-3]

If the incoming request carries `Accept: text/event-stream` (or equivalent SSE negotiation), the proxy returns immediately with:

```json
HTTP/1.1 501 Not Implemented
Content-Type: application/json

{"error": {"type": "streaming_not_supported", "message": "Use stream=False; streaming proxy ships in p7.5c"}}
```

This prevents the confusing failure mode where the Anthropic Python SDK in `stream=True` mode receives a buffered 200 and attempts to parse it as an SSE stream, producing a client-side exception with no actionable message.

### Sync-first (buffer upstream response) [D5]

p7.5b buffers the full Anthropic response before returning to the workload. Streaming proxy (hyper SSE pass-through) is deferred to p7.5c. A correct streaming pass-through requires careful backpressure, half-close handling, and SSE framing — adds 200–300 lines of security-sensitive code. The sync path works for any framework that makes a blocking `requests.post()` call, covering the majority of LangChain and similar use cases.

**Limitation:** streaming clients (`stream=True`) return 501 with a clear message. Documented in RUNBOOK.md and the template.

### egress_bound_addr stored + FUSE-exposed [DX-1]

`main.rs:774-777` currently logs `bound` and drops it. Change to:

```rust
let egress_bound_addr: Option<std::net::SocketAddr> = match agentd::egress::start_http_proxy(
    gateway_key.clone(), registry.clone(), recorder.clone(), evidence_writer.clone()
).await {
    Ok(bound) => {
        tracing::info!(addr = %bound, "egress proxy started");
        Some(bound)
    }
    Err(e) => return Err(e.context("egress proxy failed to bind (fail-closed)")),
};
```

The bound address is also exposed via FUSE at `/agents/system/egress_addr` (new virtual file, returning `http://127.0.0.1:<port>` or `not configured`). This gives operators an immediate `cat /agents/system/egress_addr` path to discover the URL without parsing flight logs.

### ProxyRegistry (thread-safe workload registration)

```rust
pub struct ProxyRegistry {
    // ephemeral_key → (agent_id, policy)
    agents: Arc<RwLock<HashMap<String, ProxyEntry>>>,
}

pub struct ProxyEntry {
    pub agent_id: String,
    pub policy: ProxyPolicy,
}

pub struct ProxyPolicy {
    pub allowed_hosts: Vec<String>,          // from Capability::Net.hosts
    pub token_budget_remaining: Arc<AtomicU64>,  // shared with scheduler [D2, E2]
}

impl ProxyRegistry {
    pub fn register(&self, ephemeral_key: String, entry: ProxyEntry);
    pub fn deregister_by_key(&self, ephemeral_key: &str);
    pub fn entry_for_key(&self, x_api_key: &str) -> Option<ProxyEntry>;
}
```

### HTTP proxy request flow

```
1.  accept TcpStream
2.  parse HTTP/1.1 request (hyper)
3.  check Accept header → if text/event-stream → 501 streaming_not_supported [DX-3]
4.  extract x-api-key header
5.  ProxyRegistry::entry_for_key(x_api_key) → 403 {"detail": "unknown_workload_key"} if missing [DX-2]
6.  check path == /v1/messages; else → 404 {"detail": "path_not_allowed"} [DX-2]
7.  strip x-api-key (ephemeral); insert x-api-key = real ANTHROPIC_API_KEY [E5]
8.  strip hop-by-hop: Host, Content-Length, Transfer-Encoding, Connection [DX-7]
9.  pass through: anthropic-version, anthropic-beta, content-type [E5]
10. reqwest forward to https://api.anthropic.com/v1/messages, timeout=120s [E4]
11. on reqwest timeout → 504 + egress_proxy_failed event [E6]
12. buffer response body, cap at 8 MB [D3, E3]
13. if body > 8 MB → 502 + egress_proxy_failed event
14. parse usage field (best-effort) → record tokens
15. token_budget_remaining.fetch_sub(tokens_used, Relaxed) [D2]
16. EgressProxy::record_inference(agent_id, model, in_toks, out_toks)
17. return upstream status code + response body to workload [E6: 4xx/5xx pass-through]
```

### Deny path structured errors [DX-2]

All rejection responses include a `detail` field for actionability:

```json
{"error": {"type": "egress_denied", "message": "<human text>", "detail": "<machine tag>"}}
```

Machine tags: `unknown_workload_key`, `path_not_allowed`, `streaming_not_supported`, `response_too_large`, `upstream_timeout`.

`EgressProxy::record_denied(agent_id, target)` emitted on all deny paths.

### Failure semantics [E6]

| Failure | HTTP status | Event |
|---------|-------------|-------|
| reqwest timeout (>120s) | 504 | `egress_proxy_failed` |
| upstream 4xx/5xx | pass-through | `egress_brokered` |
| response > 8 MB | 502 | `egress_proxy_failed` |
| malformed upstream response | 502 | `egress_proxy_failed` |
| unknown workload key | 403 | `egress_denied` |
| path not allowed | 404 | `egress_denied` |
| streaming request | 501 | `egress_denied` |

## Acceptance criteria

1. `cargo build --release` succeeds; `cargo clippy -- -D warnings` + `make clippy-linux` clean.
2. `cargo test`: all 945 existing tests + minimum 12 new p7.5b tests.
3. Binary ≤ 6 MB (no new deps — ring and hyper already linked). [E9]
4. With `proxy_addr` configured: `start_http_proxy()` stores a `SocketAddr`; FUSE `/agents/system/egress_addr` returns `http://127.0.0.1:<port>`.
5. Workload sending ephemeral key in `x-api-key` gets forwarded response; real key in forwarded `x-api-key`; ephemeral NOT present.
6. Unknown ephemeral key → 403 + `{"detail": "unknown_workload_key"}` + `egress_denied` event.
7. `Accept: text/event-stream` → 501 + `{"type": "streaming_not_supported"}`.
8. Bind failure → agentd exits non-zero + `egress_proxy_failed` event (fail-closed).
9. `Scheduler::egress_addr()` returns the bound `SocketAddr`.
10. Single-agent demo (`agent.toml`) runs unchanged when `[egress]` absent.
11. Upstream 4xx/5xx passes through with `EgressBrokered` event. [E6]
12. Response > 8 MB → 502 + `egress_proxy_failed` event. [D3]
13. Hop-by-hop headers (`Host`, `Content-Length`) are NOT present in the forwarded request. [DX-7]
