thesis 1 · the substrate

The agent is the primitive. Everything else follows.

agentOS is the operating system at the core of runtime1: a minimal, Linux-based system whose unit of execution, scheduling, and isolation is the agent, not the application — and why that has to live at the OS layer, not in a framework.

naming, once

runtime1 is the project. agentOS is the operating system inside it — the part that runs the agents. agentd is agentOS's runtime binary: the ~2 MB Rust daemon that boots as PID 1 and is the userspace. This page is about agentOS.

The problem nobody's runtime solves

Agents that touch real, sensitive systems — email, CRM, code, deals, a cap table — can't be run unsupervised today. You either babysit them with per-action approval prompts, sandbox the whole process coarsely in a container and hope, or hand your most sensitive operations to a hosted service you don't control.

None of those let a team of agents coordinate across your systems, 24/7, while guaranteeing each one is bounded, every action is audited, spend is metered, and your data doesn't leak — without you watching. That guarantee is an operating-system-shaped problem: it's about what the boundary enforces, not what the agent promises.

What "agents as the primitive" means

In a conventional OS the kernel's managed unit is the process and the human-facing unit is the application. agentOS replaces that center of gravity. The managed unit is an agent: a long-lived, stateful, non-deterministic entity defined by a role, a working context (its RAM), a connection to a model (its CPU), a set of capabilities exposed as tools, persistent memory, and a lifecycle — spawn, run, suspend, resume, delegate, terminate. There are no applications; the things you would "open" are things an agent invokes.

This table is the spine of the design. If a feature can't be mapped onto the right-hand column, it belongs to the host Linux layer and is left alone — the kernel is not the innovation, the userspace reconception is.

Two decisions gate everything

  • Cognition is remote. The device is a thin agent host; the model is an API call behind an inference gateway. No local weights, no inference engine — this is the difference between an OS that is genuinely ~2 MB and one where "light" means a lean shell around a necessarily heavy model. A local backend can be added later as another gateway implementation, never as a core assumption.
  • Single-tenant. One person's agents on one box, mutually trusting, in-process. Capability scoping between agents exists for least-privilege — not because agents distrust each other, but because a prompt-injected agent should hold the smallest possible blast radius.

Why cognition being metered changes the scheduler

Unlike CPU time, every "thought" costs real money. So budgets — tokens, dollars, wall-clock — are first-class, schedulable, enforced resources. The scheduler admission gate checks the budget before every model call; a rolling reset window means a runaway agent is deferred, not bricked; the fuse has been proven live against a real runaway loop. Agents are event-driven and mostly idle — they block on inference and tool I/O for seconds at a time — so the system suspends and resumes them around events rather than keeping them hot.

What the runtime is made of

  • Lifecycle manager & scheduler — spawns, suspends, resumes, and terminates agents; schedules inference slots and budgets, not CPU time.
  • Context manager — owns each agent's working context; pages between context and long-term memory.
  • Memory substrate — embedded structured store + semantic index, with provenance, exposed at /agents/<id>/memory.
  • Tool manager — MCP is the tool ABI; tool servers run as sandboxed subprocesses with tiered isolation.
  • Capability system — every agent runs with an explicit grant set: which tools, which memory segments, which hosts, what spend. Spawned children can only receive an attenuated subset of the parent's grants — over-granting is rejected at spawn, not clamped silently.
  • Credential broker — agents never hold raw credentials; OAuth and API secrets live behind a broker that injects them at the egress boundary. A memory dump of an agent yields inert placeholders.
  • Inference gateway — the one place cognition enters; metered, retried, streamed, and receipted.
  • Flight recorder — an append-only structured log of every prompt, tool call, verdict, and decision. Built on day one, because non-determinism makes it non-optional.

The security model, stated the way we'd want to hear it

what we refuse to say

"Watertight." Landlock + seccomp + namespaces is a capability layer — least-privilege on a process that still shares the host kernel. It is not an isolation boundary strong enough for untrusted or foreign-framework code; for that, the floor is a microVM or a user-space kernel (gVisor), and the runtime's isolation tiers say which one a workload actually got. Anyone who can call a model can, in principle, launder data through it — the model channel itself is a covert channel. We say so.

the claim we do make

Allowlist-only egress. Every allowed call metered and audited. Approval gates on risky actions. Deterministic anti-credential-theft via boundary secret rewriting. A budget fuse that has actually stopped a runaway. Dramatically reduced blast radius, and a tamper-evident audit trail of what each agent did — defense-in-depth plus accountability, not a hermetic seal. Sophisticated operators trust this framing and distrust "impenetrable."

What exists today, and what is still a hypothesis

Built and tested: the multi-agent scheduler with token/$ metering and the rolling budget fuse; the capability sandbox (Landlock, seccomp, namespaces, gVisor tiering); 4-tier memory with provenance; the /agents FUSE control plane; MCP over stdio and HTTP/SSE; streaming inference; checkpoint/restore that survives SIGTERM mid-tool-call; the credential broker; the signed receipt chain; the agentctl operator TUI; and a standing chief-of-staff workload dogfooded daily against a real inbox.

The hypothesis under test: that some work is sensitive enough that it will never be handed to somebody else's multi-tenant cloud, and that the right home for it is a substrate you run yourself. This is not a claim that hosted services are going away — the interesting case only exists because most software is hosted. The experiment is whether putting the guarantees in an OS makes unsupervised agents genuinely trustworthy, or just differently untrustworthy. That is an open question, and the code is how it gets answered.
