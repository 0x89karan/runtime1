The operating system where agents are the primitive, not applications.

runtime1 is the open-source project building agentOS: an operating system that runs a team of AI agents on hardware you own. Every agent is bounded by the capabilities it was granted, every tool and model call is brokered and recorded, and everything an agent does lands in an evidence trail you can verify — so agents can run unsupervised on systems that matter.

What you actually get

Not a framework to build on. A machine that runs your agents while you are not looking, and a cockpit for the moments you are.

agents you define

One primitive, many agents

An agent is a task, a model, a capability set and a budget — so most of what you would otherwise cron or script can be one. Seventeen templates ship to start from: read-only scouts, filesystem watchers, cron jobs, webhook responders, repo-aware workers, a librarian over your own documents. Write your own as a TOML file.

the reference implementation

A chief of staff, as the worked example

The agent we dogfood is a chief of staff that reads a real inbox overnight and leaves one brief in the morning, each item linked back to its thread. It is not the product — it is three of those seventeen templates wired together, and it exists to put the substrate under real conditions and surface the bugs worth fixing.

where your data sits

Everything but the thinking stays home

Cognition is a remote API call by design — there are no model weights here. Everything else is yours and local: the inbox, the files, the OAuth tokens, the memory store, and the record of what happened. Tool servers run as separate processes on hardware you own.

when you do look

Stop a runaway from the screen that shows it

agentctl watch is one screen with every agent on it — spend, capabilities, live output, and which ones need you. The verbs are on the same screen as the evidence: cancel a runaway, narrow a grant, approve a risky action, without leaving the terminal.

what this is

An open-source experiment, built in the open, testing one idea: that if agents are going to run unsupervised against real systems, the guarantees belong in an operating system rather than in a framework or a prompt. It is a working tool — dogfooded daily against a real inbox — and simultaneously an argument that might be wrong. There is nothing to buy, nothing to sign up for, and no roadmap promises. Read the code, disagree with the thesis, open an issue.

The idea in three sentences

01 · agents, not apps

A new primitive

A normal operating system schedules processes and CPU time. agentOS schedules agents and the resources that actually matter for them: inference slots, token budgets, dollars, and tool access. The runtime (agentd) boots as PID 1 — there is no desktop, no apps, just agents and their tools.

02 · governance built in

Bounded by construction

Agents are useful precisely when you stop watching them — and that's when they're dangerous. So the boundary does the supervising: capability grants, a budget fuse that actually stops a runaway loop, approval gates for risky actions, and a flight recorder that logs every step.

03 · evidence, not promises

Verify, don't trust

Model calls are receipted into a hash-chained, Ed25519-signed log you can verify offline. The roadmap extends this to every action class, custody-anchored audit packets, and zero-knowledge proofs that the published decision log is consistent with the policy — without revealing the policy.

the house rule

Every claim on this site is labeled the way our own architecture diagram labels components: enforced means code stops you, declared means a config or prompt says so, and not built means it doesn't exist yet. Trust in a system like this dies of overclaiming, so the threat model documents what the evidence chain cannot prove, in public, on purpose.

What's actually built

The house rule, made operable. Filter the stack by how each guarantee is actually backed — this is the same vocabulary the runtime schematic uses.

Capability grants

Every tool call is checked against the agent's grant set before it runs. A denied call is refused and recorded — reject, not clamp.

enforced

Flight recorder

Every meaningful step emits a structured JSONL event. Logging is best-effort by design and can never crash an agent.

enforced

Signed receipt chain

Hash-chained, Ed25519-signed receipts you can verify offline, with genesis anchoring and rotation. Coverage today is model calls; other action classes are roadmap.

enforced

Approval gates

A risky action parks the agent until a human resolves it. The pending request survives a restart — approvals are checkpointed.

enforced

Checkpoint & restore

Agents are snapshotted at turn boundaries and restored after a crash or restart. Tool side effects are at-least-once, not exactly-once — stated, not glossed.

enforced

Budget fuse

Per-agent and global token windows, checked at admission. Exhaustion defers the agent (with a reset window) or terminates it — a runaway loop stops.

enforced

Kernel sandbox for tool subprocesses

seccomp-bpf and Landlock are enforced on Linux x86_64 and simply unavailable on the Mac Docker path. The runtime schematic shows which is which, per platform.

declared

Brief content rules

The morning brief's escaping and size caps are prompt instructions, not code enforcement. A prompt rule is not a guarantee; the fix is runtime-authored output.

declared

Isolation between agents

Single-tenant by construction: agents are mutually trusting and run in-process. Capability scoping is least-privilege hygiene, not a security boundary between agents.

declared

Custody-anchored audit packets

Exportable evidence bundles with key custody and an out-of-band anchor, so a verifier can detect a rewind. Specified as gov.1; not built.

not built

Auditor-side trust root

Key enrollment, an anchor registry, and image pinning so a third party has something to verify against. Specified as gov.2; not built.

not built

Zero-knowledge replay proofs

Prove the published decision log is consistent with the policy without revealing the policy. Specified as zk.2 and deliberately gated on a named counterparty.

not built

TEE attestation

The only mechanism that would answer "did the host actually run this code" — the one seam cryptography alone cannot close. Considered, documented, not scheduled.

not built

How the pieces are named

Three names, one stack — worth getting straight before anything else.

the project

runtime1

The open-source experiment as a whole: the operating system, the runtime, the operator tooling (agentctl), the tool servers, the verification pipeline, and the docs. When we talk about "the repo" or "the experiment," this is the name.

the operating system

agentOS

A minimal Linux base whose entire userspace is the agent runtime: no desktop, no apps, no login shell, just agents and the tools they invoke. This is the artifact the project exists to build — the OS where agents are the primitive.

the runtime process

agentd

agentOS's runtime binary — a ~2 MB Rust daemon that boots as PID 1 and is the userspace. It holds the scheduler, the capability system, the memory substrate, the gateways, and the flight recorder. Today it also runs as an ordinary binary on a normal distro.
